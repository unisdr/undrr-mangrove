# Show more

A vanilla JavaScript utility that collapses content behind a "show more" button. It works with plain HTML through `mgShowMore()` and also provides a React wrapper.

## React labels and dynamic content

Set `labelCollapsed` and `labelOpen` per instance; their defaults are "Show more"
and "Show less". Labels update when the props change, including while expanded.
The legacy item `button_text` field is accepted but no longer controls the
initial rendered label: use `labelCollapsed` to keep server-rendered and enhanced
wording consistent. The old field was already replaced on initialisation.

Each item initialises only its own toggle and removes its handlers on unmount.
Items added after mount work immediately; existing expanded items stay expanded.
React-owned toggles opt out of the vanilla document-wide auto-initialiser.
The vanilla API remains idempotent and now returns an optional cleanup function
that removes only handlers installed by that call.

## Default

The button is placed directly after the collapsible content. Use the locale
toolbar to preview translated content and toggle labels, including Arabic.

## Detached button

The toggle button does not need to be inside or adjacent to the content container. Use `data-mg-show-more-target` to point it at any element on the page by CSS selector.

## Two on one page

Two toggles may share a target selector — the default one, or the same class on
two blocks — as long as each pair sits in its own parent. Each toggle then
reveals its own content. Two toggles under the _same_ parent still cannot be
told apart — see "How the target is resolved" below.

## Only when long

Add `data-mg-show-more-min-hidden-lines` (React: `minHiddenLines`) to collapse content only when it runs at least that many lines past the collapsed height. Shorter content stays open and the toggle gets `hidden`, so a template can wrap every body field in ShowMore without offering a "Show more" that reveals one more sentence.

- The collapsed height comes from CSS: the computed `max-height` of `.mg-show-more--collapsed`, which is `--mg-show-more-height`. Any unit works; `lh` sizes it in lines of the content's own line height.
- A line is the content's computed `line-height`. An empty attribute means 1 line.
- The decision does not depend on whether the content is open, so it cannot flip back and forth. It is made again, in the next animation frame, when the content resizes, until the reader uses the toggle.
- Ship the toggle with `hidden` in server markup. Without JavaScript the content is simply open and no dead button shows; the script reveals the toggle when it is needed.

For "show about 8 lines, but collapse only when at least 6 more would be hidden" (so only bodies over about 14 lines collapse), as the [Collection page](?path=/docs/patterns-collection-page--docs) does:

<div id="collection-body" style="--mg-show-more-height: 8lh">

</div>

### Hidden context in the label

When the toggle contains a `[data-mg-show-more-label]` element, only that element's text changes on each toggle, so visually hidden context beside it ("about this collection") stays in the accessible name.

### Show less

Collapsing a long block pulls the toggle up the page, often out of view. When that happens the script scrolls the heading just before the content (or the content itself) back into view. It honours `scroll-padding-top`, so a sticky bar such as [On this page nav](?path=/docs/components-navigation-on-this-page-nav--docs) does not cover it, and `prefers-reduced-motion`.

### Analytics

The toggle carries `data-vf-analytics-label`, which the UNDRR click tracker reads: "Show more" while collapsed and "Show less" while open, in English whatever the page language. Set `data-mg-show-more-analytics-collapsed` and `data-mg-show-more-analytics-open` for page-specific labels. A `data-vf-analytics-label` you set yourself, without those two, is left as it is.

## How it works

The `mgShowMore()` function finds all elements with `data-mg-show-more` and wires up click handlers. On click, the targeted container's `mg-show-more--collapsed` class is toggled, which controls `max-height`, `overflow`, and a CSS `mask-image` fade.

### How the target is resolved

A toggle's target selector is resolved nearest scope first: the script climbs
the toggle's ancestors and takes the first match it finds inside one.

Revealed content need not be a sibling or descendant of its toggle, so there is
no container the lookup can be confined to — but it can be ordered. For the
canonical markup the walk finds the adjacent wrapper. For two blocks in
separate subtrees each toggle finds its own, so two toggles left on the default
`.mg-show-more--container` no longer both drive the first block.

A target elsewhere on the page is still found. For a toggle that is in the
document the walk ends at `<html>`, which contains everything else, so its last
step is the document-wide lookup — the detached button above resolves the same
way it always did. The walk is never worse than the old `document.querySelector`;
it only prefers a nearer match when there is one.

Two toggles inside the **same** parent cannot be told apart this way: the first
scope holding one target holds both, and the earlier one in document order wins.
Give each of those its own selector, ideally an `id` — which is what the React
wrapper does for you.

### HTML structure

<Source language="html" code={`
<!-- Content to collapse -->
<div class="my-content">
  <p>Long content goes here...</p>
</div>

<!-- Toggle button (can be anywhere on the page) -->

<button type="button"
   class="mg-button mg-button-primary mg-show-more--button"
   data-mg-show-more="true"
   data-mg-show-more-target=".my-content"
   data-mg-show-more-label-open="Show less"
   data-mg-show-more-label-collapsed="Show more">
  Show more
</button>
`} />

The toggle must be a `<button type="button">`. Earlier versions of these docs
showed an `<a href="#">`; that anchor announced as a link and offered a dead
destination when the script failed to load. `mgShowMore()` still adds
`role="button"` and a Space handler to an anchor it finds, so existing markup
keeps working, but new markup should use a button.

### Accessibility

`mgShowMore()` wires these for you — do not hand-write them:

- `aria-controls` on the toggle, pointing at the content container. If the
  container has no `id`, the script assigns one (`mg-show-more-target-N`).
- `role="button"` on a toggle that is not already a `<button>`, together with
  a `keydown` handler so Space activates it. An anchor does not respond to
  Space on its own, and `role="button"` promises that it does.
- Expansion when keyboard focus enters a collapsed container, so Tab never
  parks focus on a control clipped out of view (WCAG 2.4.7 Focus Visible,
  2.4.11 Focus Not Obscured).

#### The collapse is visual only, and the toggle is not a disclosure

The toggle deliberately carries **no `aria-expanded`**, and the component is
not a disclosure widget in the WAI-ARIA sense. Collapsing is done with
`max-height`, `overflow: hidden` and a `mask-image` fade. All three are paint
and layout effects: the clipped text stays in the accessibility tree and the
clipped controls stay in the tab order. Verified in Chromium against the
collapsed container — the accessibility tree lists every clipped paragraph,
and tabbing goes straight through a link below the clip line.

So a screen reader reads the whole block whether it looks collapsed or not.
An `aria-expanded="false"` on the toggle would be a false statement about the
content, which is worse than no statement: it tells a screen reader user
there is hidden content to reveal when there is none, and it makes the toggle
look like a control they need to operate when operating it changes nothing
they can perceive. Nothing is lost to them — the content is all there.

Making the toggle an honest disclosure would mean genuinely hiding the
remainder (`hidden`, `display: none` or `content-visibility: hidden`), and
that is incompatible with a fade that cuts mid-line: you can only hide whole
elements, and the component's documented content model is a single run of
text in one container, with no child boundary to cut at. Choosing a real
disclosure therefore means giving up the fade, which is a visual change for
every consumer. Until that is decided, the component says nothing it cannot
back up.

If you need a true disclosure — content that is genuinely hidden until
revealed — build it from whole elements and toggle `hidden` on them, rather
than reaching for this utility.

### Data attributes

| Attribute                               | Required | Description                                                                                                                            |
| --------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `data-mg-show-more`                     | Yes      | Set to `"true"` on the toggle button to register it                                                                                    |
| `data-mg-show-more-target`              | No       | CSS selector for the content container, resolved nearest ancestor first. Defaults to `".mg-show-more--container"`                      |
| `data-mg-show-more-label-collapsed`     | No       | Button text when content is collapsed. Defaults to "Show more"                                                                         |
| `data-mg-show-more-label-open`          | No       | Button text when content is expanded. Defaults to "Show less"                                                                          |
| `data-mg-show-more-skip-auto-init`      | No       | Presence-based. Skips this button during auto-init. Call `mgShowMore([element])` to initialize manually.                               |
| `data-mg-show-more-min-hidden-lines`    | No       | Collapse only when the content runs at least this many lines past the collapsed height (empty means 1); otherwise the toggle is hidden |
| `data-mg-show-more-analytics-collapsed` | No       | Analytics label while collapsed. Defaults to "Show more"                                                                               |
| `data-mg-show-more-analytics-open`      | No       | Analytics label while open. Defaults to "Show less"                                                                                    |

### JavaScript initialization

The script file uses ES module `export` statements, so you **must** load it with `type="module"`.

<Source language="html" code={`
<!-- JS: type="module" is required -->
<script type="module" src="https://assets.undrr.org/mangrove/2.1.1/js/show-more.js"></script>
`} />

The script auto-initializes on `DOMContentLoaded` (or immediately if the DOM is already parsed). Module scripts are deferred by default, so no wrapper is needed.

For dynamically added content, import and call the init function:

<Source language="js" code={`
import { mgShowMore } from 'https://assets.undrr.org/mangrove/2.1.1/js/show-more.js';

// Initialize specific buttons
mgShowMore([myButton]);
`} />

### API

| Function             | Description                                                                                                                            |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `mgShowMore(scope?)` | Initializes show-more buttons. `scope` is an optional `NodeList` or array of elements; defaults to all `[data-mg-show-more]` elements. |

### Skipping auto-initialization

Add `data-mg-show-more-skip-auto-init` to skip a button during auto-init. This is useful when another script must run first (e.g. Drupal behaviors). Call `mgShowMore` yourself once that setup is complete:

<Source language="html" code={`
<button type="button" data-mg-show-more data-mg-show-more-skip-auto-init
   data-mg-show-more-target=".my-content">Show more</button>

<script type="module">
  import {mgShowMore} from
  'https://assets.undrr.org/mangrove/2.1.1/js/show-more.js';
  mgShowMore([document.querySelector('[data-mg-show-more-skip-auto-init]')]);
</script>

`} />

When you pass elements explicitly via `scope`, the skip attribute is ignored — the consumer is intentionally initializing.

### Customizing the collapse height

The collapsed height is controlled by the `--mg-show-more-height` CSS custom property (default: `200px`):

<Source language="css" code={`
/* Override globally */
:root {
  --mg-show-more-height: 150px;
}

/_ Or per instance _/
.my-content {
--mg-show-more-height: 300px;
}
`} />
