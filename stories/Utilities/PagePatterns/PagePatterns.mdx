# Reading column

A reading column with an optional sticky contents sidebar, for a long page whose
sections readers arrive wanting. For a full-width tinted band, combine
`mg-container-full-width` with a background utility; for a row of icons and
labels, use `IconCard` with `orientation="horizontal"` inside an `mg-grid`.
Used by the [content hub](?path=/docs/patterns-content-hub--docs) and
[landing page](?path=/docs/patterns-landing-pages--docs) patterns.

This is a class, not a component. The React wrapper in this story exists only so
it can be seen; use the markup directly.

## Reading column

<Canvas of={Stories.ReadingColumn} />

```html
<div class="mg-reading mg-reading--with-contents mg-grid mg-grid--article">
  <div><!-- contents --></div>
  <div class="mg-reading__article">…</div>
</div>
```

Constrains the article to a readable measure. With `--with-contents` the first
child becomes a sticky right sidebar from 48rem up and stacks above the article
below that — the flexible/fixed-width split itself is `mg-grid`'s `--article`
variant (see [Grid layout](?path=/docs/design-decisions-grid-layout--docs)),
so `mg-grid mg-grid--article` must be paired with `mg-reading--with-contents`
for the sidebar split to render; `mg-reading--with-contents` alone only
supplies the item placement.

## Changelog

- **1.1** — 2026-09-11 ([undrr/web-backlog#3060](https://gitlab.com/undrr/web-backlog/-/work_items/3060)): 
    - `.mg-reading--with-contents` now self-caps to its natural combined width via a new `--mg-reading-with-contents-width` custom property, fixing a dead gap between the article and the rail on any viewport wider than the two columns' combined measure — previously only patched around in one consumer's own demo CSS, not fixed here, so `ContentHub` and `LandingPages` had the same gap unaddressed until now.
    - The sidebar/article split's column shape moved out of this file's own bespoke grid and into `mg-grid`'s new `--article` variant, so it's shared, shipped, and reusable outside this pattern rather than living only here. `mg-reading--with-contents` now needs `mg-grid mg-grid--article` alongside it in markup — this file keeps only the item-placement rules specific to its own sidebar/article semantics.
- **1.0** — 2026-09-10: Added `mg-reading` as a distributed layout utility. ([#1112](https://github.com/unisdr/undrr-mangrove/issues/1112))
