# Fonts

## Roboto

Roboto is the primary font family used throughout Mangrove for body text and form content.

```scss
$mg-font-family: 'Roboto', sans-serif;
```

**Usage:**

- Body text and paragraphs
- Form inputs and form labels
- Default for all text content

### Roboto Condensed

Roboto Condensed is reserved for **compact navigation labels and decorative chrome**, not for buttons or narrative headings. Buttons and long-form headings (h1–h6 used in articles, story content, page bodies) use the body face; Roboto gives actions a calmer, more legible treatment, while Roboto Condensed at heading size feels too tight for sustained reading.

Two SCSS tokens cover the condensed-font use cases:

```scss
// Semantic alias — use this for component-level title/label classes that act
// as visual headings within a card, hero, tab, or other UI chrome context.
$mg-font-family-headings: $mg-font-family-condensed !default;

// Raw token — use when compact width is the goal and the element is not
// a heading (e.g. dense navigation that needs to fit more characters).
$mg-font-family-condensed: 'Roboto Condensed', sans-serif;
```

**When to use which:**

| Token                       | Use for                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (default body font)         | h1–h6 in narrative content. They inherit Roboto from `body`. Do not declare a `font-family` on h1–h6 in component SCSS.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `$mg-font-family-headings`  | Component title/label classes: `.mg-hero__title`, `.mg-hero__label`, `.mg-card__title`, `.mg-card__label`, `.mg-stats-card-item__value`, `.mg-stats-card-item__label`, `.mg-stats-card-item__bottom-label`, `.mg-gallery__title`, `.mg-tabs__link`, `.mg-on-this-page-nav__link`, `.mg-on-this-page-nav__cta`, `.mg-mega-topbar__item-link`, `.mg-mega-content__banner header`, `.mg-button` (CTA buttons), `.mg-footer--about-footer--links`, `.mg-tag`, and any new component class that functions as a chip, label, or compact title within UI chrome. |
| `$mg-font-family-condensed` | Dense UI chrome where compact width is the explicit design goal, not heading semantics. Currently: breadcrumbs.                                                                                                                                                                                                                                                                                                                                                                                                                                           |

If a class is a visual title or label inside a component (not part of narrative body content), prefer `$mg-font-family-headings`. The `!default` flag on the token lets a consumer theme remap the family without forking the SCSS.

## Font sources

All fonts are served from the UNDRR CDN for reliability and performance:

| Font             | CDN Path                                                         |
| ---------------- | ---------------------------------------------------------------- |
| Roboto           | `https://assets.undrr.org/static/fonts/roboto/v1.0.0/`           |
| Roboto Condensed | `https://assets.undrr.org/static/fonts/roboto-condensed/v1.0.0/` |

## Performance

All font declarations use `font-display: swap` to prevent invisible text during load. Text renders immediately with a fallback font, then swaps to the web font once loaded.

## Language-specific fonts

Mangrove supports language-specific font overrides for scripts that require specialized typography. These fonts are applied automatically based on the `lang` attribute.

### How it works

When content is marked with a language attribute (e.g., `lang="ar"`), CSS `:lang()` selectors automatically apply the appropriate fonts:

```html
<div lang="ar">
  <!-- Arabic fonts applied automatically -->
</div>
```

### Supported languages

| Language | Selector    | Font override                                        |
| -------- | ----------- | ---------------------------------------------------- |
| Arabic   | `:lang(ar)` | Noto Kufi Arabic (headings), Noto Sans Arabic (body) |

## Arabic fonts

Arabic content uses dedicated fonts, which cover the Arabic script that Roboto and Roboto Condensed do not.

### Font usage

| Purpose          | Font             | Weight   | Variable                          |
| ---------------- | ---------------- | -------- | --------------------------------- |
| Headings (h1-h6) | Noto Kufi Arabic | 400, 700 | `$mg-font-family-arabic-headings` |
| Body text        | Noto Sans Arabic | 400, 700 | `$mg-font-family-arabic-body`     |

> **Note**: This pairing was decided in [#1089](https://github.com/unisdr/undrr-mangrove/issues/1089), replacing Dubai across every brand. Kufi is a display style -- angular and high contrast -- so it belongs in headings and not at body size; Noto Sans Arabic carries the running text and shares Noto Sans' proportions. Both are SIL Open Font License 1.1.
>
> Only Regular (400) and Bold (700) are published in the UNDRR asset library for either family, so Arabic has a two-step weight ladder where Latin has a full one. Both upstream families span 100-900, so adding a weight is a packaging task, not an upstream limit. Note the ladder is not symmetric: `600` resolves up to Bold, but `500` resolves _down_ to Regular. Roboto Condensed publishes no Medium either, so chrome set in the condensed face behaves the same way in Latin.

### Implementation

Add the `lang="ar"` attribute to enable Arabic fonts:

```html
<div lang="ar" dir="rtl">
  <h1>عنوان رئيسي</h1>
  <p>هذا نص تجريبي باللغة العربية.</p>
</div>
```

To see Arabic fonts in action, view the <LinkTo kind="Components/Hero/Hero" story="Default">Hero component</LinkTo> with the locale toolbar set to Arabic.

### Arabic font sources

| Font             | Weight        | CDN path                                                          |
| ---------------- | ------------- | ----------------------------------------------------------------- |
| Noto Kufi Arabic | 400 (Regular) | `https://assets.undrr.org/fonts/noto-kufi-arabic/v1.1.0/Regular/` |
| Noto Kufi Arabic | 700 (Bold)    | `https://assets.undrr.org/fonts/noto-kufi-arabic/v1.1.0/Bold/`    |
| Noto Sans Arabic | 400 (Regular) | `https://assets.undrr.org/fonts/noto-sans-arabic/v1.0.0/Regular/` |
| Noto Sans Arabic | 700 (Bold)    | `https://assets.undrr.org/fonts/noto-sans-arabic/v1.0.0/Bold/`    |

No other weights are declared: only Regular and Bold are published in the UNDRR asset library.

Each weight is split into `arabic`, `latin` and `latin-ext` files, declared with a matching `unicode-range` so a browser fetches only the subsets a page renders. An English string inside an Arabic page pulls the small `latin` file, not the much larger `arabic` one.

**Font formats**: WOFF2 only. Browsers that support WOFF (v1) but not WOFF2 are about 0.28% of global traffic, most of it IE11, which lost support in June 2022.

### RTL support

Arabic fonts and RTL layout are handled separately:

- **`lang="ar"`** - Triggers Arabic font styles via `:lang(ar)` selector
- **`dir="rtl"`** - Triggers RTL layout adjustments (padding, margins, transforms)

For full Arabic support, use both attributes:

```html
<div lang="ar" dir="rtl">
  <h1>عنوان رئيسي</h1>
  <p>نص من اليمين إلى اليسار</p>
</div>
```

## Component development

When creating components that explicitly set `font-family`, add language-specific overrides to ensure proper rendering.

### Pattern for Arabic fonts

Attach `:lang(ar)` to the element you are styling. Never use it as an ancestor.

```scss
// Component styles
.my-component {
  font-family: $mg-font-family;
}

// Arabic font override (add at end of component file)
.my-component:lang(ar) {
  font-family: $mg-font-family-arabic-body;
}
```

The nested form `:lang(ar) { .my-component { ... } }` compiles to `:lang(ar) .my-component`, where `:lang()` constrains the **ancestor** and `.my-component` is merely a descendant. That rule fires on every matching element beneath an Arabic root regardless of that element's own language, so an English island inside an Arabic page renders in Arabic typography. Anchoring the pseudo-class to the element matches on **computed** language, which inherits and therefore stops at a `lang="en"` boundary. Fixed in [#1092](https://github.com/unisdr/undrr-mangrove/issues/1092).

### Language boundaries

Anchoring stops the Arabic rules from _matching_ non-Arabic elements, but `font-family` still inherits: a `lang="en"` island would otherwise inherit the Arabic family from `body:lang(ar)`. Two zero-specificity rules in `_foundational.scss` reassert the family at the switch point only, using a child combinator so component children that inherit their container's face keep it.

```scss
:where(:lang(ar)) > :where([lang]:not([lang=''], :lang(ar))) {
  font-family: $mg-font-family;
}

:where(:not(:lang(ar))) > :where([lang]:not([lang='']):lang(ar)) {
  font-family: $mg-font-family-arabic-body;
}
```

Two consequences worth knowing:

- `lang=""` means _unknown_ in HTML, not _Latin_, so an element carrying it inherits rather than being reset.
- The boundary rules can only reassert one family, and they reassert the base body face. A language switch on a generic element (`<span>`, `<a>`) inside component chrome — an English link inside an Arabic `.mg-card__title` — therefore falls back to Roboto rather than Roboto Condensed. Put `lang` on the element that carries the component class instead; `:where()` gives the boundary rules zero specificity, so the component rule wins.

See <LinkTo kind="Design decisions/Language boundaries">Language boundaries</LinkTo> for a live demo that reads the resolved font family back out of the rendered page.
