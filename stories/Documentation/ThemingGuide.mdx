# Theming guide

Mangrove ships five built-in themes. Colour, spacing, radius and component tokens are CSS custom properties, so a theme is a block of property overrides that takes effect the moment you add its class — no rebuild. This page explains the token system, shows the override that works in 2.0, and walks through building a new theme.

## Built-in themes

| Theme                | Stylesheet                | Body class                 | Interactive colour |
| -------------------- | ------------------------- | -------------------------- | ------------------ |
| **Global UNDRR**     | `style.css`               | none — the `:root` default | `#004f91`          |
| **PreventionWeb**    | `style-preventionweb.css` | `mg-theme-preventionweb`   | `#0a6969`          |
| **IRP**              | `style-irp.css`           | `mg-theme-irp`             | `#0f78bf`          |
| **MCR2030**          | `style-mcr.css`           | `mg-theme-mcr`             | `#591a61`          |
| **DELTA Resilience** | `style-delta.css`         | `mg-theme-delta`           | `#004f91`          |

A sub-brand stylesheet includes both `:root` defaults and a `.mg-theme-*` block. **The class activates the brand**; without it, components use the default UNDRR palette. `style-all.css` includes all brand blocks for multi-brand pages or runtime switching. Load one Mangrove stylesheet per page.

DELTA's interactive colour is UNDRR blue by design: alpha.3 replaced the navy Mangrove had been using with DELTA's real sourced palette. See [DELTA's palette is corrected](/docs/getting-started-release-notes-v2-0--docs) in the v2.0 release notes.

### Legacy 10px root (removed in 2.0)

The `-legacy` theme variants and the 10px root font-size they preserved were removed in Mangrove 2.0. Mangrove now assumes a standard 16px document root and ships only the standard themes. Sites migrating off the old 10px root must serve a 16px root and convert their own rem-based CSS to a 16px basis — see the [v2.0 release notes](/docs/getting-started-release-notes-v2-0--docs) (breaking change #5).

## Two token systems

Mangrove uses two token systems:

- **CSS custom properties** for runtime theming (`--mg-color-*`, `--mg-spacing-*`, `--mg-radius-*`, and component tokens).
- **SCSS variables** only where runtime variables cannot work (`@media`, `@if`, `@font-face`, selector interpolation).

Remaining SCSS variables:

| Variable                                                                                                                                | Why it stays SCSS                                                                                                                                                                                                                              |
| --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$mg-breakpoint-mobile`, `$mg-breakpoint-tablet`, `$mg-breakpoint-desktop`, `$mg-breakpoint-desktop-wide`                               | `@media` needs a static value                                                                                                                                                                                                                  |
| `$mg-font-size-100` … `$mg-font-size-1100` (12 steps)                                                                                   | interpolated and passed to Sass functions at compile time                                                                                                                                                                                      |
| `$mg-font-body`, `$mg-font-tag`, `$mg-font-line-height-500`, `$mg-font-line-height-700`                                                 | aliases over the type scale                                                                                                                                                                                                                    |
| `$mg-font-face-sans`, `$mg-font-face-sans-condensed`, `$mg-font-face-mono`, `$mg-font-face-arabic-display`, `$mg-font-face-arabic-sans` | `@font-face` and Sass interpolation need a compile-time value. These are the _faces_; the _roles_ components actually read (`--mg-font-family-text`, `-heading`, `-display`, `-ui`, `-code`) are custom properties and are themable at runtime |
| `$mg-html-font-size`                                                                                                                    | the rem anchor `mg-rem()` divides by; fixed at `16` in 2.0 and no longer overridable                                                                                                                                                           |
| `$mg-tabs-border-bottom`                                                                                                                | drives an `@if`, which is compile-time                                                                                                                                                                                                         |

Other legacy `$mg-*` variables no longer exist. Referencing one fails the build; assigning one compiles but has no effect. `_variables.scss` warns for common migrated names:

`$mg-color-interactive`, `$mg-color-interactive-active`, `$mg-color-button-background`, `$mg-color-button-background--hover`, `$mg-border-color-button`, `$mg-color-tag`, `$mg-color-form-check`, `$mg-color-form-focus`, `$mg-color-hero--secondary`, `$mg-spacing-150`, `$mg-spacing-300`.

The same warning covers the six font-family variables removed by the role model: `$mg-font-family`, `$mg-font-family-condensed`, `$mg-font-family-headings`, `$mg-font-family-icons`, `$mg-font-family-arabic-headings` and `$mg-font-family-arabic-body`. Each message names the role that replaced it. See [Fonts](?path=/docs/design-decisions-fonts--docs).

A legacy variable not on that warning list can still fail silently, so watch build logs closely.

## How to override a token

Set the custom property inside a selector. Use `:root` to change every brand on the page, or a `.mg-theme-*` block to change one.

```scss
// Globally, for the whole document
:root {
  --mg-color-interactive: 46 125 50;
}

// Or scoped to one brand
.mg-theme-myorg {
  --mg-color-interactive: 46 125 50;
}
```

Font families work the same way. The five `--mg-font-family-*` roles are custom properties, so a brand re-points them in its own block:

```scss
.mg-theme-myorg {
  // Set this brand's chrome in the body face rather than the condensed one.
  --mg-font-family-ui: var(--mg-font-family-text);
}
```

A role can only point at a typeface Mangrove already emits a `@font-face` for. Introducing a new typeface means overriding a `$mg-font-face-*` Sass variable before the import and loading the font yourself — and because faces sit outside the brand mixins, that applies to every brand in `style-all.css`. Per-brand typefaces are not yet available from `tokens/*.yaml`.

This is plain CSS. You can put it in a stylesheet that loads after Mangrove, in a SCSS partial you compile yourself, or in a `<style>` block — there is no import-order requirement and no rebuild of Mangrove. Semantic tokens derive from each other with live `var()` chains, so overriding `--mg-color-interactive` also moves the tag, form, hero and button colours that reference it.

## Token shapes: channels vs colours

**Most colour tokens hold bare RGB channels** — `--mg-color-interactive: 0 79 145` — and components wrap them at the point of use. That is what makes alpha compositing possible:

```css
color: rgb(var(--mg-color-interactive));
background: rgb(var(--mg-color-interactive) / 0.1);
```

**Three tokens hold a complete colour instead**, because a channel triple cannot express `transparent`:

- `--mg-color-button-background`
- `--mg-color-button-background--hover`
- `--mg-border-color-button`

Assign these a finished colour, never channels:

```css
.mg-theme-myorg {
  --mg-color-interactive: 46 125 50; /* channels */
  --mg-color-button-background: rgb(var(--mg-color-interactive)); /* colour   */
}
```

All three changed shape in `2.0.0-alpha.3`. An override still written as channels produces an invalid declaration that the browser drops silently — the symptom is buttons losing their fill. See [breaking change #7](/docs/getting-started-release-notes-v2-0--docs) in the release notes.

### The focus ring is not a brand colour

Focus rings do not follow `--mg-color-interactive`. They read `--mg-color-focus-ring`, which resolves to `--mg-color-gold-800` (`#866200`) in every theme, with `--mg-color-focus-ring-inverse` for dark surfaces. Focus and selection have to be distinguishable signals, so a theme changing its brand colour must not weaken the keyboard indicator. You can override the ring, but then you own its contrast against every surface it lands on.

## Where the token values live

Mangrove declares more than 350 distinct custom properties across the five themes. A table here would be stale within a release, so this page points at the sources instead.

| To find                              | Look at                                                                                                                                                                                                                                                                                      |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The authoritative value of any token | `tokens/mangrove.yaml` (brand-neutral base) and `tokens/undrr.yaml`, `tokens/preventionweb.yaml`, `tokens/irp.yaml`, `tokens/mcr.yaml`, `tokens/delta.yaml`                                                                                                                                  |
| What a theme actually emits          | `stories/assets/scss/generated/_tokens-{brand}.scss`, or the `.mg-theme-{brand}` block in the compiled `stories/assets/css/style-{brand}.css`                                                                                                                                                |
| Swatches and scales you can browse   | <LinkTo kind="design-decisions-colors" story="docs">Colors</LinkTo>, <LinkTo kind="design-decisions-spacing" story="docs">Spacing</LinkTo>, <LinkTo kind="design-decisions-typography" story="docs">Typography</LinkTo>, <LinkTo kind="design-decisions-widths" story="docs">Widths</LinkTo> |
| Which token a component reads        | that component's `.scss` file                                                                                                                                                                                                                                                                |

The YAML sources are the truth. `yarn build:tokens` compiles them into the generated partials; `yarn scss` runs it first. Editing a generated partial is pointless — the next build overwrites it. A brand file is merged _over_ the base before references resolve, so overriding one primitive cascades to everything derived from it.

### The tokens you are most likely to change

Verified against the compiled output. Every one is a channel triple unless marked.

| Token                                                                                | Controls                                                     |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| `--mg-color-interactive`                                                             | links, primary actions; most other colour tokens chain to it |
| `--mg-color-interactive-active`                                                      | hover and active states                                      |
| `--mg-color-secondary`, `--mg-color-tertiary`, `--mg-color-quaternary`               | hero and card colour variants                                |
| `--mg-color-button-background`, `--mg-color-button-background--hover`                | button fill (**full colour**)                                |
| `--mg-border-color-button`                                                           | button border (**full colour**, may be `transparent`)        |
| `--mg-radius-button`, `--mg-radius-tag`, `--mg-radius-form-input`, `--mg-radius-tab` | corner geometry (lengths)                                    |
| `--mg-color-tag`, `--mg-color-tag--hover`                                            | tag text and border                                          |
| `--mg-color-form-check`, `--mg-color-form-focus`                                     | checkbox/radio colour, focused field border                  |
| `--mg-color-hero`, `--mg-opacity-hero`                                               | hero overlay colour and opacity                              |
| `--mg-color-focus-ring`                                                              | keyboard focus indicator — override with care                |

## Creating a new theme

### Step 1: Add a token source

Create `tokens/myorg.yaml`. Declare the brand block, then only the tokens that differ from the base — everything else is inherited, and anything derived from what you change moves with it.

```yaml
$brand:
  id: myorg
  extends: undrr
  title: My Org
  selector: '.mg-theme-myorg'

brand:
  $type: color
  $private: true
  primary:
    $value: '#2e7d32'
    $description: The one primitive this brand states.

color:
  $type: color
  interactive: { $value: '{=brand.primary}' }
  interactive-active: { $value: '{=brand.primary}' }
  # $format states the shape at the point of use — this token is consumed
  # as a finished colour, not as channels.
  button-background:
    $value: '{=color.interactive}'
    $format: srgb-rgb-function

radius:
  $type: dimension
  button: { $value: '{spacing.50}' }
```

`{path}` emits a live `var()` chain, so the token follows whatever the referenced token becomes; `{=path}` resolves the value at build time. `$private` keeps a token out of the CSS output. The conventions are documented in the header of `tokens/mangrove.yaml`, and `tokens/preventionweb.yaml` is the shortest complete example to copy.

Run `yarn build:tokens` to emit `stories/assets/scss/generated/_tokens-myorg.scss`. The generator fails the build on an unknown reference, a circular reference, a duplicate output name or a wrong token shape, so a malformed source cannot quietly produce a stylesheet with missing colours.

### Step 2: Add a theme partial and an entry point

`stories/assets/scss/_theme-myorg.scss` wraps the generated mixin in the brand selector:

```scss
@import './generated/tokens-myorg';

.mg-theme-myorg {
  @include mg-tokens-tabs;
  @include mg-tokens-myorg;
}
```

`stories/assets/scss/style-myorg.scss` is the entry point:

```scss
@import './variables';
@import './theme-myorg';
@import './fonts';
@import './breakpoints';
@import './mixins';
@import './utility';
@import './foundational';
@import './components';
```

Run `yarn scss`, then apply `class="mg-theme-myorg"` to `<body>` or any wrapping element. The class can sit on any ancestor, and different subtrees can carry different theme classes.

### Not contributing to Mangrove?

If the theme belongs to your own project rather than to the library, you do not need the token pipeline at all. Write the `.mg-theme-myorg { }` block by hand in your own stylesheet, load it after Mangrove's, and skip both steps above. The pipeline exists so that _Mangrove's_ brands stay in sync with a source; a consumer theme has no such source to stay in sync with.

**Contributing a new official theme?** You also need to register it in Storybook, build the CSS and deploy it to Drupal. See the <LinkTo kind="contributing-architecture" story="docs">Architecture guide</LinkTo>.

## Migrating 1.x overrides

If you arrive with a 1.x theme, the mechanical change is this:

```scss
// 1.x — reassign the SCSS variable before importing Mangrove
$mg-color-interactive: #2e7d32 !default;
$mg-color-button-background: #2e7d32 !default;
@import '@undrr/undrr-mangrove/stories/assets/scss/style';

// 2.0 — declare custom properties in a selector, order irrelevant
.mg-theme-myorg {
  --mg-color-interactive: 46 125 50;
  --mg-color-button-background: rgb(var(--mg-color-interactive));
}
```

Four things to check as you go:

1. **Colour values become channels.** `#2e7d32` becomes `46 125 50` — except for the three full-colour tokens [named above](#token-shapes-channels-vs-colours).
2. **`rgba()`, `darken()`, `lighten()` and `color.adjust()` no longer work on these values.** A Sass colour function cannot take a `var()`. Use `rgb(var(--token) / 0.5)` for alpha, and a computed literal for the rest.
3. **The sub-brand `_variables-*.scss` files are gone**, replaced by `_theme-*.scss`.
4. **Compiled-CSS consumers of a sub-brand must add the `mg-theme-*` class**, or they get the UNDRR palette.

The full list, including the 10px root removal and the button token shape change, is in the [v2.0 release notes](/docs/getting-started-release-notes-v2-0--docs).

## RTL considerations

### How RTL is triggered

RTL layout is activated by the `dir="rtl"` attribute on the `<html>` element. In Storybook, selecting "Arabic" from the locale toolbar (globe icon) sets both `dir="rtl"` on the document and `window.UNDRR.dir = 'rtl'`. In Drupal, the CMS sets the `dir` attribute based on the page language.

### Locale toolbar in Storybook

The locale toolbar provides three options:

| Locale   | Language code | Direction |
| -------- | ------------- | --------- |
| English  | `en`          | LTR       |
| Arabic   | `ar`          | RTL       |
| Japanese | `ja`          | LTR       |

Arabic is the only locale that triggers RTL. The decorator in `preview.js` sets `lang` and `dir` attributes on `<html>` and `#storybook-root`, and updates `window.UNDRR.langCode` and `window.UNDRR.dir`.

### RTL in themes

Theming and RTL are independent. All five themes support RTL. When testing a theme in RTL, select the theme from the paintbrush toolbar and the locale from the globe toolbar. Both apply simultaneously.

### RTL-aware CSS patterns

Mangrove uses logical properties and `[dir="rtl"]` selectors where needed. Component-level SCSS files handle their own RTL overrides where layout direction matters (for example chevron icons, margin directions, text alignment).

### Burmese language adjustments

Burmese-specific font-size overrides (`:lang(my)`) were removed in v1.4 as they are not used by any current UNDRR property.
