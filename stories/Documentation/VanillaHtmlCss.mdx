# Vanilla HTML/CSS integration

Use Mangrove in static HTML or server-rendered pages without a JavaScript build
step. Start with a CSS-only example, then add the JavaScript each interactive
component needs. The code is Apache-2.0 licensed; the UNDRR look and feel is
proprietary.

## Quick start

### 1. Include CSS files

Save this as `index.html` and open it in a browser with an internet connection.
You should see an “Organization” tag in the default UNDRR theme. This example
needs no JavaScript.

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Mangrove example</title>
    <link
      rel="stylesheet"
      href="https://assets.undrr.org/mangrove/2.4.0/css/style.css"
    />
  </head>
  <body>
    <span class="mg-tag">Organization</span>
  </body>
</html>
```

### 2. Copy HTML structures

Open the component's docs and expand **Show code**. Stories such as Tag opt in
to rendered HTML there; other stories show JSX. If the snippet is JSX, open the
story in its Canvas view and select the **HTML** panel to copy the live markup.
For interactive components, follow the documented JavaScript or hydration setup
rather than copying runtime-generated markup alone. Keep the complete structure;
a class name may omit required wrappers, labels or scripts.

For agents consuming the library, the [AI integration guide](?path=/docs/getting-started-ai-and-mcp-integration--docs)
explains how to obtain rendered HTML and hydration examples from the manifest.

### Complete page example

[See on CodePen](https://codepen.io/khawkins98/pen/MYwbKwe) for a full template (header, navigation, hero, tabs, footer, analytics, messaging).

Use [Buttons](?path=/docs/components-buttons-buttons--docs)

Choose breadcrumbs, paging or menus for the reader's navigation task. Follow the
component's keyboard and JavaScript instructions as well as its markup.

## Best practices

### 1. Semantic HTML first

Use anchors for navigation and buttons for actions. A styled link retains its
link semantics:

```html
<a class="mg-button mg-button-primary" href="/publications">
  Browse publications
</a>
```

### 2. Accessibility attributes

Keep visible labels, input associations and documented ARIA attributes when
copying markup. Decorative icons should be hidden from assistive technology;
meaningful controls need an accessible name. See the [accessibility requirements](?path=/docs/getting-started-accessibility--docs)
for the full contract.

### 3. Responsive design

Use the documented [grid patterns](?path=/docs/design-decisions-grid-layout--docs)
and test your composed page at narrow widths, zoomed text and RTL. Component
responsiveness does not establish that the surrounding page layout will reflow.

## JavaScript

Use the component's documented integration: some need only CSS, some have
standalone vanilla modules and others mount React bundles into HTML containers.

### Vanilla JS modules

For a page containing the documented Tabs markup, load its module after parsing
the page:

```html
<script type="module">
  import { mgTabs } from 'https://assets.undrr.org/mangrove/2.4.0/js/tabs.js';
  mgTabs();
</script>
```

Module scripts defer execution until the document has been parsed. The [CDN reference](?path=/docs/getting-started-integration-cdn-reference--docs)
lists the standalone modules; each component guide owns its initialization
options. Load only the modules your page uses.

### Precompiled React components

React bundles need an import map supplying matching React and React DOM versions.
The complete example below includes that setup. Use the [CDN reference](?path=/docs/getting-started-integration-cdn-reference--docs)
for paths and the
[hydration guide](?path=/docs/getting-started-integration-hydration-guide--docs)
for supported components and runtime behaviour. A component visible in Storybook
is not necessarily published as a standalone bundle.

### Hydration helper (recommended)

For components that export `fromElement`, use `createHydrator` to read the
container's data attributes and manage the React root. The complete ShareButtons
example below demonstrates this. When adapting it, use the selected component's
own import, selector and data attributes from its documentation.

### Manual mounting (for components without hydration support)

A published component without `fromElement` needs explicit props and a React
root. The [React integration guide](?path=/docs/getting-started-integration-react-integration--docs)
lists each bundle's import contract. Do not infer a bundle path from a story
name; confirm that the component is published first.

For example, keep the CSS and import map from the complete page below, then
replace its sharing section and module script with this CtaButton mount:

```html
<div id="mangrove-action"></div>

<script type="module">
  import React from 'react';
  import { createRoot } from 'react-dom/client';
  import { CtaButton } from 'https://assets.undrr.org/mangrove/2.4.0/components/CtaButton.js';

  createRoot(document.getElementById('mangrove-action')).render(
    React.createElement(CtaButton, {
      label: 'Browse publications',
      href: '/publications',
    })
  );
</script>
```

This demonstrates manual mounting. The [HTML button example](#1-semantic-html-first)
above is sufficient for a static navigation link.

## Complete HTML page

A self-contained page you can save as an `.html` file and open in a browser. It loads the UNDRR theme, sets up an import map for React, and renders a ShareButtons component using the hydration helper.

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Mangrove component demo</title>

    <!-- Mangrove CSS theme -->
    <link
      rel="stylesheet"
      href="https://assets.undrr.org/mangrove/2.4.0/css/style.css"
    />

    <!-- Import map: provides React to Mangrove ES module bundles -->
    <script type="importmap">
      {
        "imports": {
          "react": "https://esm.sh/react@19.3.0",
          "react/jsx-runtime": "https://esm.sh/react@19.3.0/jsx-runtime",
          "react-dom": "https://esm.sh/react-dom@19.3.0",
          "react-dom/": "https://esm.sh/react-dom@19.3.0/"
        }
      }
    </script>
  </head>
  <body>
    <main>
      <h1>Share this page</h1>

      <!-- Mount point: the hydrator finds this element by its data attribute -->
      <section
        data-mg-share-buttons
        data-main-label="Share this"
        data-on-copy-label="Link copied"
        data-sharing-subject="Mangrove demo page"
      ></section>
    </main>

    <!-- Load the hydration runtime and component, then mount -->
    <script type="module">
      import createHydrator from 'https://assets.undrr.org/mangrove/2.4.0/components/hydrate.js';
      import ShareButtons, {
        fromElement,
      } from 'https://assets.undrr.org/mangrove/2.4.0/components/ShareButtons.js';

      createHydrator({
        selector: '[data-mg-share-buttons]',
        component: ShareButtons,
        fromElement,
      });
    </script>
  </body>
</html>
```

To adapt this page, check the selected component in the [supported hydration components](?path=/docs/getting-started-integration-hydration-guide--docs)
and use its own attributes and import contract. The hydrator replaces the
container's contents; do not put unrelated page content inside it.

## UNDRR integration

All UNDRR pages should include analytics and messaging scripts.

### Analytics

Track user behavior with GA4 enhancements:

```html
<script
  src="https://assets.undrr.org/analytics/v1.0.0/google_analytics_enhancements.js"
  defer
></script>
```

See [Analytics enhancements](?path=/docs/platform-services-analytics-enhancements--docs) for full documentation.

### Critical messaging

Receive emergency broadcasts across all UNDRR properties:

```html
<script src="https://messaging.undrr.org/src/undrr-messaging.js" defer></script>
```

Optionally add a container for message placement:

```html
<div class="mg-critical-messaging"></div>
```

See [Critical messaging](?path=/docs/platform-services-critical-messaging--docs) for full documentation.

## Troubleshooting

### Import map browser support

Check the [browser support policy](?path=/docs/getting-started-browser-support--docs)
for your target browsers. If an older browser needs an import-map polyfill,
configure it before module execution and verify the complete component in that
browser.

### CORS errors when self-hosting

If you host Mangrove JS files on your own server, the browser may block cross-origin imports. Ensure your server sends the correct headers:

```
Access-Control-Allow-Origin: *
Content-Type: application/javascript
```

When serving from `assets.undrr.org`, CORS headers are already configured.

### Component renders as blank

If a `data-mg-*` container stays empty after the page loads, check these items in order:

1. **Import map present?** The `<script type="importmap">` block must appear before any `<script type="module">` tags. Browsers ignore import maps added after the first module script runs.
2. **React version mismatch?** The `react` and `react-dom` versions in the import map must match. Mixing versions causes silent failures.
3. **Correct selector?** The `selector` passed to `createHydrator` must match the `data-mg-*` attribute on the container element. Open the browser console and look for errors from the hydration runtime.
4. **Network failures?** Open DevTools > Network tab and check that all `.js` files loaded with status 200. A 404 on the component or `hydrate.js` will prevent rendering.
5. **Conflicting import maps?** Keep the example's mappings together before the module script. Check that other page scripts have not already resolved React from a different URL.
6. **Console errors?** `createHydrator` logs errors to `console.error` and restores the original container HTML on failure. Check the browser console for details.
