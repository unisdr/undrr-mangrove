# Sass integration guide

Compile Mangrove's SCSS source yourself when you need its mixins, want to import only some components, or are building a theme into your own bundle. If all you need is a stylesheet, the <LinkTo kind="getting-started-integration-cdn-reference" story="docs">CDN reference</LinkTo> is a shorter route.

Before customizing, review **<LinkTo kind="getting-started-about-mangrove" story="docs">About Mangrove</LinkTo>** to understand what's shared across themes and what each property controls.

## Installation

```bash
yarn add @undrr/undrr-mangrove

# or
npm install @undrr/undrr-mangrove
```

The SCSS source files are in `stories/assets/scss/` within the installed package; the token sources are in `tokens/`.

## What is still Sass

In Mangrove 2.0, colour, spacing, radius and every component token are **CSS custom properties**, generated from `tokens/*.yaml`. You do not override them in Sass — you declare them in a selector. See the <LinkTo kind="getting-started-integration-theming-guide" story="docs">Theming guide</LinkTo> for the full explanation and the recipe.

Sass still owns the values that cannot be resolved at runtime, because `@media`, `@if`, `@font-face` and interpolation cannot read `var()`. That is the whole of the remaining SCSS variable API, [listed below](#scss-variables-reference) — breakpoints, the type scale, font families and two compile-time constants. Everything else that used to be a `$mg-*` variable is gone: referencing one fails the build, and *assigning* one compiles cleanly and does nothing. `_variables.scss` emits a Sass `@warn` for the names consumers are known to set, so watch your build log.

## SCSS file structure

Mangrove's styles are a set of partials imported by a theme entry point:

```
stories/assets/scss/
  style.scss                   # Default (UNDRR) theme entry point
  style-preventionweb.scss     # PreventionWeb theme
  style-irp.scss               # IRP theme
  style-mcr.scss               # MCR2030 theme
  style-delta.scss             # DELTA Resilience theme
  style-all.scss               # Combined bundle — all brand blocks in one file
  style-gutenberg.scss         # Legacy Gutenberg editor subset
  _variables.scss              # SCSS variables, mg-rem(), the :root token block
  _theme-{brand}.scss          # Wraps the generated token mixin in .mg-theme-{brand}
  generated/_tokens-{brand}.scss  # Build output of `yarn build:tokens` — never edit
  _tokens-tabs.scss            # Tab token block
  _tokens-data-viz.scss        # Data-visualisation palettes
  _fonts.scss                  # @font-face blocks and the Arabic script map
  _breakpoints.scss            # devicebreak() mixin
  _mixins.scss                 # Focus ring, vendor-prefix and utility mixins
  _utility.scss                # CSS utility classes
  _foundational.scss           # Base typography and element styles
  _components.scss             # Rollup of all component SCSS imports
```

Each theme entry point follows the same import order:

```scss
@import "./variables";        // SCSS variables + the :root custom property block
@import "./theme-{name}";     // .mg-theme-{name} { } token overrides (omitted in the default)
@import "./fonts";
@import "./breakpoints";
@import "./mixins";
@import "./utility";
@import "./foundational";
@import "./components";
```

The generated token partials are build output. `yarn scss` runs `yarn build:tokens` first, so a fresh clone compiles without a separate step.

## Root font-size and mg-rem()

Mangrove assumes the browser-standard 16px document root. The compiled CSS does not set a `font-size` on `html`, so user font-size preferences are respected.

Spacing, font-size and width values are authored in pixels and converted at build time by `mg-rem($px)`:

```scss
padding: mg-rem(15);       // 0.9375rem
font-size: mg-rem(16);     // 1rem
```

`$mg-html-font-size` is the anchor `mg-rem()` divides by. **In 2.0 it is fixed at `16` and can no longer be overridden** — the `!default` is gone, and the `style-*-legacy.css` builds that served a 10px root are deleted. Sites on a 10px root must serve a 16px root and convert their own rem-based CSS to a 16px basis. See the [v2.0 release notes](/docs/getting-started-release-notes-v2-0--docs) (breaking change #5).

## SCSS variables reference

This is the complete surviving SCSS variable API. Everything else is a CSS custom property — see <LinkTo kind="getting-started-integration-theming-guide" story="docs">Theming guide</LinkTo> for where those values live.

### Breakpoints

Static because `@media` cannot read `var()`. Note that these are the raw values; the `devicebreak()` mixin [below](#mixins-reference) uses its own em-based set and is what component SCSS actually uses.

| Variable | Value |
|----------|-------|
| `$mg-breakpoint-mobile` | `480px` |
| `$mg-breakpoint-tablet` | `900px` |
| `$mg-breakpoint-desktop` | `1164px` |
| `$mg-breakpoint-desktop-wide` | `1440px` |

### Font sizes

Generated from `tokens/mangrove.yaml` into `generated/_tokens-mangrove.scss`, and exported as Sass because they are interpolated and passed to Sass functions at compile time.

| Variable | Value | Pixels at a 16px root | Notes |
|----------|-------|----------------------|-------|
| `$mg-font-size-100` | `0.625rem` | 10px | |
| `$mg-font-size-150` | `0.703125rem` | 11.25px | |
| `$mg-font-size-200` | `0.78125rem` | 12.5px | |
| `$mg-font-size-250` | `0.875rem` | 14px | |
| `$mg-font-size-300` | `1rem` | 16px | Regular body text |
| `$mg-font-size-400` | `1.125rem` | 18px | |
| `$mg-font-size-500` | `1.4375rem` | 23px | |
| `$mg-font-size-600` | `2rem` | 32px | |
| `$mg-font-size-800` | `2.25rem` | 36px | |
| `$mg-font-size-900` | `2.5rem` | 40px | |
| `$mg-font-size-1000` | `3rem` | 48px | |
| `$mg-font-size-1100` | `4rem` | 64px | |

Aliases over that scale: `$mg-font-body` (`$mg-font-size-300`), `$mg-font-tag` (`$mg-font-size-250`), `$mg-font-line-height-500` (`1.25em`), `$mg-font-line-height-700` (`1.5em`).

### Font faces and font roles

Type is the one place where the SCSS layer and the custom-property layer both matter, so it has two token sets.

**Faces** are Sass variables — one per typeface Mangrove ships a `@font-face` for. All `!default`.

| Variable | Value |
|----------|-------|
| `$mg-font-face-sans` | `"Roboto", sans-serif` |
| `$mg-font-face-sans-condensed` | `"Roboto Condensed", sans-serif` |
| `$mg-font-face-mono` | `ui-monospace, "SFMono-Regular", "Consolas", "Liberation Mono", "Menlo", monospace` |
| `$mg-font-face-arabic-display` | `"Noto Kufi Arabic", sans-serif` |
| `$mg-font-face-arabic-sans` | `"Noto Sans Arabic", sans-serif` |

**Roles** are CSS custom properties. Every component stylesheet reads a role; none reads a face. `_fonts.scss` re-points the roles for Arabic, which is why no component carries a `:lang(ar)` font rule.

| Role | Latin | Arabic |
|------|-------|--------|
| `--mg-font-family-text` | `$mg-font-face-sans` | `$mg-font-face-arabic-sans` |
| `--mg-font-family-heading` | `$mg-font-face-sans` | `$mg-font-face-arabic-display` |
| `--mg-font-family-display` | `$mg-font-face-sans-condensed` | `$mg-font-face-arabic-display` |
| `--mg-font-family-ui` | `$mg-font-face-sans-condensed` | `$mg-font-face-arabic-sans` |
| `--mg-font-family-code` | `$mg-font-face-mono` | `$mg-font-face-mono` |

Latin resolves exactly as it did before the roles existed, and no new `font-family` declaration matches a Latin element, so a theme that sets its own face on `h1`–`h3` keeps it. To re-point a role for one brand, override the custom property in a `.mg-theme-*` block — but a role can only point at a face Mangrove already loads. To introduce a typeface Mangrove does not ship, assign the face variable before the import and load the font yourself; quote any family name that is not a plain CSS identifier. Note that faces sit outside the brand mixins, so a Sass override applies to every brand in `style-all.css`.

The six 1.x font variables — `$mg-font-family`, `-condensed`, `-headings`, `-icons`, `-arabic-headings`, `-arabic-body` — were removed in 2.0. See [breaking change #8](/docs/getting-started-release-notes-v2-0--docs) in the v2.0 release notes for what to do if you set any of them.

Arabic pairs Noto Kufi Arabic display type with Noto Sans Arabic body text, replacing Dubai; the reasoning is in the [v2.0 release notes](/docs/getting-started-release-notes-v2-0--docs).

### Compile-time constants

| Variable | Value | Purpose |
|----------|-------|---------|
| `$mg-html-font-size` | `16` | The rem anchor for `mg-rem()`. Fixed; not overridable. |
| `$mg-tabs-border-bottom` | `true` (`!default`) | Drives an `@if` in the tab styles. |

## Mixins reference

### `devicebreak` (from `_breakpoints.scss`)

The responsive media query mixin used throughout Mangrove.

| Name | Media query | Approximate size |
|------|------------|-----------------|
| `small` | `width <= 47.9375em` | Up to ~767px |
| `mediumonlytab` | `width <= 89.9375em` | Up to ~1439px |
| `medium` | `width >= 48em` | 768px and up |
| `large` | `width >= 64em` | 1024px and up |
| `xlarge` | `width >= 90em` | 1440px and up |

```scss
.my-component {
  padding: var(--mg-spacing-100);

  @include devicebreak(medium) {
    padding: var(--mg-spacing-200);
  }
}
```

### Focus ring (from `_mixins.scss`)

Mangrove's keyboard focus indicator is two bands — a light separator against the control, then the ring itself — with the ring drawn as an `outline` so it survives forced-colours mode. Use the mixin rather than restating the geometry; that is what keeps the indicator consistent and theme-aware.

| Mixin | Use for |
|-------|---------|
| `mg-focus-ring` | The default outside-the-control ring |
| `mg-focus-ring-inset` | Controls that cannot paint outside their own box |

```scss
.my-control:focus-visible {
  @include mg-focus-ring;
}
```

### Other mixins (from `_mixins.scss`)

| Mixin | Signature | Purpose |
|-------|-----------|---------|
| `mg-card-image-zoom` | `@include mg-card-image-zoom` | Shared card image hover zoom, reduced-motion aware |
| `transition` | `@include transition($transitions...)` | Prefixed `transition` |
| `transform` | `@include transform($transforms)` | Prefixed `transform` |
| `rotate` | `@include rotate($deg)` | Shorthand for `transform: rotate()` |
| `translate` | `@include translate($x, $y)` | Shorthand for `transform: translate()` |
| `scale` | `@include scale($scale)` | Shorthand for `transform: scale()` |
| `skew` | `@include skew($x, $y)` | Shorthand for `transform: skew()` |
| `animation` | `@include animation($animation)` | Prefixed `animation` |
| `gradient` | `@include gradient($direction, $list)` | Prefixed `linear-gradient` background |
| `background-image` | `@include background-image($deg, $colorname, $opacity)` | `linear-gradient` background |
| `x-appearance` | `@include x-appearance($value)` | Prefixed `appearance` |

The vendor-prefix mixins predate Autoprefixer. If your pipeline already runs it, you do not need them.

### `mg-typography` (from `_variables.scss`)

Sets font size with the matching padding for heading-like elements. Sizes: `"extra-small"`, `"small"`, `"medium"`, `"large"`, `"xlarge"`, `"huge"`, `"xhuge"`.

```scss
.my-heading {
  @include mg-typography("large");
  // font-size: 2rem; padding-top: var(--mg-spacing-250); padding-bottom: var(--mg-spacing-150)
}
```

### Placeholder selectors (from `_mixins.scss`)

Use with `@extend`:

| Placeholder | Purpose |
|-------------|---------|
| `%paragraph-font-100` to `%paragraph-font-300` | Responsive font sizes (smaller on mobile, larger on desktop) |
| `%border-bottom` | `border-bottom: 1px solid rgb(var(--mg-color-neutral-400))` |
| `%border-none` | `border: none` plus `background-image: none` |
| `%img-cover` | Full-width cover-fit image |
| `%img_none` | `background-image: none` |
| `%absolute__content` | Absolutely positioned `::before`/`::after` content |
| `%background-white` | `background-color: white` |

## Overriding tokens

Tokens are CSS custom properties, so you override them by declaring them in a selector — not by reassigning a variable before an import. Order does not matter and Mangrove does not need rebuilding.

```scss
// Applies to the whole document
:root {
  --mg-color-interactive: 46 125 50;      // bare RGB channels
}

// Or scoped to one brand
.mg-theme-myorg {
  --mg-color-interactive: 46 125 50;
  // These three tokens hold a finished colour, not channels — wrap them.
  --mg-color-button-background: rgb(var(--mg-color-interactive));
  --mg-color-button-background--hover: rgb(var(--mg-color-interactive-active));
  --mg-border-color-button: transparent;
}
```

Most palette tokens hold bare channels so components can composite alpha — `rgb(var(--mg-color-interactive) / 0.1)`. `--mg-color-button-background`, `--mg-color-button-background--hover` and `--mg-border-color-button` are the exception: they hold a complete colour, because a channel triple cannot express `transparent`. Assigning the wrong shape produces an invalid declaration the browser drops without an error.

The <LinkTo kind="getting-started-integration-theming-guide" story="docs">Theming guide</LinkTo> covers the token sources, the tokens you are most likely to change, and how to build a full theme.

## Importing individual component styles

If you only need specific components, import the partials directly. The full list is in `stories/assets/scss/_components.scss`.

```scss
// Import base dependencies first
@import "stories/assets/scss/variables";
@import "stories/assets/scss/fonts";
@import "stories/assets/scss/breakpoints";
@import "stories/assets/scss/mixins";
@import "stories/assets/scss/foundational";

// Then import only the components you need
@import "stories/Components/Buttons/CtaButton/buttons";
@import "stories/Components/Cards/Card/card";
@import "stories/Components/Forms/form-base";
@import "stories/Components/Tab/tab";
```

Component stylesheets depend on `_variables.scss` for `mg-rem()`, the type scale and the `:root` token block — including the five `--mg-font-family-*` roles, which every component reads and none declares a fallback for — and on `_breakpoints.scss` and `_mixins.scss` for `devicebreak()` and the focus ring. Import those first or the build fails.

`_fonts.scss` earns its place in that list twice over: it declares the `@font-face` blocks, and it carries the Arabic script map that re-points the roles. Drop it and the roles still resolve, but only to their Latin faces — Arabic text asks for Roboto, which has no Arabic coverage, and every glyph falls back to whatever the reader's OS supplies. Nothing warns you. Import it exactly once: Sass's legacy `@import` re-emits, so a second import would duplicate all 32 `@font-face` blocks.

This import list is checked by a test that compiles it and asserts both halves: the roles defined ahead of their first use, and the Arabic map present. If you shorten it, expect Times New Roman or an unstyled Arabic page.

## Build tool configuration

When compiling Mangrove's SCSS from `node_modules`, point your Sass compiler at the package root.

**Webpack:**

```javascript
// webpack.config.js
const path = require('path');

module.exports = {
  module: {
    rules: [
      {
        test: /\.scss$/,
        use: [
          'style-loader',
          'css-loader',
          {
            loader: 'sass-loader',
            options: {
              sassOptions: {
                includePaths: [
                  path.resolve(__dirname, 'node_modules/@undrr/undrr-mangrove'),
                ],
              },
            },
          },
        ],
      },
    ],
  },
};
```

**Vite:**

```javascript
// vite.config.js
import { defineConfig } from 'vite';

export default defineConfig({
  css: {
    preprocessorOptions: {
      scss: {
        includePaths: [
          'node_modules/@undrr/undrr-mangrove',
        ],
      },
    },
  },
});
```

With `includePaths` configured, imports resolve relative to the package root:

```scss
@import "stories/assets/scss/variables";
@import "stories/assets/scss/breakpoints";
@import "stories/assets/scss/mixins";
```

## Migrating from 1.x

| 1.x | 2.0 |
|-----|-----|
| `$mg-color-interactive: #2e7d32;` before the import | `:root { --mg-color-interactive: 46 125 50; }` in any stylesheet |
| `color: $mg-color-interactive` | `color: rgb(var(--mg-color-interactive))` |
| `rgba($mg-color-interactive, 0.5)` | `rgb(var(--mg-color-interactive) / 0.5)` |
| `padding: $mg-spacing-150` | `padding: var(--mg-spacing-150)` |
| `darken($mg-color-interactive, 10%)` | a computed literal, or a second token — Sass colour functions cannot take a `var()` |
| `@import "./variables-irp"` | `@import "./theme-irp"` |
| `$mg-html-font-size: 10` | not supported; serve a 16px root |

Referencing a removed variable fails the build. Assigning one does not, so check your Sass log for `Mangrove 2.0:` warnings before assuming an override took effect. The complete list of breaking changes is in the [v2.0 release notes](/docs/getting-started-release-notes-v2-0--docs).
