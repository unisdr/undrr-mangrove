# Status label

A workflow status shown as a coloured indicator followed by the status name. Use it in record and event lists, on a record's own page, and anywhere a piece of content has an editorial state a reader or editor needs to see.

CSS only. There is no React component and no JavaScript — the markup is two elements, so Drupal, Twig, and plain HTML consumers can emit it directly.

## Usage

### HTML

```html
<span class="mg-status-label mg-status-label--published">
  <span class="mg-status-label__indicator"></span>
  Published
</span>
```

The indicator is an empty `<span>`, not an icon font or an image, so it needs no alternative text. The status name is always present as real text.

### The four DELTA statuses

| Modifier                                | Label                        | Indicator | Shape   |
| --------------------------------------- | ---------------------------- | --------- | ------- |
| `.mg-status-label--draft`               | Draft                        | `#f4e496` | Square  |
| `.mg-status-label--waiting-information` | Waiting for more information | `#bcae67` | Plus    |
| `.mg-status-label--waiting-validation`  | Waiting for validation       | `#fec124` | Diamond |
| `.mg-status-label--published`           | Published                    | `#0a6969` | Circle  |

### Service health states

| Modifier                     | Typical label | Indicator             | Shape    |
| ---------------------------- | ------------- | --------------------- | -------- |
| `.mg-status-label--warning`  | Degraded      | `--mg-color-gold-800` | Triangle |
| `.mg-status-label--negative` | Offline       | `--mg-color-red-900`  | Octagon  |

They are used by [ServiceNotice](?path=/docs/components-notice-service-notice--docs) and suit any service or system health state.

Used without a modifier the indicator is neutral grey. Prefer that for a status outside this workflow rather than borrowing a colour that already means something else.

## Where these values come from

The colours, the geometry, and the four status names are taken from the DELTA design system board **"Status Labels for Records and Events"** (Elements & Patterns → 02 Components).

The colour-to-label mapping was read off the board's own swatch/label pairs. Each 44 × 44 swatch sits directly to the left of its label, and the two are vertically centred on each other to within 2px:

| Swatch (y range)      | Label (y range)                          | Centres     |
| --------------------- | ---------------------------------------- | ----------- |
| `#f4e496` (2720–2764) | Draft (2728–2758)                        | 2742 / 2743 |
| `#bcae67` (2768–2812) | Waiting for more information (2775–2805) | 2790 / 2790 |
| `#fec124` (2817–2861) | Waiting for validation (2822–2852)       | 2839 / 2837 |
| `#0a6969` (2863–2907) | Published (2869–2899)                    | 2885 / 2884 |

The dot-plus-text shape rather than a filled pill is also from the file: the board's own table example and its "Colors in Status Dropdown" both draw a 14px circle, an 8px gap, and the status name at 16px. No filled status pill appears anywhere on the design system pages.

Two of the four colours were already in Mangrove: `--mg-color-accent-100` is `#f4e496` and `--mg-color-accent-400` is `#0a6969`. The published teal differs from the Figma swatch by one unit in the blue channel (`#0a6969` vs `#0a696a`) — the existing token is used rather than a near-duplicate. `--mg-color-accent-500` and `--mg-color-accent-600` were added for the remaining two.

## Shape as well as colour

Each status has its own shape. This is not a fix for a WCAG failure — the status name is always rendered as text next to the indicator, so the meaning is not carried by colour alone. Three other things make the second cue worth having.

**Some of the colours are close to each other under colour vision deficiency.** Simulating the six indicator colours (Machado et al. matrices, full severity) and comparing them as CIE76 deltaE gives:

| Pair                                                  | Normal | Protanopia | Deuteranopia | Tritanopia |
| ----------------------------------------------------- | ------ | ---------- | ------------ | ---------- |
| Degraded / Offline                                    | 58.6   | 25.2       | **3.4**      | 59.4       |
| Draft / Waiting for more information                  | 19.6   | **19.5**   | **19.5**     | **19.0**   |
| Neutral / Draft                                       | 42.9   | 43.8       | 43.0         | **18.3**   |
| Waiting for more information / Waiting for validation | 43.7   | 40.6       | 40.3         | **20.3**   |
| Neutral / Published                                   | 48.9   | 40.5       | 44.4         | 48.6       |

Degraded and Offline are effectively the same olive dot for a reader with deuteranopia. Draft and "waiting for more information" sit around 19 deltaE for everyone, colour-blind or not. Under tritanopia the four pale statuses converge into one cluster.

**The component is CSS only.** Consumers write their own markup, so the indicator will be reused without its label — in a table cell, a card corner, a filter chip. Mangrove cannot stop that, and when it happens the colour really is the only cue. A shape keeps those uses legible.

**A second cue is faster for everyone.** Scanning a long list for "everything still in draft" is a shape-matching task, not a reading task.

The mapping is conventional rather than arbitrary, so the marks carry their usual meaning where they have one:

| Status                       | Shape    | Why                                                                   |
| ---------------------------- | -------- | --------------------------------------------------------------------- |
| No modifier                  | Circle   | Unchanged. The base class names no status, so it keeps the plain dot. |
| Draft                        | Square   | A flat, inert block — nothing has moved yet.                          |
| Waiting for more information | Plus     | Something more is needed before the record can move.                  |
| Waiting for validation       | Diamond  | The flowchart decision mark — someone else has to make a call.        |
| Published                    | Circle   | Unchanged. The settled end state, and the mark the DELTA board draws. |
| Degraded                     | Triangle | The caution triangle.                                                 |
| Offline                      | Octagon  | The stop sign.                                                        |

Published and the neutral base share the circle. Their colours are the pair that stays furthest apart in every simulation (40+ deltaE), so shape is not what has to separate them.

## Accessibility

- **SC 1.4.1 Use of colour.** The status name is always rendered as text, so the indicator is reinforcement, never the message. Do not build an indicator-only variant. The shapes are a second cue on top of that, not the thing that satisfies the criterion.
- **SC 1.4.3 Contrast (minimum).** The label text resolves to `--mg-color-text` (`#1a1a1a`), 17.40:1 on a white page and 15.63:1 on a tinted panel.
- **SC 1.4.11 Non-text contrast.** The four indicator fills are 1.28:1 (draft), 1.63:1 (waiting for validation), 2.24:1 (waiting for more information) and 6.49:1 (published) against white. Three of the four would be close to invisible unbounded, so every indicator carries a 1px `--mg-color-neutral-500` ring at 5.74:1. Because the dots are decorative the ring is not strictly required by 1.4.11, but without it the component looks broken on a white page. Set `--mg-status-label-indicator-border-width: 0` to remove it. On the circle and the square the ring is a real `border`, exactly `--mg-status-label-indicator-border-width` wide. On the four clipped shapes a border would be cut through by the clip path, so the ring is the indicator's own background showing around an inset `::before`. Both read the same two tokens, and `--mg-status-label-indicator-border-width: 0` removes the ring on all seven, but the clipped four do not render it at a uniform width: insetting the box shrinks the polygon instead of offsetting its edges, so the ring is the full width on the octagon and along the triangle's base, around 0.7px on the diamond, about a third of the token on the plus's inner corners, and pinches to nothing at the triangle's apex. Treat it as a boundary on the silhouette rather than a measured stroke, and raise `--mg-status-label-indicator-border-width` if a particular surface needs a heavier edge.
- **Forced colours.** Windows High Contrast repaints every background in a system colour, which would leave the fills identical and the shapes doing all the work. The indicators opt out of forcing and redraw themselves: each named status is a solid `CanvasText` shape, and the base indicator keeps a `Canvas` centre so it stays the one hollow mark. The offline octagon is chamfered at 20% rather than the 29.3% of a regular octagon, which is the most circle-like octagon there is, so its silhouette still separates from the published circle at 14px in this mode.
- **Grouping.** When several statuses appear together as a legend, use `.mg-status-label-group` on a `<ul>` so screen readers announce the count.
- **RTL.** The component is laid out with flex and logical properties. The indicator moves to the right of the text under `dir="rtl"` with no extra CSS. Every shape is symmetrical about its vertical axis, so none of them needs mirroring.
- **Zoom.** The indicator sizes are multiples of `--mg-status-label-indicator-size`, which is set in `rem`, so the shapes scale with browser zoom and with a larger default font size.
- **Print.** The clipped shapes have no border, so both their ring and their fill are `background-color`, and a browser printing with background graphics off would drop them while the circle and the square kept their border. A `@media print` block declares those backgrounds essential so all seven marks survive, the same fix `icons.scss` makes for mask-image icons. A host page whose print reset sets `background: transparent !important` will still clear them; the status name is text, so the row still reads.
- **Alignment.** The shapes have different bounding boxes, but each one is pulled back to `--mg-status-label-indicator-size` of inline space with a compensating `margin-inline`, so a column or a table cell of statuses keeps one text alignment edge and the larger marks overhang it slightly, as an optically centred glyph should.

## Design tokens

| Token                                              | Default                  | Description                                    |
| -------------------------------------------------- | ------------------------ | ---------------------------------------------- |
| `--mg-status-label-gap`                            | `--mg-spacing-75`        | Space between indicator and text               |
| `--mg-status-label-font-size`                      | `16px`                   | Label text size                                |
| `--mg-status-label-color`                          | `--mg-color-text`        | Label text colour                              |
| `--mg-status-label-indicator-size`                 | `14px`                   | Indicator size; each shape is a multiple of it |
| `--mg-status-label-indicator-radius`               | `50%`                    | Corner radius of the base indicator            |
| `--mg-status-label-indicator-border-width`         | `1px`                    | Indicator ring width                           |
| `--mg-status-label-indicator-border-color`         | `--mg-color-neutral-500` | Indicator ring colour                          |
| `--mg-status-label-indicator`                      | `--mg-color-neutral-100` | Neutral indicator fill                         |
| `--mg-status-label-indicator--draft`               | `--mg-color-accent-100`  | Draft                                          |
| `--mg-status-label-indicator--waiting-validation`  | `--mg-color-accent-500`  | Waiting for validation                         |
| `--mg-status-label-indicator--waiting-information` | `--mg-color-accent-600`  | Waiting for more information                   |
| `--mg-status-label-indicator--published`           | `--mg-color-accent-400`  | Published                                      |

`--mg-status-label-indicator-radius` shapes the base indicator and the published circle. The five status shapes set their own geometry, so changing the radius does not round them off.

### Theming

No sub-brand overrides these tokens. PreventionWeb, IRP and MCR2030 have no defined workflow status palette, so they inherit DELTA's; a brand that needs its own should redefine the four `--mg-status-label-indicator--*` properties inside its `.mg-theme-*` block rather than restyling the modifiers.
