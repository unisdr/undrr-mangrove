# UNDRR logos

The UNDRR logo is a keystone element of the identity and is used to represent the entire organization.

### Overview

The UNDRR logo is the keystone element of the identity program and should be used to represent the entire organization.

When to use:

- To promote business.
- To create an identity for the organization.

### Formatting

#### Default

Within the design system, the logo is used in the header and footer components. The logo is available in blue or white.

### Content

A well-established and consistently presented identity is a very valuable asset. To protect and strengthen the trademark status of the logo, the approved versions must not be altered, modified, changed, or added to in any way.

### Translated logos

Language-specific wordmarks are published to [assets.undrr.org](https://assets.undrr.org/logos/undrr/), one raster PNG per language/color combination (`undrr-logo-{lang}-{color}.png`). Color coverage varies by language:

| Language | Colors available | Published |
| --- | --- | --- |
| Arabic (`ar`) | black, blue, white | white pending CDN publish (undrr/web-backlog#3061) |
| Spanish (`es`) | black, blue, white | yes |
| French (`fr`) | black, blue, white | white pending CDN publish (undrr/web-backlog#3061) |
| Russian (`ru`) | black, blue, white | white pending CDN publish (undrr/web-backlog#3061) |
| Chinese (`zh`) | black, white | white pending CDN publish (undrr/web-backlog#3061); no blue (not available in a web-ready format) |

The "pending CDN publish" white assets are already wired into `undrr-logo-assets.js` — the URL, `lang`, and dimensions are correct, but the file doesn't exist at assets.undrr.org yet, so requesting one of those today loads a broken image rather than falling back to English. This is deliberate: the catalog can't distinguish "not published yet" from "never will be," so it treats a listed entry as real. Remove the `white` entry for a language from `UNDRR_LOGO_LOCALES` if that turns out to be the wrong call before these ship.

The blue/white stories above resolve these automatically via `getUndrrLogoAsset` (`undrr-logo-assets.js`) — switch Storybook's Locale toolbar rather than reaching for a language/color combination directly. The `black` color isn't surfaced by any story (only `blue`/`white` are used by the default logo and page header); call `getUndrrLogoAsset(locale, 'black')` directly if you need it.

Pass the `lang` prop (a BCP 47 tag matching the wordmark's language) as correct, valid markup — treat it as a hint rather than a guarantee, since screen readers generally read `alt` text using the page's ambient language and support for honoring `lang` set directly on an `<img>` varies by browser/AT combination.

**Do not combine translated logos with `crop="autocrop"`** (below): the translated PNGs are ~2.3-2.9:1 (roughly square, with the localized subtitle stacked on its own line), not the ~6.6:1 of the default English horizontal wordmark the crop box is tuned for. Verified by simulating the crop: it cuts the bottom off the subtitle line rather than fitting it.

### Autocropping variant

Set `crop="autocrop"` to crop the logo to a fixed box below the desktop breakpoint instead of shrinking the whole image with `object-fit: contain`. This keeps the wordmark legible at small sizes and is what the [page header](?path=/docs/components-pageheader--docs) ("black bar") uses by default. The crop box is tuned for the default English horizontal wordmark's aspect ratio only — re-check it in `logo.scss` before applying it to any other asset. This story is also locale-smart, and deliberately drops `autocrop` whenever the Locale toolbar resolves a translated asset rather than crop it incorrectly — the same resolution `PageHeader`'s `locale` prop does. Note Spanish is the only translated white asset actually live today (see the coverage table above).
