# Table

When you need to present large datasets in a way that's actually readable (and doesn't make users want to throw their laptop out the window), tables are your best friend. All tables require the `.mg-table` class as the foundation.

### When to use tables

- **Large datasets:** When you have substantial amounts of structured data
- **Comparative data:** Perfect for side-by-side comparisons
- **Scannable information:** Users need to quickly find specific data points
- **Reports and analytics:** Financial data, metrics, or any tabular reporting

### Column alignment

Table content starts at the logical inline edge by default, so text remains easy to scan in both left-to-right and right-to-left layouts. Apply `.mg-table__cell--center` only to content that benefits from centring, such as a compact status, and `.mg-table__cell--end` to numeric columns that should align for comparison. `.mg-table__cell--start` explicitly restores the default when a cell must override a broader alignment rule.

### Scrollable table

For wide tables, `responsive="scroll"` now renders a `.mg-table-scroll-region` around the native table. The region is keyboard-focusable and has an accessible name; translate the optional `scrollLabel` prop for the page language. Default and stacked markup remain unchanged. The legacy `.mg-table--scroll` class is retained, but new plain HTML should use a wrapper:

```html
<div
  class="mg-table-scroll-region"
  role="region"
  aria-label="Disaster records"
  tabindex="0"
>
  <table class="mg-table"><!-- headers and cells --></table>
</div>
```

Default cells have more breathing room; `.mg-table--small` retains compact density. Long prose wraps naturally. The scroll region keeps wide columns together without making the page itself scroll horizontally.

## Technical notes

Striped tables work especially well for financial data or any content where users need to track across multiple columns — the alternating row colors act as visual guides.

> **Implementation note (for contributors):** The component automatically applies CSS classes based on your props, building combinations like `mg-table mg-table--small mg-table--striped mg-table--stacked` for complex layouts.

### CSS class structure

- **Base:** `mg-table` (required on all tables)
- **Size:** `mg-table--small` (large is default)
- **Styling:** `mg-table--striped`, `mg-table--border`
- **Responsive:** `mg-table--stacked`, `mg-table--scroll`
- **Cell alignment:** `mg-table__cell--start`, `mg-table__cell--center`, `mg-table__cell--end`

### Class combinations

Combine modifier classes to get the right table for your context:

```html
<!-- Small, striped, stacks on mobile -->
<table class="mg-table mg-table--small mg-table--striped mg-table--stacked">
  …
</table>

<!-- Bordered, auto-responsive (uses JS or CSS container) -->
<table class="mg-table mg-table--border mg-table--auto">…</table>

<!-- Default table — no modifiers needed -->
<table class="mg-table">…</table>
```

## Usage guidelines

The table component handles all the responsive heavy lifting for you, so you can focus on your content rather than wrestling with CSS breakpoints. Mix and match variants to create exactly the table experience your users need.

### Accessibility considerations

- Tables include proper semantic structure with `thead` and `tbody`
- Scrollable tables are keyboard navigable with `tabIndex="0"`
- RTL (right-to-left) language support is built-in
