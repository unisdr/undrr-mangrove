# Vertical card

A content teaser card in portrait/stacked layout. Image on top, text below. Used across all UNDRR sites for news, events, publications, and general content listings.

## When to use

- Content listings and search results in grid layouts
- News and event teasers
- Any content that benefits from a prominent image above a title and summary

## Anatomy

- **Image** (optional): 16:9 aspect ratio, full width of the card
- **Labels** (optional): Content type or category tags
- **Title**: Linked heading with blue color, underline, and chevron indicator
- **Summary** (optional): Body text, supports inline HTML links
- **CTA button** (optional): Primary action button

The entire card is clickable via a stretched link on the title.

## Cards together

Let the containing grid or flex row stretch its items to the tallest sibling.
Vertical cards fill that space, keep their image at 16:9, and push the final CTA
to the bottom. Standalone cards keep their natural height. Each wrapped row sizes
independently; no fixed card height or text truncation is needed.

### Responsive grid

Place cards directly in a CSS grid with its default stretch alignment. Resize
this example to compare rows, including cards without an image or action.

### Flex rows and wrappers

Use `align-items: stretch` on the row. If your CMS adds a wrapper around each
card, make that wrapper `display: flex` too so the card can stretch inside it.
An ancestor using `align-items: start` or a block wrapper will keep cards at their
natural height; the card cannot determine its siblings' height on its own.

Use the `variant` prop to change the title accent color. These match the Hero component color system and adapt per theme.

| `primary` (default) | —                     | `$mg-color-interactive` (blue) |

## Title link visibility

By default, card titles display three signals that they are clickable:

1. **Blue color** matching the theme's interactive color (adapts per theme)
2. **Underline** with a 3px offset
3. **Chevron indicator** pointing right (flips left automatically in RTL layouts)

On hover, the underline intensifies.

### Opting out

To disable link visibility signals (for example, on cards where the title should look like a plain heading), add the `mg-card--plain-title` class.

**In React:**

```jsx
<VerticalCard data={data} className="mg-card--plain-title" />
```

**In Drupal templates or static HTML:**

```html
<article class="mg-card mg-card__vc mg-card--plain-title">...</article>
```

This removes the blue color, underline, and chevron. The card remains clickable via the stretched link.

<Canvas of={VerticalCardStories.PlainTitleVerticalCard} />

> **Implementation note (for contributors):** The chevron is a CSS border triangle rendered via the `::after` pseudo-element on the title link. On hover, the underline stroke increases to `2px`. RTL flipping is applied via a `[dir="rtl"]` CSS selector.

## Cards without links

A card should almost always be a link. The whole surface is a click target, the title carries the affordances, and a reader who has understood the card knows what activating it will do. Prefer that.

In practice unlinked cards happen anyway — an editor leaves the link field empty, a referenced node is unpublished, or the card exists only to carry a button. Mangrove handles that case explicitly rather than leaving it to chance.

Omit `link` (or pass an empty string) and the card renders its title as plain text. There is no anchor, so there is no chevron, no underline, no interactive colour, no stretched click target, and no hover elevation. Labels stay visible but drop the interactive modifier. The card still sits at the same height as its linked neighbours in a group.

<Canvas of={VerticalCardStories.NoLinkVerticalCard} />

### A button instead of a card link

For a card whose only destination is its button, set `buttonLink` and leave `link` empty. The title stays plain text and the CTA is an ordinary in-flow link, so there is exactly one thing to click and it is visibly the thing you meant to click.

```jsx
<VerticalCard
  data={[
    {
      title: 'Jobs and Careers',
      summaryText: 'Stay current on the latest vacancies.',
      button: 'Browse vacancies',
      buttonLink: 'https://www.preventionweb.net/community/careers',
    },
  ]}
/>
```

`buttonLink` falls back to `link` when omitted, so a card that sets only `link` behaves exactly as before.

<Canvas of={VerticalCardStories.ButtonOnlyVerticalCard} />

Linked and unlinked cards frequently sit in the same row. They should read as one family: same height, same spacing, same type — differing only in whether the title is interactive.

### Repairing `href=""` from Drupal Gutenberg

Drupal Gutenberg has been emitting `<a href="">` for unlinked cards. An empty `href` is not "no link" to a browser — it resolves to the current page, so the title takes keyboard focus, activating it reloads the page, and the stretched overlay covers the card and swallows clicks aimed at the button beside it.

`card.scss` neutralises that markup: `.mg-card__title a[href=""]` and `.mg-card__title a:not([href])` lose the chevron, the stretched overlay, the interactive colour and the pointer cursor. Already-published content is repaired without an upstream change.

CSS cannot remove the anchor from the tab order, so this is mitigation, not a fix. Producers of card markup should emit a plain-text title when there is no destination:

```html
<header class="mg-card__title">Jobs and Careers</header>
```

## Props

| Prop        | Type   | Default     | Description                                                             |
| ----------- | ------ | ----------- | ----------------------------------------------------------------------- |
| `data`      | Array  | Required    | Array of card data objects                                              |
| `variant`   | String | `'primary'` | Color variant: `'primary'`, `'secondary'`, `'tertiary'`, `'quaternary'` |
| `className` | String | —           | Additional CSS classes on the card element                              |

### Data object properties

| Property      | Type   | Description                                                                                             |
| ------------- | ------ | ------------------------------------------------------------------------------------------------------- |
| `title`       | String | Card heading text                                                                                       |
| `link`        | String | URL for the title link and stretched link. Omit it, or pass an empty string, to render an unlinked card |
| `target`      | String | Optional browsing context shared by the title and CTA links                                             |
| `rel`         | String | Optional link relationship shared by the title and CTA links                                            |
| `imgback`     | String | Image URL                                                                                               |
| `imgalt`      | String | Alt text for the image                                                                                  |
| `summaryText` | String | Body text (HTML supported)                                                                              |
| `label1`      | String | First category label                                                                                    |
| `label2`      | String | Second category label                                                                                   |
| `button`      | String | CTA button label                                                                                        |
| `buttonLink`  | String | CTA destination. Defaults to `link`; set it to give an unlinked card a button                           |

## Accessibility

- The entire card surface is clickable as a single link (via the title link) — but only when the card has a destination. An unlinked card renders a plain-text title, so it exposes no link role and takes no place in the tab order
- Inline links in the summary remain independently clickable (`z-index: 2`) — they are not overridden by the card link
- Focus states are visible on all interactive elements
- RTL layout is automatic when `dir="rtl"` is set on the document

> **Implementation note (for contributors):** The card-wide click area uses a CSS `::before` pseudo-element on the title `<a>`, stretched to cover the full card. Inline links in the summary have `z-index: 2` to layer above the stretched link overlay.
