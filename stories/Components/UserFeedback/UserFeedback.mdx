# User feedback

A compact page-level prompt for quick usefulness feedback plus an optional
issue-report link. It is distilled from the
[UNDRR microsites pattern](https://gitlab.com/undrr/drupal-microsites/-/commit/d74d9ab342fec6cbbaeeebf026f116e4da3bbecf)
and aligned with Mangrove theme, translation, and hydration contracts.

## When to use

- Place it near the end of a content page, typically immediately before `Footer`.
- Use the binary response for low-friction analytics, not as a substitute for user research.
- Keep the issue link available when a product has a team or workflow that can act on reports.

UserFeedback and Footer remain separate components. Stack them as adjacent
siblings; do not nest one inside the other.

## React

```jsx
import { UserFeedback } from '@undrr/undrr-mangrove';
import SiteFooter from './SiteFooter';

const recordResponse = response => {
  analytics.track('page_feedback', { response });
};

export default function PageEnd() {
  return (
    <>
      <UserFeedback
        feedbackUrl="/contact/website-feedback"
        onResponse={recordResponse}
      />
      <SiteFooter />
    </>
  );
}
```

`onResponse` receives `"yes"` or `"no"`. Mangrove does not store responses; the
consuming product owns analytics, consent, and retention.

## Hydration

Render an empty container with component data. Localised labels are optional and fall back to English individually.

```html
<div
  data-mg-user-feedback
  data-feedback-url="/contact/website-feedback"
  data-question="Is this page useful?"
  data-yes-label="Yes"
  data-no-label="No"
  data-report-issue-label="Report an issue on this page"
></div>
```

```js
import createHydrator from '@undrr/undrr-mangrove/components/hydrate.js';
import UserFeedback, {
  fromElement,
} from '@undrr/undrr-mangrove/components/UserFeedback.js';

createHydrator({
  selector: '[data-mg-user-feedback]',
  component: UserFeedback,
  fromElement,
});
```

## Static HTML

When JavaScript is unavailable, render the initial prompt as useful static HTML and submit responses through product-owned URLs or a small progressive-enhancement script. Do not render inert Yes/No buttons.

```html
<section
  class="mg-user-feedback mg-container mg-grid mg-grid__col-2"
  aria-label="Is this page useful?"
  data-vf-google-analytics-region="undrr-feedback-container"
>
  <div class="mg-user-feedback__prompt">
    <h2 class="mg-user-feedback__question">Is this page useful?</h2>
    <div class="mg-user-feedback__actions">
      <a class="mg-button mg-button-secondary" href="/feedback?response=yes">
        Yes
      </a>
      <a class="mg-button mg-button-secondary" href="/feedback?response=no">
        No
      </a>
    </div>
  </div>
  <a
    class="mg-user-feedback__issue"
    data-mg-user-feedback-form
    data-mg-user-feedback-type="report-issue"
    href="/contact/website-feedback"
  >
    Report an issue on this page
  </a>
</section>
```

## Behavior and accessibility

- Yes and No are native buttons and work with Enter and Space.
- Selecting a response replaces the prompt with a polite confirmation and moves focus to it, so keyboard and screen-reader users do not lose their place.
- The detailed-feedback link in the initial prompt stays in the current tab. The optional follow-up link opens a new tab and uses `noopener noreferrer`.
- The section has a stable accessible name after the visible question is replaced.
- Logical alignment supports RTL, labels wrap at narrow widths, and existing button tokens provide focus, forced-colour and reduced-motion behavior.
- Existing `data-vf-google-analytics-region` and `data-mg-user-feedback-*` hooks preserve the source pattern's analytics integration points.
