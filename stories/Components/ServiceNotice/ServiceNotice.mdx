# Service notice

An in-page notice or card overlay shown when an embedded third-party service (such as MapX, an external analytics feed, or an API endpoint) is unreachable or running in a degraded state.

It shows a degraded or offline status badge, an explanation, a retry action, a link to an external status page, and optional automatic retries. It renders through the [Notice](?path=/docs/components-notice-notice--docs) component, so it inherits its layout, tokens, compact and overlay modifiers.

## Automatic retry

Set `countdownSeconds` together with `onRetry` to retry automatically. After each attempt the wait doubles (for example 15s, 30s, 60s), and after `maxAutoRetries` attempts (default 3) the countdown stops and only the manual retry button remains. This keeps a hard outage from being polled indefinitely.

When the service recovers, remove the notice. Changing `countdownSeconds` starts a new retry cycle.

## Integration

### 1. Pure HTML / CSS

```html
<div class="mg-notice mg-notice--warning">
  <div class="mg-notice__header">
    <span
      class="mg-icon mg-icon-exclamation-triangle mg-notice__icon"
      aria-hidden="true"
    ></span>
    <h3 class="mg-notice__title">MapX layer service degraded</h3>
    <span class="mg-status-label mg-status-label--warning">
      <span class="mg-status-label__indicator" aria-hidden="true"></span>
      Degraded
    </span>
  </div>
  <div class="mg-notice__description">
    <p>
      Geospatial tiles are taking longer than usual to render. Cached layers
      remain accessible.
    </p>
  </div>
  <div class="mg-notice__actions mg-buttons">
    <button type="button" class="mg-button mg-button-primary">
      <span
        class="mg-icon mg-icon-refresh mg-button__icon"
        aria-hidden="true"
      ></span>
      Retry connection
    </button>
    <a
      href="https://messaging.undrr.org/"
      target="_blank"
      rel="noopener noreferrer"
      class="mg-button mg-button-secondary mg-button-outline"
    >
      View status page
      <span class="mg-u-sr-only">(opens in a new tab)</span>
      <span
        class="mg-icon mg-icon-external-link mg-button__icon"
        aria-hidden="true"
      ></span>
    </a>
  </div>
</div>
```

The markup is a [Notice](?path=/docs/components-notice-notice--docs) with a [StatusLabel](?path=/docs/components-status-label--docs) in its header; there is no separate `mg-service-notice` stylesheet. A retry countdown uses `mg-notice__meta` inside the actions row. The offline state swaps in `mg-notice--negative`, `mg-icon-power-off` and `mg-status-label--negative`. Static HTML should announce the outage itself if it is injected after page load (for example with a `role="status"` region).

This markup is presentation only. The retry button has no handler, no countdown runs and nothing is announced. If you need a working retry without React code of your own, use the hydration contract below instead of copying this HTML.

### 2. Drupal Twig with React hydration

```twig
<div data-mg-service-notice
  data-title="{{ 'MapX service unreachable'|t }}"
  data-description="{{ 'Unable to establish a secure connection to the map tile server.'|t }}"
  data-status="offline"
  data-retry
  data-retry-label="{{ 'Reconnect'|t }}"
  data-status-url="https://messaging.undrr.org/"
  data-status-url-label="{{ 'Check status'|t }}"
  data-countdown-seconds="30"
  data-max-auto-retries="3">
</div>
```

```javascript
import createHydrator from '@undrr/undrr-mangrove/src/hydrate';
import ServiceNotice, {
  fromElement,
} from '@undrr/undrr-mangrove/stories/Components/ServiceNotice/ServiceNotice.hydrate';

const hydrator = createHydrator({
  selector: '[data-mg-service-notice]',
  component: ServiceNotice,
  fromElement,
});

Drupal.behaviors.mangroveServiceNotice = {
  attach(context) {
    hydrator.update(context);
    // once() (core/once): one listener per container across attaches.
    once(
      'mg-service-notice-retry',
      '[data-mg-service-notice]',
      context
    ).forEach(el => {
      el.addEventListener('mg-service-notice:retry', () => {
        // Re-fetch your data here, then remove the notice once it loads.
        console.log('Retry requested');
      });
    });
  },
};
```

Drupal calls `attach` again for every AJAX response, BigPipe placeholder and modal, often with a context that contains containers it has already seen. `once()` keeps the listener to one per container; add `core/once` to your library's dependencies.

With `data-retry` present, the retry button and every automatic retry dispatch a bubbling `mg-service-notice:retry` event on the container. Without `data-retry`, no retry button or countdown is rendered. Title and description are read as plain text.

### Hydration contract

The container must carry `data-mg-service-notice`. Everything else is optional.

| Attribute                | Maps to            | Notes                                                                                                                                              |
| ------------------------ | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data-title`             | `title`            | Plain text. Falls back to the text of a child `.mg-notice__title`.                                                                                 |
| `data-description`       | `description`      | Plain text. Falls back to the text of a child `.mg-notice__description`.                                                                           |
| `data-status`            | `status`           | `offline`; any other value gives `degraded`.                                                                                                       |
| `data-heading-level`     | `headingLevel`     | `h2` to `h6`.                                                                                                                                      |
| `data-is-compact`        | `isCompact`        | `"true"` (preferred). The `mg-notice--compact` class on the container also works; it is removed on hydration so the container is not styled twice. |
| `data-is-overlay`        | `isOverlay`        | `"true"` (preferred). The `mg-notice--overlay` class on the container also works; it is removed on hydration so the container is not styled twice. |
| `data-retry`             | `onRetry`          | Boolean attribute. Renders the retry button and dispatches `mg-service-notice:retry`.                                                              |
| `data-retry-label`       | `retryLabel`       | Retry button text.                                                                                                                                 |
| `data-status-url`        | `statusUrl`        | http or https only; other schemes are ignored.                                                                                                     |
| `data-status-url-label`  | `statusUrlLabel`   | Status link text.                                                                                                                                  |
| `data-countdown-seconds` | `countdownSeconds` | Needs `data-retry`.                                                                                                                                |
| `data-max-auto-retries`  | `maxAutoRetries`   | Defaults to 3.                                                                                                                                     |
| `data-labels`            | `labels`           | JSON object of translated strings, using the keys listed under Translations.                                                                       |

| Event                     | Dispatched on           | When                                                                                        |
| ------------------------- | ----------------------- | ------------------------------------------------------------------------------------------- |
| `mg-service-notice:retry` | The container (bubbles) | The retry button is pressed or an automatic retry fires. Only when `data-retry` is present. |

The same contract is published for AI agents in the `hydration` field of `ai-components/components-notice-service-notice.json`.

### 3. Vanilla HTML page (CDN)

No build step is needed. Load the Mangrove stylesheet, load React through an import map, render an empty container and hydrate it from the CDN. Replace `{version}` with the Mangrove release you use.

```html
<link
  rel="stylesheet"
  href="https://assets.undrr.org/mangrove/{version}/css/style.css"
/>

<script type="importmap">
  {
    "imports": {
      "react": "https://esm.sh/react@19.3.0",
      "react-dom": "https://esm.sh/react-dom@19.3.0",
      "react-dom/": "https://esm.sh/react-dom@19.3.0/"
    }
  }
</script>

<div
  id="map-notice"
  data-mg-service-notice
  data-title="Map service temporarily unavailable"
  data-description="Unable to connect to the tile server."
  data-status="offline"
  data-retry
  data-status-url="https://messaging.undrr.org/"
  data-countdown-seconds="30"
  data-max-auto-retries="3"
></div>

<script type="module">
  import createHydrator from 'https://assets.undrr.org/mangrove/{version}/components/hydrate.js';
  import ServiceNotice, {
    fromElement,
  } from 'https://assets.undrr.org/mangrove/{version}/components/ServiceNotice.js';

  createHydrator({
    selector: '[data-mg-service-notice]',
    component: ServiceNotice,
    fromElement,
  });

  document
    .getElementById('map-notice')
    .addEventListener('mg-service-notice:retry', () => {
      // Re-fetch your data here, then remove the notice once it loads.
      console.log('Retry requested');
    });
</script>
```

## Accessibility

- The component includes a visually hidden `role="status"` region. It is filled just after mount, so the status and title are announced even when the notice appears already populated (for example as an overlay). It is updated again when an automatic retry is scheduled and when automatic retries stop.
- The visible countdown is `aria-hidden`, because announcing every second would drown out everything else. Screen reader users hear "Retrying automatically in N seconds" once per attempt instead.
- The status badge pairs a coloured dot with visible text (Degraded / Offline), satisfying WCAG 2.2 SC 1.4.1 (Use of Color).
- The status page link opens in a new tab with `rel="noopener noreferrer"`. Visually hidden text ("(opens in a new tab)", overridable with `labels.opensInNewTab`) tells screen reader users before they follow it (technique [G201](https://www.w3.org/WAI/WCAG22/Techniques/general/G201), supporting the Level AAA SC 3.2.5 Change on Request).
- `headingLevel` lets the title fit the page's heading outline instead of forcing `h3`.

## Translations

Labels are provided for the six UN official languages. The non-English strings are drafts and need native-speaker review before release.

Pass overrides with the `labels` prop, or the `data-labels` JSON attribute when hydrating. The keys are `retryLabel`, `statusUrlLabel`, `opensInNewTab`, `statusDegraded`, `statusOffline`, `countdownPrefix`, `countdownAnnouncement` (with a `{seconds}` token) and `autoRetryStopped`.
