## Usage

```jsx
import { MegaMenu } from '@components';

// Default (no logo)
<MegaMenu sections={menuItems} />

// Branded variant (with logo)
<MegaMenu
  sections={menuItems}
  logoSrc="https://assets.undrr.org/logos/pw/pw-logo.svg"
  logoAlt="PreventionWeb"
/>
```

### Multilingual sites and language-prefixed logo links

Pass the language-prefixed root path to `logoHref` (for example, `"/ar/"` for Arabic). In Drupal, output this from Twig into the `data-mg-mega-menu-logo-href` attribute:

```html
<div
  data-mg-mega-menu
  data-mg-mega-menu-logo-src="https://assets.undrr.org/logos/pw/pw-logo.svg"
  data-mg-mega-menu-logo-alt="PreventionWeb"
  data-mg-mega-menu-logo-href="/ar/"
></div>
```

`logoHref` defaults to `'/'`. If logo asset attributes are absent, the Drupal
wrapper resolves `logoSrc` and `logoAlt` from body class; it does not infer
`logoHref`, so pass language-prefixed roots explicitly.

## Props

| Prop             | Type    | Default   | Description                                                                                                 |
| ---------------- | ------- | --------- | ----------------------------------------------------------------------------------------------------------- |
| sections         | array   | []        | Array of menu sections to display                                                                           |
| delay            | number  | 300       | Delay in milliseconds before closing menu on mouse leave                                                    |
| hoverDelay       | number  | 180       | Delay in milliseconds before opening menu (prevents accidental opens)                                       |
| logoSrc          | string  | —         | Image URL for the logo. When provided, enables the branded variant                                          |
| logoAlt          | string  | ''        | Alt text for the logo image                                                                                 |
| logoHref         | string  | '/'       | Where the logo links to. For multilingual sites, pass the language-prefixed root from the CMS (e.g. `/ar/`) |
| logoWidth        | number  | —         | Optional explicit width for CLS prevention                                                                  |
| logoHeight       | number  | —         | Optional explicit height for CLS prevention                                                                 |
| enableFilter     | boolean | false     | Enable a contextual menu-finder dialog from desktop left columns and filtering in the mobile drawer         |
| enableSiteSearch | boolean | true      | Offer full-site search option when filtering (default: true)                                                |
| searchUrl        | string  | '/search' | Base URL for full-site search fallback (defaults to syndicated search page /search#query=)                  |

### Section object properties

| Property          | Type   | Required | Description                                                                                                                               |
| ----------------- | ------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| title             | string | Yes      | Top-level menu item label                                                                                                                 |
| icon              | string | No       | Icon class name shown before the title (e.g., `"mg-icon mg-icon-chart-bar"`). Desktop topbar only; hidden in mobile sidebar.              |
| bannerHeading     | string | No       | Heading text shown in the mega content panel                                                                                              |
| bannerDescription | string | No       | Description shown in the mega content panel. Rendered as unsanitised HTML — see [Banner HTML trust contract](#banner-html-trust-contract) |
| bannerButton      | object | No       | `{ url, label }` — when present, the top-level item renders as an `<a>` link                                                              |
| items             | array  | No       | Array of sub-items (triggers mega dropdown when present)                                                                                  |

### Banner HTML trust contract

`bannerDescription` accepts caller-sanitised HTML in desktop banners,
no-items panels and the mobile sidebar. Sanitise it when building `sections`
from CMS/API data, whether passed as a prop or through `data-sections`.
Drupal's filtered text formats can provide this boundary; otherwise use a
sanitiser such as [DOMPurify](https://github.com/cure53/DOMPurify):

```js
import DOMPurify from 'dompurify';

const sections = apiSections.map(section => ({
  ...section,
  bannerDescription: DOMPurify.sanitize(section.bannerDescription),
}));
```

Mangrove does not sanitise this field. The desktop check for `<` selects a
text wrapper or HTML rendering; it is not a filter. `bannerHeading` is plain text.

## Accessibility

### Keyboard navigation

- **← / →** move between top-level items; focusing an item opens its panel.
- **↓** enters the desktop panel. **Tab / Shift+Tab** move through its controls.
- **Escape** closes the current surface and restores its trigger. Inactive
  panels are inert and hidden from assistive technology.
- Mobile dialogs contain Tab focus; arrows retain native behaviour. Entering a
  level focuses its heading; Back restores the previous row and scroll position.
  See [mobile navigation](#mobile-progressive-navigation).

### ARIA attributes

The root is a labelled `<nav>` containing a plain list, without a `menubar`
role. Top-level links/buttons expose `aria-expanded` where a panel exists.
Each panel is a labelled live region with section-specific category/submenu
landmarks. Desktop nested lists retain `menu`/`menuitem` roles, and the selected
category uses `aria-current="page"`.

The mobile opener exposes `aria-expanded`, `aria-controls` and
`aria-haspopup="dialog"`. The dialog is labelled by its current-level heading;
its links and drill-in buttons use native semantics. A branded logo's accessible
name comes from `logoAlt`, falling back to “Home”.

### Find links inside navigation

Set `enableFilter` to search **all menu destinations**, regardless of the
section used to open the finder. The site's Search navigation item is unchanged.

**Desktop:** panels with a left introduction/categories column show **Find in
menu** in a fixed footer. It opens a native modal with a focused input. Results
scroll independently of the input, icon-only Close button and site-search footer.
Close, Escape or a backdrop click restores the footer button while preserving the
underlying category and scroll position. Clear stays in the dialog. Closing the
parent, switching to mobile, disabling filtering or removing the utility clears
the finder; it does not reopen automatically. If the utility disappears, focus
returns to the surviving top-level control.

**Mobile:** the drawer input searches across sections. Clearing restores the
current drill-down level. Results scroll while the input and Close remain visible.

#### Matching and controls

- Every query word must match the title or breadcrumb, in any order. English
  “and” and “&” are optional between other terms: “events news” finds
  “News & Events”. Each matching word is highlighted.
- Ranking favours exact titles, prefixes and title matches before breadcrumb
  or combined matches. Repeated URLs appear once; each breadcrumb row is one
  link and wraps in RTL or narrow layouts.
- Acronyms match automatically by word initials or internal capitals: “GAR”
  finds “Global Assessment Report” and “PW” finds “PreventionWeb”. Matching is
  case-insensitive and accepts “G-A-R”, “G.A.R.” or “G A R”. English connector
  words such as “for” and “of” may be omitted; numeric years are ignored.
  Whole-label acronyms of at least two letters match titles or individual
  ancestors, after direct title matches. Acronym prefixes and invented
  combinations across breadcrumb levels do not match. Displayed names and
  site-search queries stay unchanged.
- If there are no matches, a single word of at least four characters allows
  one insertion, deletion, substitution or adjacent letter swap against whole
  words: “carers” finds “Careers”. Phrases retain non-fuzzy word matching.
- Counts use a hidden live region; no matches show **No matching pages in this
  menu**. `enableSiteSearch` adds an outlined CTA with an RTL-aware arrow,
  preserving the original query. Its default destination is `/search#query=…`;
  provide that page or set `searchUrl`.
- **⌘K / Ctrl K** opens the desktop finder only with focus in its owning panel,
  outside editors. The hint follows the platform. **↑ / ↓** move between input
  and results; **Enter** in the input follows the first result, or site search
  if there are none. Tab retains native control order. IME composition keys do
  not dismiss either surface. Finder focus prevents hover dismissal.

Override `menuFilterLabel`, `filterPlaceholder`, `clearFilterLabel`,
`noFilterResultsLabel`, `filterMatchesCount` (`{count}`), `searchSiteLabel`
(`{query}`) or `closeLabel` through `labels`. See [runtime translations](#runtime-ui-translations).

#### Theme styling and experience principles

The finder reuses Dialog surfaces, native links, 44px targets and shared focus
rings. Themes own surface expression; matches use neutral highlights and bold
text, retained in forced colours. Behaviour is unchanged with `enableFilter={false}`.
See [motion decisions](#motion-decisions) for hover feedback.

| Property                          | Default                     | Purpose                        |
| --------------------------------- | --------------------------- | ------------------------------ |
| `--mg-mega-filter-font-size`      | `--mg-font-size-300` (16px) | Input and destination type     |
| `--mg-mega-filter-meta-font-size` | `--mg-font-size-250` (14px) | Breadcrumbs, labels and status |

Override these on `.mg-mega-wrapper`. The design follows the
[experience principles](?path=/docs/design-decisions-experience-principles--docs);
it has not been validated through user research.

## Server-rendered / CDN usage

MegaMenu supports [layered hydration](https://github.com/PreventionWeb/undrr-mangrove/blob/main/docs/HYDRATION.md). This is a complex-tier component: in most integrations the `sections` prop comes from an API or server-side builder, not from static HTML. The `fromElement` function extracts timing, logo, finder/search options, language, labels and an optional inline JSON sections attribute. Consumer wrappers typically override `sections`.

```html
<div
  data-mg-mega-menu
  data-delay="300"
  data-hover-delay="180"
  data-sections='[{"title":"About","items":[...]}]'
></div>
```

| Attribute          | Default | Description                                                                 |
| ------------------ | ------- | --------------------------------------------------------------------------- |
| `data-delay`       | `300`   | Delay in ms before closing the menu on mouse leave                          |
| `data-hover-delay` | `180`   | Delay in ms before opening the menu on hover                                |
| `data-sections`    | —       | JSON array of menu sections (optional; most consumers provide this via API) |
| `data-logo-src`    | —       | Logo image URL                                                              |
| `data-logo-alt`    | `''`    | Alt text for the logo image                                                 |
| `data-logo-href`   | `'/'`   | Where the logo links to (e.g., `/ar/` for language-prefixed root)           |
| `data-logo-width`  | —       | Explicit width for CLS prevention                                           |
| `data-logo-height` | —       | Explicit height for CLS prevention                                          |

> **Drupal note:** The Drupal wrapper reads prefixed attribute names (`data-mg-mega-menu-logo-src`, etc.) and falls back to a `SITE_LOGOS` body-class map when no logo attributes are set. CDN / vanilla HTML consumers use the short `data-logo-*` names above.

```js
import createHydrator from 'https://assets.undrr.org/mangrove/2.3.0/components/hydrate.js';
import MegaMenu, {
  fromElement,
} from 'https://assets.undrr.org/mangrove/2.3.0/components/MegaMenu.js';
createHydrator({
  selector: '[data-mg-mega-menu]',
  component: MegaMenu,
  fromElement,
});
```

See the [hydration guide](https://github.com/PreventionWeb/undrr-mangrove/blob/main/docs/HYDRATION.md) for the full API and integration details.

## Mobile progressive navigation

Below 900px, the nav strip scrolls horizontally with native touch swipes or mouse click-and-drag. Dragging does not open a section. Tap a label to open its
section in the bounded overlay; the hamburger opens all sections. Groups drill into nested
levels on the same surface with labeled Back/Close controls. Section headings
link directly to landing pages; banner content appears inline under links.

Focus and scroll are restored on back/close; Escape and tapping exposed page
close the menu and return focus to opener. The panel uses a translucent blurred
surface with opaque fallback and switches to opaque/no-transition for reduced
motion/transparency, increased contrast, and forced colors.

This is a drop-in update: existing `sections`, logo/timing props, Drupal
attributes, and hydration entry points are unchanged. `labels` also accepts
`backLabel`, `allSectionsLabel`, `closeLabel`, `overviewLabel`,
`toggleMobileNavLabel`; omitted keys use the selected catalogue, then English defaults. Legacy `menuLabel`
is still accepted but no longer displayed.

## Motion decisions

Follow [Motion and animation](?path=/docs/design-decisions-motion--docs).
Pointer intent delays (`hoverDelay`, `delay`) are separate from visual timing.

- Destinations, category changes and finder open/close/results update immediately;
  there are no category pulses, panel flashes or staggered links. The public
  `mg-mega-content__right--sliding` class remains a compatibility hook.
- Mobile surfaces and newly entered levels use an 8px logical offset with the
  fast (160ms) duration and standard easing. The backdrop uses a fast opacity
  transition. `@starting-style` supplies entry; unsupported browsers open immediately.
- Finder controls/result rows use reversible fast background-colour transitions
  only for hover-capable devices with no motion preference, outside forced colours.
  Keyboard and touch feedback stay immediate. Shared CTA styles own site-search
  button feedback. Desktop reveals and legacy chevrons use the medium (300ms) token.

Reduced motion and forced colours remove movement without hiding content or
active states. Mobile travel mirrors in RTL. Exit retention reads themed CSS
durations/delays; closing releases focus and scroll immediately and makes retained
content inert. Reopening cancels pending removal. Preference changes leave the
current state usable; hydration and resting theme changes add no incidental motion.
