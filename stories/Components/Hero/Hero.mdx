# Mangrove hero (main)

Hero is a full-width page section with title, summary, and optional CTA buttons.
It supports two layouts and four color variants.

## Overview

### Layouts

**`layout="background"` (default):** Full-bleed background image plus overlay; use for campaign/homepage moments.

**`layout="split"`:** Theme-colored background with text and media columns; use for topic pages and section intros. Content stays first in DOM order (LTR/RTL).

### Heading level

`headingLevel` sets the title element (`h1`, `h2`, `h3`; default `h1`). Use
`h1` for page-primary heading and `h2`/`h3` for mid-page heroes.

### Media slot (split layout only)

The media column accepts three shapes, discriminated by `media.type`:

| `media.type`        | Required fields                            | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"image"` (default) | `src`, `alt` (empty string for decorative) | Rendered as a cover-fit `<img>`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `"video"`           | `src` (iframe-embeddable URL), `title`     | Rendered as a 16:9 `<iframe>`. Use the provider's embed URL (e.g. `https://www.youtube.com/embed/…`). `title` is required for screen reader users.                                                                                                                                                                                                                                                                                                                                                |
| `"html"`            | `html` (pre-sanitized HTML string)         | Rendered via `dangerouslySetInnerHTML`. The **consumer must sanitize** — Mangrove does not escape this string. Use for custom embeds, figures with attribution overlays, or any markup that doesn't fit image/video. A `<figure>` dropped directly into the slot is styled by Mangrove as a full-bleed image with an attribution strip overlay. Wrap content in your own container (as in the example below) to add padding, decoration, or composition on top of the hero's coloured background. |

If `media.type` is omitted, Hero falls back to `image` for backward compatibility.

### Column split (split layout only)

The `split` prop controls the content/media column ratio, aligned to the MG 12-column grid:

| `split`           | Content | Media  | Use case                   |
| ----------------- | ------- | ------ | -------------------------- |
| `"2/3"` (default) | 8 cols  | 4 cols | Text-heavy topic pages     |
| `"1/2"`           | 6 cols  | 6 cols | Balanced content and image |
| `"1/3"`           | 4 cols  | 8 cols | Media-led, image dominates |

### When to use

- Use `layout="background"` for visually-led pages where the image is central to the brand moment.
- Use `layout="split"` when you need dense body copy alongside a representative image (e.g., topic pages, campaign sections).

### Page-level setup

The hero's full-bleed background is sized with `100vw`, which counts the vertical scrollbar while its containing block does not. On any page that scrolls vertically the hero therefore overhangs by half a scrollbar on each side and the page picks up about 8px of horizontal scroll. Nothing inside the component can measure the scrollbar, so the page root has to absorb it, and the library does not ship that rule. See [page-level setup on the full-width utility](?path=/docs/components-fullwidth--docs#page-level-setup) for the rule to add, and for what it costs — content wider than the page becomes unreachable, which matters for Drupal Views tables in particular.

### Colour variants and contrast

`variant="secondary"` no longer paints the hero in the orange accent. The orange carries no text — white body copy on it was 2.65 against WCAG's 4.5, and the orange CTA label on the white pill was the same 2.65 the other way round — so the variant now keeps the theme's own hero colour in both layouts, uses the default hero colour for its CTA ink, and wears the Sendai orange as an 8px rule along the leading edge, with no copy over it. `tertiary` and `quaternary` still change the surface. An orange rule is 2.95 on white, under the 3:1 of SC 1.4.11, so it is emphasis and not the only signal that a hero is secondary. See [the colour contrast methodology](https://github.com/unisdr/undrr-mangrove/blob/main/docs/COLOUR-CONTRAST-METHODOLOGY.md#the-orange-accent-carries-no-text) for the measurements.

## Example — mobile banner and panel

Below 900px the background layout is a different composition: the photograph is
a banner across the top of the hero and the copy sits on the theme's hero
colour beneath it. Copy over the frame could not be made to clear 4.5:1 in any
theme at those widths, and veiling the frame far enough to fix it would have
covered the photograph where it is smallest — so the copy moved instead. The
banner's depth is `--mg-hero-banner-block-size`. This story pins a phone
viewport, because a desktop canvas cannot show it. See
[the hero scrim](https://github.com/unisdr/undrr-mangrove/blob/main/docs/COLOUR-CONTRAST-METHODOLOGY.md#the-hero-scrim)
for the measurements.

<Canvas of={HeroStories.MobileBanner} meta={HeroStories} />

A hero with no photograph has nothing for the banner to inherit, so the
component adds `mg-hero--no-image` and the banner collapses to nothing rather
than reserving a third of a phone screen for an image that never arrives. The
copy keeps the solid panel and the same contrast. **Consumers who hand-author
the markup must add that class themselves when they omit the background
image** — a stylesheet cannot ask whether a background image resolved.

## Changelog

- **1.9.0** — 2026-09-19 ([#1264](https://github.com/unisdr/undrr-mangrove/issues/1264)): **Consumer-visible change to the hero's mobile composition.** Below 900px the background layout no longer puts copy over the photograph. The photograph is a banner across the top of the hero, `--mg-hero-banner-block-size` deep (`min(56vw, 20rem)`, so 218px on a 390px phone), and the copy sits beneath it on the theme's hero colour under the same 0.16 scrim the desktop copy band wears. The hero is taller there, because the two are stacked rather than overlaid, and a page whose first screenful was "image with words on it" is now "image, then words". `size="immersive"` drops its `min-height` below the breakpoint and spends the room on a deeper banner (`min(78vw, 27.5rem)`) instead, because that height existed to give the photograph space _behind_ copy that is no longer there. Nothing changes above 900px. The reason is that the vertical veil could not be made to work: the copy filled the frame while the veil faded toward the top, so the eyebrow label sat where the tint was at its 0.08 end opacity and **failed in all five themes at every width from 320px to the breakpoint** — IRP 2.25–2.43, UNDRR 2.21–2.40, PreventionWeb 2.39–2.58, MCR2030 2.68–3.03, DELTA 2.80–3.15 against the 4.5 bar, with IRP's title also under the 3:1 large-text bar at 320px and 360px (2.91, 2.99). 72 of 210 measured cells failed. With no photograph behind the copy the contrast is a token pair again, so it is solved rather than sampled, and the figure no longer depends on the image: IRP 6.19, PreventionWeb 8.12, UNDRR and DELTA 10.08, MCR2030 13.67, identical to within 0.01 over a near-white wall, a high-key sky, a busy high-frequency pattern and a white-sky landscape. 0 of 210 cells fail, LTR and RTL, at 320, 360, 390, 414, 600, 768 and 900. A horizontal re-sweep at 910, 1164, 1440 and 1920 in both directions returns all 120 cells identical to the figures [#1256](https://github.com/unisdr/undrr-mangrove/issues/1256) shipped. The two colour options that were costed instead — holding the tint full height, or raising the mobile scrim to about 0.44 — were rejected because both buy the copy by spending the photograph at exactly the width where there is least of it; the measurements and the reasoning are in [the hero scrim](https://github.com/unisdr/undrr-mangrove/blob/main/docs/COLOUR-CONTRAST-METHODOLOGY.md#the-hero-scrim). New property: `--mg-hero-banner-block-size`. CSS only — no new element, no script, so consumers who hand-author the markup get the same composition. One case the CSS cannot decide for itself: a hero with **no** background image has nothing for the banner to inherit, and the reserved band would be a third of a phone screen of flat brand colour above the copy, so `Hero` and `ChildHero` now add `mg-hero--no-image` when `imgback` is absent and the banner collapses to nothing there (the copy keeps the panel and the same figures). The inline `background-image` is dropped with it, rather than emitting the `url(undefined)` every image-less hero used to request and 404. Hand-authored markup without a background image has to add that class itself.
- **1.8.0** — 2026-09-19 ([#1256](https://github.com/unisdr/undrr-mangrove/issues/1256)): The background layout's gradient gains a neutral scrim above the brand tint, so body copy clears 4.5:1 against a bright photograph in every theme. Below 900px the vertical veil still fails in every theme — see [the hero scrim](https://github.com/unisdr/undrr-mangrove/blob/main/docs/COLOUR-CONTRAST-METHODOLOGY.md#the-hero-scrim) for the measurements and the options.
