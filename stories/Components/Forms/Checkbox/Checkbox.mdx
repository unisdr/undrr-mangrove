# Checkbox

A checkbox input for selecting one or more options.

## Overview

The checkbox component lets users select or deselect individual options. Each checkbox operates independently and can be grouped inside a `<fieldset>`.

## When to use

- When the user can select zero, one, or multiple options from a set.
- For binary choices like accepting terms or toggling a preference.

## States

- **Default**: Unchecked, red border.
- **Checked**: Red fill with checkmark.
- **Hover**: Purple border on hover.
- **Focus**: Blue outline on keyboard focus.
- **Disabled**: Grey border, non-interactive.

## Switch toggle (`.mg-switch`)

For immediate binary state switches (e.g., activating map layers, live filtering, feature toggles) where a standard form checkbox reads as an unanswered form field, use `.mg-switch` with `role="switch"`.

<Canvas of={CheckboxStories.Switch} />

```html
<label class="mg-switch">
  <input type="checkbox" role="switch" class="mg-switch__input" />
  <span class="mg-switch__track" aria-hidden="true">
    <span class="mg-switch__thumb"></span>
  </span>
  <span class="mg-switch__label">Active map layer</span>
</label>
```

> **Note:** The native `<input type="checkbox">` manages the checked/unchecked state for assistive technologies automatically. When toggling the switch via JavaScript, update the `checked` property on the input element rather than managing `aria-checked` separately.

### Pending state

Use the pending state when flipping a switch starts something that takes a moment to confirm, such as saving a setting to a server. It works in both directions: off to on, and on to off.

The switch moves straight to the requested position. A small ring inside the thumb shows that the change is not confirmed yet, the track turns slightly greyer, and the cursor changes to `progress`. When the request settles, remove the pending state. If it failed, move the switch back.

<Canvas of={CheckboxStories.SwitchPending} />

Set `aria-busy="true"` on the input while the request runs:

```html
<label class="mg-switch">
  <input
    type="checkbox"
    role="switch"
    class="mg-switch__input"
    id="alerts-switch"
    aria-busy="true"
    checked
  />
  <span class="mg-switch__track" aria-hidden="true">
    <span class="mg-switch__thumb"></span>
  </span>
  <span class="mg-switch__label">Real-time alerts</span>
</label>
<p class="mg-form-help" id="alerts-status" role="status"></p>
```

If your markup cannot add attributes to the input, add `mg-switch--pending` to the label instead. Prefer `aria-busy`, because it also tells assistive technology the control is busy.

Try it below. Toggle the switch with the mouse or the Space key, then press it again while it is saving. Set `outcome` in the controls to `failure` or `timeout` to see the switch revert.

The example below does what the story does. `saveSetting` is your own request, and it should pass `signal` to `fetch()` so a timeout cancels it.

```js
const input = document.querySelector('#alerts-switch');
const status = document.querySelector('#alerts-status');
const TIMEOUT_MS = 10000;
let current = null; // the request in flight
let lastNudge = 0;

// Presses while saving are ignored and announced, at most every 3 seconds.
function stillSaving() {
  if (Date.now() - lastNudge < 3000) return;
  lastNudge = Date.now();
  status.textContent = '';
  setTimeout(() => {
    if (current) status.textContent = 'Still saving…';
  }, 100);
}

input.addEventListener('click', event => {
  if (!current) return;
  event.preventDefault(); // keeps checked where it is
  stillSaving();
});

input.addEventListener('change', () => {
  if (current) {
    // A script changed the switch mid-request: undo it.
    input.checked = !input.checked;
    stillSaving();
    return;
  }
  const requested = input.checked;
  const request = { controller: new AbortController() };
  current = request;
  status.textContent = 'Saving…';
  // Mark busy a frame later, so the new state is announced first.
  requestAnimationFrame(() => {
    if (current === request) input.setAttribute('aria-busy', 'true');
  });

  const settle = ok => {
    if (current !== request) return; // stale: this request timed out
    current = null;
    clearTimeout(request.timer);
    input.setAttribute('aria-busy', 'false');
    if (ok) {
      status.textContent = requested
        ? 'Real-time alerts turned on'
        : 'Real-time alerts turned off';
      return;
    }
    request.controller.abort();
    input.checked = !requested;
    status.textContent = 'Could not save the change. Try again.';
  };

  request.timer = setTimeout(() => settle(false), TIMEOUT_MS);
  saveSetting(requested, request.controller.signal).then(
    () => settle(true),
    () => settle(false)
  );
});
```

**Accessibility**

- Set `aria-busy="true"` on the input while saving, and `false` (or remove it) when done. `aria-busy` is a global ARIA attribute, so it is valid on `role="switch"`. Screen readers rarely announce it on a form control, so do not rely on it alone.
- Announce each step in a polite live region, such as an element with `role="status"`: "Saving…" when the request starts, then the outcome ("Real-time alerts turned on") or an error that says what to do next.
- Presses while pending are ignored, and each ignored press announces "Still saving…", at most once every few seconds so a repeated key does not flood the region. Clearing the region before writing lets the same message be announced again.
- Guard `change` as well as `click`, because a script can change the switch too. Let only the request in flight settle the switch, and time out a request that never answers, so a hung request cannot leave the switch locked.
- On failure or timeout, set `checked` back to its previous value and announce the error.
- Keep focus on the switch. Do not move focus to the message.
- Pending does not disable the input. The `disabled` attribute would drop focus and hide the control from some assistive technology. If you want the control to look unavailable as well, add `aria-disabled="true"`. It keeps the switch focusable, dims the track without fading the focus ring, and does not stop the switch toggling, so you still need the guards above.

**Order of announcements.** The example sets `aria-busy` one frame after the change, not in the same task. Assistive technology may hold back updates from an element marked busy, so marking it busy straight away could swallow the announcement of the new checked state. The ignore guard applies at once; only the attribute waits. This order has not yet been tested with real screen readers. Before relying on it, test a focused switch with NVDA and JAWS on Windows and VoiceOver on macOS and iOS: check that the new state, "Saving…", "Still saving…" and the outcome are each announced once.

**Reduced motion and forced colours**

- With `prefers-reduced-motion: reduce`, the ring does not spin. It shows as a static dotted ring, so the pending state stays visible without motion.
- In forced colours mode (such as Windows high contrast), the switch uses system colours: a bordered track, a solid thumb, a `Highlight` fill when on, and a ring in a colour that contrasts with the thumb. Disabled switches, on or off, use a `Canvas` track with `GrayText` parts. The focus ring is a `Highlight` outline outside the track border. This also fixes the track and thumb, which were invisible in forced colours before.

**Theming**

The switch reads these custom properties, each with the default shown. Set them on the switch or on any ancestor, such as a region of the page or a theme wrapper.

| Custom property                         | Default                                  |
| --------------------------------------- | ---------------------------------------- |
| `--mg-switch-track-background`          | `rgb(var(--mg-color-neutral-400))`       |
| `--mg-switch-track-background--checked` | `rgb(var(--mg-color-interactive))`       |
| `--mg-switch-thumb-background`          | `rgb(var(--mg-color-neutral-0))`         |
| `--mg-switch-track-overlay--pending`    | `rgb(var(--mg-color-neutral-500) / 0.4)` |
| `--mg-switch-track-overlay--disabled`   | `rgb(var(--mg-color-neutral-0) / 0.55)`  |
| `--mg-switch-pending-ring-color`        | `rgb(var(--mg-color-interactive))`       |
| `--mg-switch-pending-ring-gap-color`    | `rgb(var(--mg-color-neutral-300))`       |

Keep the ring at 3:1 or more against the thumb, and the thumb at 3:1 or more against the pending track. The disabled overlay should match the page colour, because it stands in for `disabled`'s 0.45 opacity.

## Accessibility

- The label is programmatically associated with the checkbox via `htmlFor`/`id`.
- For groups of checkboxes, wrap them in a `<FormGroup>` (renders `<fieldset>` with `<legend>`).
- Keyboard users can toggle the checkbox with Space.
