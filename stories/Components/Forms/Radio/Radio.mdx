# Radio button

A radio button for selecting a single option from a set.

## Overview

The radio component allows users to select exactly one option from a group. Radio buttons with the same `name` attribute are mutually exclusive. Wrap groups in a `<FormGroup>` for accessibility.

## When to use

- When the user must select exactly one option from a set.
- For lists of 2-4 options (for more options, consider a select dropdown).

## States

- **Default**: Unselected, red circular border.
- **Selected**: Red fill with white inset.
- **Hover**: Purple border on hover.
- **Focus**: Blue outline on keyboard focus.
- **Disabled**: Grey border, non-interactive.

## Option rows

Pass `row`, or add `mg-form-check--row` to the wrapper, to draw the radio button as a full-width row. The whole row is the target, and the row itself shows hover, keyboard focus and selection. Wrap the group in a `<FormGroup>` as usual.

<Canvas of={RadioStories.Row} />

### When to use option rows

- When each option is a phrase or a sentence, or may wrap in translation.
- When the choice is the main task on the screen, such as a question, a survey step or a single setting, and a larger target helps on a touch screen.
- Use the default radio button in a dense form, a filter list or anywhere the options are short and many. A row is at least 48 pixels tall, so a long list of rows is a long page.
- Use one presentation for a whole group. Do not mix rows and default radio buttons in the same group.

### How a row behaves

- **Rest**: no edge and no fill, so a group does not read as a stack of boxes. The edge is there, transparent, so nothing moves when a state draws it.
- **Hover and keyboard focus**: the row takes an edge in the interactive colour. The focus ring stays on the control.
- **Selected**: the row takes the edge and a light tint of the interactive colour.
- **Disabled**: the label is greyed, the row does not respond to the pointer and a selected row keeps a neutral edge. A disabled `FormGroup` does the same for every row in it.
- **Error**: the control takes its red boundary as usual, and the message sits on its own line under the label.
- **Long labels**: the label wraps and the control stays on its first line.
- **Label before**: `labelPosition="before"` puts the control at the end of the row.
- **Right to left**: the row uses logical properties and mirrors under `dir="rtl"`.

<Canvas of={RadioStories.RowStates} />

```html
<div class="mg-form-check mg-form-check--row">
  <input
    class="mg-form-check__input mg-form-check__input--radio"
    type="radio"
    id="warning-sms"
    name="warning"
    value="sms"
  />
  <label class="mg-form-check__label" for="warning-sms">Text message</label>
</div>
```

Markup with no ids can make the row a `label` that wraps the control, with the text in a `span`:

```html
<label class="mg-form-check mg-form-check--row">
  <input
    class="mg-form-check__input mg-form-check__input--radio"
    type="radio"
    name="warning"
    value="sms"
  />
  <span class="mg-form-check__label">Text message</span>
</label>
```

The variant has no read-only state. [Quiz question](?path=/docs/components-quiz-quiz-question--docs) locks its rows after a correct or revealed answer with styles of its own.

## Accessibility

- The label is programmatically associated with the radio button via `htmlFor`/`id`.
- For groups, wrap radios in a `<FormGroup>` (renders `<fieldset>` with `<legend>`).
- Keyboard users can navigate between radio buttons with arrow keys.
- In an option row the stretched label makes the whole row the target, at least 48 pixels tall, and the control keeps its own boundary and focus ring. Selection is never colour alone: the control shows it. In forced-colours mode a selected row has a double edge in the system highlight colour, other rows have no edge until hover or keyboard focus and a disabled row uses the system's inactive colour. The row states use `:has()`, which every [supported browser](?path=/docs/getting-started-browser-support--docs) has; without it the row still selects and only the row's own edge and tint are missing.
- In forced-colours mode (such as Windows high contrast) a selected radio button shows a dot in the system highlight colour. A disabled radio button uses the system's inactive colour, selected or not.
- The shared click tracker on UNDRR sites names a click on a radio after its `name`, which every radio in the group shares, and a click on the label after its `for` id, which is generated when no `id` is passed. Set `analyticsLabel` to give the input and its label a fixed `data-vf-analytics-label` instead. Each radio is labelled on its own, so include the option's stable `value` (for example `Subscribe frequency: monthly`), never its translated label text.
