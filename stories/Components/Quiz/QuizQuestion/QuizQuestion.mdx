# Quiz question

One self-checking question that sits in the page flow between ordinary content. The visitor answers, selects "Check answer" and gets immediate feedback. It is for engagement: answers are checked in the browser, nothing is stored, and the answer key is readable in the page.

Use it with <LinkTo kind="components-quiz-quiz-score" story="docs">Quiz score</LinkTo> to show a running score for the page.

<Canvas of={QuizQuestionStories.MultipleChoice} meta={QuizQuestionStories} />

## When to use

- A knowledge check inside an article, explainer or landing page, where trying again is part of the point.
- Several independent questions on one page, with or without a score.

Do not use it for anything that must be trustworthy: assessed quizzes, certificates, or any result that is stored or reported. The key is in the page. See [Known limitations](#known-limitations).

## Question types

### Multiple choice

One correct option uses radio buttons. Each option is a full-width row, at least 48 pixels tall, and the whole row selects.

## A page of questions

Questions need no wrapper. Each one counts the questions that share its scope, numbers itself and reports its state. The scope is the nearest ancestor with a `data-mg-quiz` attribute, or the whole page without one. Add the attribute to any element to run two separate quizzes on one page.

## React

```jsx
import QuizQuestion from '@undrr/undrr-mangrove/components/QuizQuestion.js';
import QuizScore from '@undrr/undrr-mangrove/components/QuizScore.js';

<QuizQuestion
  lang="en"
  type="multiple_choice"
  prompt="Which hazard most directly threatens a rain-fed crop like the one in this photo?"
  media={<img src="/wheat.jpg" alt="A farmer sits at the edge of a wheat field during harvest" />}
  options={[
    { value: 'drought', label: 'Drought', correct: true },
    { value: 'surge', label: 'Storm surge' },
  ]}
  explanation="A rain-fed crop depends on seasonal rainfall."
  questionId="hazards-1"
  onCheck={({ correct, questionId }) => analytics.track('quiz_check', { correct, questionId })}
/>
<QuizQuestion lang="en" type="true_false" prompt="A storm tide is a tsunami." answer={false} />
<QuizQuestion lang="en" type="text" prompt="Which framework runs to 2030?" expected={['Sendai Framework']} />
<QuizQuestion
  lang="en"
  type="fill_blank"
  prompt="Adopted in [1], Japan, in the year [2]."
  blanks={[
    { label: 'City', expected: ['Sendai'] },
    { label: 'Year', expected: ['2015'] },
  ]}
/>
<QuizScore lang="en" />
```

<Controls of={QuizQuestionStories.MultipleChoice} />

The type names (`multiple_choice`, `true_false`, `text`, `fill_blank`) match the Drupal grader types, so the same question definition works in both places.

`questionId` is optional, for consumers that need to tie a result to a question. It is reflected as `data-mg-quiz-id` on the question root and passed to `onCheck`. DOM ids and radio names do not use it, so the same question can still appear twice on a page.

## Languages and label overrides

Pass `lang` to select the built-in English, Arabic, Spanish, French, Japanese, Russian or Simplified Chinese labels. Regional tags such as `fr-CA` select their base language, and Arabic selects right-to-left unless `dir` is set. Unsupported languages keep their `lang` and show English labels. Use the Storybook locale toolbar to preview them.

The catalogue covers the interface only: the check button, feedback, "Select all that apply", numbering, True and False, and the names of blanks. Prompts, options, explanations and blank labels are content and are translated by whoever writes the question.

Override individual labels with `labels`. The rest still come from the selected language.

```jsx
<QuizQuestion lang="fr" labels={{ checkAnswer: 'Valider' }} {...question} />
```

## Behaviours

- **Check.** The button grades the current answer. An empty attempt (nothing selected, or only whitespace typed) asks for an answer and is neither graded nor counted. After a wrong answer the visitor can change the answer and check again as often as they like.
- **Feedback.** A Notice appears under the button: `positive` for correct, with the explanation if there is one, and `info` for the other two. "Not correct yet. Try again." is a wrong answer; "Choose an answer first." or "Type an answer first." is an empty attempt. The two share a variant because neither is an error, and the wording tells them apart. A wrong answer never shows the explanation or marks the right option, because the visitor can try again.
- **A correct answer locks the question.** The controls become read-only and the check button is removed, so the result always belongs to the answer on screen. The options that were not chosen are toned down. "Start again" on Quiz score unlocks every question.
- **Changing an answer clears the result.** After a wrong answer or an empty attempt, the first change to the answer removes the feedback and returns the question to unanswered. The score counts it as unanswered until it is checked again.
- **State.** The root carries `data-mg-quiz-state` (`unanswered`, `correct` or `incorrect`) and a `mg-quiz:change` event is dispatched on the document whenever it changes. The Notice is the only visible statement of the result.
- **Focus.** After a wrong answer or an empty attempt focus stays on the button, so a keyboard user can adjust the answer and check again. After a correct answer the button is removed, so focus moves to the feedback, which shows the focus ring for keyboard users; the next Tab goes to whatever follows the question. When Enter in a text field gives the correct answer, focus stays in that field, which is now read-only.
- **Motion.** None. Feedback appears immediately; there is nothing to disable under reduced motion.
- **Print.** The check button is hidden. The question, the answer the visitor entered and any feedback print as shown, and a question is not split across pages where the printer allows.

## Accessibility

- Choice and fill-in-the-blank questions are a `fieldset` whose `legend` is the prompt (or "Complete the sentence" when the blanks are inline). "Select all that apply" is the group's description.
- The short-answer input is labelled by the prompt. Each inline blank has an accessible name: the blank's label, or "Blank 1 of 2".
- Feedback is a polite live region that is in the page from the start. The Notice inside it has no role of its own, so a result is announced once. Checking the same answer twice replaces the message element, so it can be announced again.
- State is never colour alone: the Notice carries text and an icon.
- A locked question has `aria-disabled="true"` on its radios or checkboxes and `readonly` on its text fields. Neither is `disabled`, so the chosen answer stays in the tab order and keeps its full contrast.
- The feedback container has `tabindex="-1"` so that it can take focus when a correct answer removes the check button. It is not a tab stop.
- Radios, checkboxes, inputs and the button are the Mangrove Forms and button classes, with their focus rings. Option rows are at least 48 pixels tall and the button at least 44.
- Layout uses logical properties and mirrors under `dir="rtl"`.

## Server-rendered usage

Drupal and other server-rendered consumers render a container per question and let Mangrove mount the component on it. The server supplies data; grading, feedback, numbering, score and translated labels all come from Mangrove.

### Markup and data contract

```html
<div
  data-mg-quiz-question
  data-mg-ssr
  data-question='{"type":"multiple_choice","prompt":"Which hazard most directly threatens a rain-fed crop like the one in this photo?","options":[{"value":"drought","label":"Drought","correct":true},{"value":"surge","label":"Storm surge","correct":false}],"explanation":"A rain-fed crop depends on seasonal rainfall."}'
>
  <!-- No-JavaScript state. Replaced when the component mounts. -->
  <div class="mg-quiz-question mg-quiz-question--multiple-choice">
    <fieldset class="mg-form-group mg-quiz-question__group">
      <legend class="mg-form-group__legend">
        Which hazard most directly threatens a rain-fed crop like the one in
        this photo?
      </legend>
      <div class="mg-quiz-question__media">
        <img
          src="/wheat.jpg"
          alt="A farmer sits at the edge of a wheat field during harvest"
        />
      </div>
      <div class="mg-quiz-question__options">
        <label class="mg-form-check mg-quiz-question__option">
          <input
            class="mg-form-check__input mg-form-check__input--radio"
            type="radio"
            value="drought"
          />
          <span class="mg-form-check__label">Drought</span>
        </label>
        <label class="mg-form-check mg-quiz-question__option">
          <input
            class="mg-form-check__input mg-form-check__input--radio"
            type="radio"
            value="surge"
          />
          <span class="mg-form-check__label">Storm surge</span>
        </label>
      </div>
    </fieldset>
    <noscript>
      <p class="mg-form-help mg-quiz-question__note">
        Checking your answers needs JavaScript.
      </p>
    </noscript>
  </div>
</div>
```

In a fill-in-the-blank fallback, wrap each blank and the punctuation that follows it in `mg-quiz-question__blank-unit`, as the mounted component does, so the two wrap together:

```html
<p class="mg-quiz-question__sentence">
  The Sendai Framework was adopted in
  <span class="mg-quiz-question__blank-unit">
    <input
      class="mg-form-input mg-quiz-question__blank"
      type="text"
      aria-label="City"
    />
    ,
  </span>
  Japan.
</p>
```

| Attribute                   | Purpose                                                                                                              |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `data-mg-quiz-question`     | Marks the container to hydrate. Required.                                                                            |
| `data-question`             | The question as one JSON object, including its answer key. Required.                                                 |
| `data-mg-ssr`               | Keeps the inner markup on screen until the component replaces it, so the page never shows an empty box. Recommended. |
| `data-lang`                 | Language of the interface labels. Defaults to the nearest `lang` attribute, then English.                            |
| `dir`                       | Explicit direction on the container.                                                                                 |
| `data-labels`               | JSON object of label overrides.                                                                                      |
| `data-number`, `data-total` | Set the position instead of counting it.                                                                             |
| `data-show-number="false"`  | Leaves numbering out.                                                                                                |

`data-question` by type:

| Type              | Fields                                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| All               | `type`, `prompt` (plain text; line breaks as `\n`), optional `explanation` (plain text), optional `id` (string)                |
| `multiple_choice` | `options`: list of `value`, `label`, `correct`; optional `multiple`                                                            |
| `true_false`      | `answer`: `true` or `false`. The legacy pair of `options` with values `"true"` and `"false"` and a `correct` flag is also read |
| `text`            | `expected`: list of accepted answers; optional `caseSensitive`                                                                 |
| `fill_blank`      | `prompt` with `[1]`, `[2]`; `blanks`: list of optional `label`, `expected`, optional `caseSensitive`                           |

The JSON is the single source for the question. The inner markup is only what the visitor sees before or without JavaScript, with one exception: the contents of `.mg-quiz-question__media` are carried into the mounted component, so the server can render any image markup it likes (responsive `picture`, `figure` with a caption). That HTML is inserted as written, so it must come from the server's own sanitized rendering.

`id` is an optional stable identifier, for consumers that will later need to tie a result to a question. It is reflected as `data-mg-quiz-id` on the `.mg-quiz-question` root, where a `mg-quiz:change` listener can read it beside `data-mg-quiz-state`. In React it is the `questionId` prop.

The answer-key fields (`correct`, `answer`, `expected`) are optional in the data shape and are reserved for self-checking. A question with no usable key still renders and can be answered, but no answer is marked correct: each checked answer gets "Not correct yet. Try again." and counts as incorrect in the score. The exception is `true_false`, where a missing `answer` is treated as `true`. Grading decided by the server is a later addition; nothing here supports it yet.

Escape the JSON for an HTML attribute. In Twig, `{{ question|json_encode }}` inside a double-quoted attribute is escaped by autoescaping.

### Mounting

```js
import createHydrator from '@undrr/undrr-mangrove/components/hydrate.js';
import QuizQuestion, {
  fromElement,
} from '@undrr/undrr-mangrove/components/QuizQuestion.js';
import QuizScore, {
  fromElement as scoreFromElement,
  ensureQuizScoreHost,
} from '@undrr/undrr-mangrove/components/QuizScore.js';

const questions = createHydrator({
  selector: '[data-mg-quiz-question]',
  component: QuizQuestion,
  fromElement,
});
ensureQuizScoreHost(document);
const score = createHydrator({
  selector: '[data-mg-quiz-score]',
  component: QuizScore,
  fromElement: scoreFromElement,
});

Drupal.behaviors.mangroveQuiz = {
  attach(context) {
    questions.update(context);
    ensureQuizScoreHost(document);
    score.update(document);
  },
};
```

`ensureQuizScoreHost` adds a `data-mg-quiz-score` container after the last question, for consumers whose questions are independent blocks with no template that knows which one is last. It keeps that container after the last question when more arrive, and leaves alone a container the server rendered itself.

### Without JavaScript

The inner markup is the whole no-JavaScript state: a readable question with working native controls and no check button, so nothing on the page is dead. The server renders no button, feedback or score; the component adds them when it mounts. If `data-question` is missing or unreadable the component does not mount and the same markup stays.

Add a short note in `<noscript>` so a visitor without JavaScript knows why nothing checks the answer: a paragraph with the classes `mg-form-help mg-quiz-question__note` as the last child of `.mg-quiz-question`. The text is the consumer's and is translated by the consumer; it is not in the component's label catalogue, because the component is not running when it shows. `<noscript>` keeps the note out of sight while the script is loading. It does not cover a script that is allowed but fails to load; that visitor sees the same question without the note.

### The same question twice

The markup contract has no `id` and no `name` attributes. The mounted component generates both, unique to each mount, so two copies of one question (a cached block, an embed) have independent radio groups, labels, feedback and score entries. The optional `id` in `data-question` is not used for either, so both copies can carry the same one.

## Known limitations

- The answer key is in the page and nothing is stored, so a result cannot be trusted. Sign-in, stored attempts, attempt limits, hiding the result until submission, timing, question pools and certificates all need design before any assessed use.
- A wrong answer never reveals the answer or a hint, however many times the visitor tries.
- Only "Start again" on Quiz score unlocks a correct answer. A page with one question and no score has no way to try that question again.
- The question surface has no public `--mg-quiz-*` custom properties. It uses shared tokens only.

## Implementation notes

> **Implementation note (for contributors):** Why the quiz components work the way they do, in answer to the design questions in [#1481](https://github.com/unisdr/undrr-mangrove/issues/1481). Read these before changing the behaviour.

### Structure

There are two components, `QuizQuestion` with a `type` and `QuizScore`, and no wrapper component.

One question component has a type because the frame (number, prompt, media, check, feedback, state) is identical and only the answer control differs. Four components would repeat the frame and its contract four times.

The score is a separate component because it is page-level, appears once, and a page of questions is valid without it. Folding it into the question would make one question responsible for its siblings.

No wrapper is required because the first consumer cannot supply one: Drupal's questions are independent blocks separated by ordinary content, and no template surrounds them. Questions and the score find each other through the document.

### Ownership of behaviour

The component is hydrated React, so the React and server-rendered paths are one implementation with one set of tests, and it reuses the Forms, Notice and ProgressBar components directly. The cost is that the server's inner markup is replaced on mount and not enhanced in place, which is why the JSON is the source of truth and the markup is not.

Questions do not share React state, since each may be its own root. Each publishes `data-mg-quiz-state` on its root and dispatches a `mg-quiz:change` event on the document; the score and the numbering count from the DOM when they hear it. This keeps working when questions arrive or leave in batches (AJAX, BigPipe) and when two copies of the bundle are on a page.

The grading rules live in one pure module with no DOM or React dependency (`gradeAnswer`), exported for consumers that need the same rules elsewhere.

### Feedback

A wrong answer is `info`, not `negative`. Trying again is the point of the component, and a red error panel reads as a reprimand.

The Notice is the only place the result is stated. A status in the question header or a coloured edge on the card would say the same thing again.

Focus does not move after a wrong answer: moving it to the feedback would force a keyboard user to travel back to the answer for every retry.

The Notice title is a paragraph, not a heading, so a page of answered questions does not add a heading per question to the document outline.

### Numbering and score

Questions number themselves by counting their scope, because the server does not know the order either.

The score is not sticky and not repeated in each question. The feedback in each question and the numbering already say where the visitor is; a floating score would compete with the content the questions sit in.

### Fill in the blank

Blanks sit in the sentence because that is its natural reading order. A screen-reader user moving through the sentence hears the words, then the named input, in order. The prompt cannot be the legend here, because interactive controls inside a legend are not announced reliably, so the legend is "Complete the sentence".

Inline inputs are a fixed width so their size does not hint at the answer. Blanks that the prompt does not refer to fall back to labelled fields under the sentence, so no content is lost when an editor forgets a reference.

### Locked and resting states

A correct answer locks because a result that stays on screen while the answer under it changes is wrong, and the score would count it. Read-only was chosen over `disabled` for the locked controls: Mangrove's disabled text colour (`neutral-400`) is too faint for an answer the visitor still wants to read, and a disabled control leaves the tab order.

Option rows have no border at rest. The radio or checkbox is the control and keeps its own boundary; the row edge appears on hover, on keyboard focus and when selected, so a question is not a stack of outlined boxes.

### Media

An image or figure sits inside the question, between the prompt and the answer controls, so a question about a picture reads as one unit and the page layout cannot split it from the picture.

### Room for server grading

These were kept open so a server-graded mode can be added without a new component:

- **Grading is one function behind one call.** `handleCheck` collects a serializable answer (a string, or a list of strings) and asks `gradeAnswer` for a boolean. A `grader` prop returning a promise could replace that call, and the question already renders without `correct` or `expected` fields.
- **The state attribute can take more values.** `data-mg-quiz-state` and the score read named states, so `checking` or `submitted` can be added. Only the score's count of `correct` and `incorrect` assumes two outcomes.
- **Feedback text is not tied to the key.** The explanation is a prop and could come back from the server with the result.
- **The score counts the DOM.** A server-held score could replace the count behind the same component.
