# Quiz score

The running score and end summary for the <LinkTo kind="components-quiz-quiz-question" story="docs">quiz questions</LinkTo> on a page. It is a count for the visitor only: the component stores nothing and sends nothing.

<Canvas of={QuizScoreStories.Complete} meta={QuizScoreStories} />

## When to use

- After the last question of a page with several questions.
- Once per quiz. To run two quizzes on one page, put each in an element with a `data-mg-quiz` attribute and give each its own score.

Leave it out for a single question; the question's own feedback is enough.

## Behaviours

- **Empty at first.** Nothing shows until the first answer is checked. An empty attempt does not count.
- **In progress.** "1 of 5 correct so far." with a ProgressBar of questions answered. The bar says how many are answered, so the sentence does not repeat it. With `showProgress={false}` the sentence is the longer "Score so far: 1 of 5 correct (answered: 2)."
- **How a question is counted.** The score reads the state of each question. `correct` is answered and correct. `incorrect` is answered and not correct. `revealed`, a question the visitor ended with "Show answer", is also answered and not correct: it moves the progress bar and lets the quiz complete, and it never adds to the number correct. `unanswered` is neither.
- **Complete.** "You got 4 of 5 correct." and a "Start again" button, once every question is answered. A wrong answer can still be changed. Changing it returns that question to unanswered, so the score goes back to in progress until the answer is checked again.
- **Start again.** Unlocks and clears every question in the scope, including those locked by a correct or revealed answer, and moves focus to the first one. A "Show answer" button has to be earned again. Scrolling to the first question is smooth only when the visitor has not asked for reduced motion.
- **Scope.** The score counts the mounted questions in the nearest `data-mg-quiz` ancestor, or every mounted question on the page that is not inside one. A server-rendered question that did not mount and a question with nothing to answer are not counted, so they cannot hold the score short of complete.
- **Changes to the page.** Questions that mount or unmount through React or `createHydrator` are counted as they come and go. Markup that other code removes or replaces without unmounting it (Drupal AJAX, BigPipe) is counted out only when the consumer asks: see [Server-rendered usage](#server-rendered-usage).

## Languages and label overrides

`lang` selects the built-in English, Arabic, Spanish, French, Japanese, Russian or Simplified Chinese labels, as it does for Quiz question. Override individual labels with `labels`.

| Key                      | English                                                                  | Placeholders                         |
| ------------------------ | ------------------------------------------------------------------------ | ------------------------------------ |
| `scoreSoFar`             | `{correct}` of `{total}` correct so far.                                 | `{correct}`, `{total}`               |
| `scoreSoFarWithAnswered` | Score so far: `{correct}` of `{total}` correct (answered: `{answered}`). | `{correct}`, `{total}`, `{answered}` |
| `scoreFinal`             | You got `{correct}` of `{total}` correct.                                | `{correct}`, `{total}`, `{answered}` |
| `progressLabel`          | Questions answered                                                       |                                      |
| `progressValue`          | `{answered}` of `{total}`                                                | `{answered}`, `{total}`              |
| `reset`                  | Start again                                                              |                                      |

`scoreSoFar` is used while the progress bar is shown and `scoreSoFarWithAnswered` when it is switched off. Override both if you override one and use `showProgress={false}`.

The sentences keep numbers out of grammatical agreement, so no plural forms are needed. Keep that property in an override.

> **Note:** the translations have not had native-speaker review. They have had a specialist-style pass by an AI model, checked against Mangrove's other label catalogues for terms and form of address. Treat them as working defaults, not certified translations, and override any label with `labels` where an editor prefers other wording.

## Accessibility

- The score sentence is a `role="status"` element that is in the page from the start, so each change is announced politely, after the question's own feedback.
- The progress bar is the native `progress` element through ProgressBar, named "Questions answered", with "2 of 5" as its value text. It is outside the status element, so it is not read out on every change.
- "Start again" removes itself, so it moves focus to the first question's first control before it goes.

## Server-rendered usage

Render an empty container where the score belongs, or let Mangrove add one after the last question.

```html
<div data-mg-quiz-score></div>
```

| Attribute                    | Purpose                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------- |
| `data-mg-quiz-score`         | Marks the container to hydrate. Required.                                       |
| `data-lang`                  | Language of the labels. Defaults to the nearest `lang` attribute, then English. |
| `dir`                        | Explicit direction on the container.                                            |
| `data-labels`                | JSON object of label overrides.                                                 |
| `data-show-progress="false"` | Leaves the progress bar out.                                                    |
| `data-show-reset="false"`    | Leaves "Start again" out.                                                       |

Two more attributes take part:

| Attribute                 | Purpose                                                                                                  |
| ------------------------- | -------------------------------------------------------------------------------------------------------- |
| `data-mg-quiz`            | On any ancestor: makes that element a scope, so its questions and score are counted apart from the page. |
| `data-mg-quiz-score-auto` | Set by `ensureQuizScoreHost` on a container it created. Do not render it from the server.                |

Without JavaScript there is no score, because nothing can be checked.

Two functions are exported with the component. The mounting example in <LinkTo kind="components-quiz-quiz-question" story="docs">Quiz question</LinkTo> shows both in a Drupal behavior.

- `ensureQuizScoreHost(context)` adds the score container for consumers whose questions are independent blocks with no template that knows which one is last. It looks for `data-mg-quiz-question` containers inside `context` (the document by default) and handles only the scopes they belong to. In each of those scopes it creates the container after the last question container of the whole scope, unless the scope already has one. When more questions arrive, it moves a container it created so that it stays after the last one, and it leaves alone a container the server rendered. A question container counts whether or not it mounted, so the score stays below a question that is showing its fallback. Each call ends by asking the questions and scores on the page to count again.
- `refreshQuiz(context, { defer })` asks for that count on its own. Call it after other code has removed or replaced quiz markup without unmounting it, or with `defer: true` just before it does. Without either call the score catches up the next time an answer is checked or cleared. "When the page changes" in Quiz question has the details.

## Analytics

The component stores nothing and sends nothing. UNDRR sites load a shared click tracker separately ([Analytics enhancements](https://mangrove.undrr.org/?path=/docs/platform-services-analytics-enhancements--docs)) that names a pointer press on a button after `data-vf-analytics-label` and adds the innermost `data-vf-google-analytics-region`. "Start again" carries `Quiz: Start again`, whatever the language of its visible label. It is the only control in the score, so that press is all the tracker can receive from it: not the score, the number of questions or any answer. The component sets no region of its own.

## Implementation notes

> **Implementation note (for contributors):** The score holds no state of its own. It listens for `mg-quiz:change` on the document and counts `data-mg-quiz-state` on the mounted question roots in its scope. The event is batched, one for all the changes of a task, so the score updates a microtask after an answer is checked, before the browser paints. "Start again" dispatches `mg-quiz:reset` on the scope, and each question in that scope clears itself. The reasons are in the implementation notes of <LinkTo kind="components-quiz-quiz-question" story="docs">Quiz question</LinkTo>.

## Changelog

- **1.0**, 2026-11-12 ([#1481](https://github.com/unisdr/undrr-mangrove/issues/1481)): Initial component. Running and final score for the quiz questions in a scope, optional progress bar and "Start again", built-in translations with overrides and hydration with `ensureQuizScoreHost`.
  - The running score is the short "1 of 5 correct so far." beside the progress bar, and the longer form with the answered count (`scoreSoFarWithAnswered`) when the bar is off.
  - Only mounted questions are counted, so a server-rendered question that did not mount does not hold the score short of complete. A question in the `revealed` state counts as answered and not correct.
  - "Start again" is an outline secondary button, matching the check buttons on a page of questions. It unlocks questions locked by a correct answer or by "Show answer", and carries the fixed analytics label `Quiz: Start again`.
  - `ensureQuizScoreHost(context)` looks only at the scopes with a question inside `context` and ends with a recount. `refreshQuiz()` recounts after other code has changed the page, and a score whose markup was removed releases its document listener on the next count.
  - The score counts once for each batch of changes, not once for each question that mounts or is checked.
