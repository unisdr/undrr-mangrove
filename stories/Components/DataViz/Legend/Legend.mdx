# Legend

A key for a map or chart: it names the colours and symbols a visualization uses
so a reader can tell what a shade of red or a swatch of blue means.

Legend renders the key only. It does not draw the map or the chart, and it does
not read data — you pass it the same colours and breakpoints your visualization
was drawn with.

## When to use

| Need                                                       | Use                                                                 |
| ---------------------------------------------------------- | ------------------------------------------------------------------- |
| A colour ramp over a continuous measure (ground shaking)   | `type="continuous"`                                                 |
| Binned intervals with fixed cut points (temperature bands) | `type="stepped"`                                                    |
| A fixed set of named categories (disaster types)           | `type="categorical"`                                                |
| A count, share, or single figure with no colour scale      | [StatsCard](?path=/docs/components-cards-stats-card--docs)          |
| A filterable list of records                               | [Syndicated search](?path=/docs/components-syndicated-search--docs) |

## Storybook variations

### Continuous ramp

A gradient across a measure with no natural breaks. Give it two or three ticks;
more crowd the bar at narrow widths.

Legend text is styled for light surfaces. There is no dark-surface variant: on a dark background, set the text colours yourself or place the legend on a light panel.

<Canvas of={LegendStories.Continuous} />

### Stepped

Discrete bands, one swatch per interval. Use it when the cut points are part of
the message, such as classified hazard or anomaly bands.

<Canvas of={LegendStories.Stepped} />

### Categorical

Named categories, each with a swatch and an optional value. `layout="inline"`
wraps the entries in a row.

<Canvas of={LegendStories.Categorical} />

### Categorical grid

`layout="grid"` puts the entries in columns. Prefer it when labels are long or
there are more than about six categories.

<Canvas of={LegendStories.CategoricalGrid} />

### Vertical orientation

Continuous and stepped legends can run vertically, which suits a legend docked
beside a tall map.

## Usage

```jsx
import { Legend } from '@undrr/undrr-mangrove';

<Legend
  title="Disaster type"
  type="categorical"
  layout="inline"
  items={[
    {
      label: 'Earthquake',
      color: 'rgb(var(--mg-color-red-500))',
      value: '45%',
    },
    { label: 'Flood', color: 'rgb(var(--mg-color-blue-500))', value: '30%' },
    {
      label: 'Drought',
      color: 'rgb(var(--mg-color-orange-500))',
      value: '25%',
    },
  ]}
/>;
```

Ticks are positioned from the `position` string when you supply one. Without
it, ticks are spread evenly across the bar, and a single tick sits at the
start.

```jsx
<Legend
  title="Peak ground acceleration (cm/s²)"
  type="continuous"
  customRamp="linear-gradient(to right, #00f, #0ff, #0f0, #ff0, #f00)"
  ticks={[
    { label: '0', position: '0%' },
    { label: '500', position: '50%' },
    { label: '> 1000', position: '100%' },
  ]}
/>
```

Pass a `rampClass` instead of `customRamp` when the gradient belongs in your own
stylesheet rather than in an inline style.

## Vanilla HTML and Drupal

Legend has no JavaScript behaviour, so it needs neither hydration nor a vanilla
lifecycle module, and there is no `js/legend.js` to wait for. This is a
decision, not a gap: a legend is static presentation. It has no state, no
interactive controls and no keyboard model, so there is nothing for a lifecycle
to manage. The CSS-only path is the whole component here, not a subset of it —
emit the markup, load a Mangrove stylesheet, and you have everything the React
version gives you.

In the AI manifest, Legend is `vanillaModule: false` with a
`vanillaModuleNote` saying the same thing, so an agent reading the manifest
does not have to probe `/js/` to find out.

If your legend entries need to _do_ something — toggle a map layer, filter a
chart series — that interactivity belongs to your own controls rather than to
the legend. Put a [Checkbox or switch](?path=/docs/components-forms-checkbox--docs)
beside each entry, or hold the list in a
[Drawer or floating panel](?path=/docs/components-navigation-drawer--docs),
which does have a vanilla lifecycle module. Keep the interactive control
outside the legend's own markup: a legend is a `role="group"`, and burying a
control in one only makes it harder to reach than a plain button beside it.

A server-rendered page can emit the same markup and load a Mangrove stylesheet:

```html
<div
  class="mg-legend mg-legend--categorical mg-legend--inline"
  role="group"
  aria-labelledby="legend-title"
>
  <p id="legend-title" class="mg-legend__title">Disaster type</p>
  <ul class="mg-legend__list">
    <li class="mg-legend__item">
      <span class="mg-legend__swatch" style="background-color: #d73027"></span>
      <span class="mg-legend__label">Earthquake</span>
      <span class="mg-legend__value">45%</span>
    </li>
  </ul>
</div>
```

| `.mg-legend__bar`          | The colour ramp                                          |
| `.mg-legend__bar--stepped` | The ramp when it is made of discrete steps               |

| `.mg-legend__tick`         | One tick, placed from `--mg-legend-tick-pos`             |
| `.mg-legend__tick-label`   | Tick text                                                |
| `.mg-legend__list`         | Categorical entry list                                   |
| `.mg-legend__item`         | One categorical entry                                    |

| `.mg-legend__label`        | Entry label                                              |
| `.mg-legend__value`        | Optional value beside an entry label                     |

## Accessibility

- The legend is a `role="group"` named by its title, so a screen reader
  announces the group before reading the entries. Without a `title` the group
  is unnamed — give every legend a title.
- Colour is never the only cue: each categorical entry has a text label, and
  each step in a stepped ramp carries a visually hidden label for its band.
  Supply `label` on every `items` entry.
- The ramp itself is `aria-hidden="true"`. The ticks carry the reading.
- Tick placement uses logical properties, so a legend mirrors in right-to-left
  layouts. Check your own `customRamp` gradient direction in Arabic: a
  `to right` gradient does not flip on its own.
- Check the contrast of your swatch colours against the surface they sit on.
  Mangrove cannot validate colours you pass in.

## Theme behaviour

Legend uses shared Mangrove tokens for its title, labels and ticks, so it picks
up each theme's type and neutral colours. The swatch and ramp colours come from
your data, not from the theme — they are identical in UNDRR, PreventionWeb, IRP
and MCR2030.

- **1.0.5** — 2026-09-18 ([#1197](https://github.com/unisdr/undrr-mangrove/issues/1197)): Documentation only. Says outright that Legend has no vanilla lifecycle module and that none is planned, because a legend is static presentation with no state, no interactive controls and no keyboard model — so a CSS-only adoption is the complete component rather than a partial one. Points anyone who needs interactive legend entries at a Checkbox or switch beside each entry, or a Drawer, kept outside the legend's own `role="group"`. The AI manifest states the same through `vanillaModule: false` and a `vanillaModuleNote`, so it can be read without probing `/js/` for a 404.
- **1.0.4** — 2026-09-18 ([#1216](https://github.com/unisdr/undrr-mangrove/pull/1216), [#1200](https://github.com/unisdr/undrr-mangrove/issues/1200)): `.mg-legend__list` hides its markers with `list-style: none` followed by `list-style-type: ""` (the new `mg-list-unmarked` mixin). Safari drops the implicit `list` role from a markerless list, so VoiceOver stopped announcing the entry count; an empty string is still a marker, so the role survives and nothing renders. No `role="list"` is needed on the `<ul>`, and no markup or layout changes.

It wrapped the legend in an `mg-theme-dark` class that the library never defined and set a `Dark` theme override that does not exist, so it rendered labels at 1.2:1 and implied a dark-surface API that Legend does not have. The docs now say plainly that Legend is styled for light surfaces.

Removed a duplicated `Continuous` canvas and expanded the page: when to use each type, React usage with tick positioning, the plain HTML equivalent, a CSS class reference, accessibility notes and theme behaviour.
