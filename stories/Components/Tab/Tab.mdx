# Tabs

Tabs let users switch between related groups of content without leaving the page. One panel is visible at a time.

## When to use

Use tabs when you have two or more named content sections that users might want to switch between, but don't need to compare side by side at the same time.

Don't use tabs for site navigation. Use links or menus instead.

## Variants

Two layouts are available. **Horizontal** is best for 2-5 short labels.
**Stacked** (accordion-style) is better for long labels or many sections.
Horizontal tabs stay in one row and scroll when needed; use `stackOnMobile` to
switch horizontal tabs to stacked disclosures below 480px.

Horizontal scrolling is the default. To restore the older mobile disclosure
behavior, pass `stackOnMobile` (or `data-mg-js-tabs-stack-on-mobile`). Below
480px, layout/roles/keyboard behavior switch together; at 480px+ tabs return to
horizontal. Panels stay mounted so form values persist.

## Interactions

**Horizontal tabs:**

- A soft fill identifies the selected tab. Hover and keyboard focus have distinct treatments.
- Clicking a tab opens its panel and reveals the tab in the rail without scrolling the page vertically. Native scrolling alone preserves selection.
- Arrow Left/Right selects and focuses the adjacent tab (wraps around, with directions reversed in RTL). Down arrow moves focus into the open panel. Home/End select the first/last tab. Initial default and deep-link selection does not steal focus.

**Stacked tabs:**

- Clicking a trigger toggles its panel open/closed independently.
- Space or Enter activates the focused trigger.
- Arrow Up/Down moves focus between triggers (wraps around). Home/End jump to first/last trigger.
- With `singleOpen`, opening one panel closes all others (accordion behavior).

URL hashes work as deep links in both variants, e.g. `#mg-tabs__section-tab-2` opens that section on load.

## Accessibility

**Horizontal tabs** follow the ARIA tab pattern (`tablist`, `tab`,
`tabpanel`, roving tabindex). Only the active tab is in Tab order; arrow keys
navigate tabs. Name each group with `labels.tabListLabel` (React) or
`data-mg-js-tabs-label` (HTML, default "Sections"). Without JavaScript, all
panel content remains visible.

**Stacked tabs** use an accessible disclosure pattern (`aria-expanded`,
`aria-controls`, `region`, `aria-labelledby`). In Chromium, collapsed panels are
findable via Ctrl+F; Firefox/Safari treat them as hidden to find-in-page.

> **Implementation note (for contributors):** Horizontal tabs use `role="tablist"` on the list, `role="tab"` with `aria-selected` on triggers, and `role="tabpanel"` on panels (roving tabindex). Stacked tabs use `role="button"` with `aria-expanded` and `aria-controls` on triggers, `role="region"` with `aria-labelledby` on panels. The `hidden="until-found"` attribute on stacked panels enables Ctrl+F discoverability in Chromium; other browsers fall back to standard `hidden` behavior.

The filter input has an `aria-label` and an `aria-describedby` hint ("Results will filter as you type"). A live region (`role="status"`) announces result counts as the user types, and displays "No matching sections found" visually when there are zero matches.

## Usage

Tabs are vanilla JavaScript: HTML plus a module script. A `<Tab>` React wrapper
is also available in Mangrove source ([see below](#react-usage)).

### Vanilla JS (recommended)

#### 1. Include the CSS

Pick the Mangrove theme stylesheet for your site ([CDN reference](/?path=/docs/getting-started-integration-cdn-reference--docs) lists all themes).

```html
<link
  rel="stylesheet"
  href="https://assets.undrr.org/mangrove/2.0.0-rc.1/css/style.css"
/>
```

#### 2. Include the JavaScript

The script file uses ES module `export` statements, so you **must** load it with `type="module"`:

```html
<!-- JS: type="module" is required -->
<script
  type="module"
  src="https://assets.undrr.org/mangrove/2.0.0-rc.1/js/tabs.js"
></script>
```

The script auto-initializes on `DOMContentLoaded` (or immediately if the DOM is already parsed). Module scripts are deferred by default, so `mgTabs()` runs after the DOM is available.

For manual or dynamic initialization, import the function:

```html
<script type="module">
  import { mgTabs } from 'https://assets.undrr.org/mangrove/2.0.0-rc.1/js/tabs.js';
  mgTabs();
</script>
```

`mgTabs()` finds every `[data-mg-js-tabs]` element on the page and wires up the tab behavior.

#### 3. Add the HTML markup

**Horizontal tabs (default)**

```html
<article
  class="mg-tabs mg-tabs--horizontal"
  data-mg-js-tabs
  data-mg-js-tabs-variant="horizontal"
  data-mg-js-tabs-label="Programme sections"
>
  <div class="mg-tabs__rail">
    <div class="mg-tabs__scroll">
      <ul class="mg-tabs__list">
        <li class="mg-tabs__item">
          <a class="mg-tabs__link" href="#mg-tabs__section-overview">
            Overview
          </a>
        </li>
        <li class="mg-tabs__item">
          <a
            class="mg-tabs__link"
            href="#mg-tabs__section-details"
            data-mg-js-tabs-default="true"
          >
            Details
          </a>
        </li>
      </ul>
    </div>
  </div>
  <div class="mg-tabs__panels">
    <div class="mg-tabs-content" data-mg-js-tabs-content>
      <section class="mg-tabs__section" id="mg-tabs__section-overview">
        <p>Overview content.</p>
      </section>
    </div>
    <div class="mg-tabs-content" data-mg-js-tabs-content>
      <section class="mg-tabs__section" id="mg-tabs__section-details">
        <p>Detail content.</p>
      </section>
    </div>
  </div>
</article>
```

Existing interleaved HTML is also supported: the runtime moves horizontal panels outside the list during initialisation. Keep all panel IDs unique across the page. Panel HTML must be sanitised by the consuming application before it is passed to Mangrove.

**Stacked tabs (accordion-style)**

Change the modifier class and variant attribute:

```html
<article
  class="mg-tabs mg-tabs--stacked"
  data-mg-js-tabs
  data-mg-js-tabs-variant="stacked"
>
  <ul class="mg-tabs__list">
    <li class="mg-tabs__item">
      <a class="mg-tabs__link" href="#mg-tabs__section-item-1">Section 1</a>
    </li>
    <li class="mg-tabs-content" data-mg-js-tabs-content>
      <section class="mg-tabs__section" id="mg-tabs__section-item-1">
        <p>Content for section 1.</p>
      </section>
    </li>

    <li class="mg-tabs__item">
      <a class="mg-tabs__link" href="#mg-tabs__section-item-2">Section 2</a>
    </li>
    <li class="mg-tabs-content" data-mg-js-tabs-content>
      <section class="mg-tabs__section" id="mg-tabs__section-item-2">
        <p>Content for section 2.</p>
      </section>
    </li>
  </ul>
</article>
```

**Stacked tabs as FAQ (all closed, single-open)**

Add `data-mg-js-tabs-default-open="false"` to start all panels closed, `data-mg-js-tabs-single-open` for accordion behavior, and `data-mg-js-tabs-filterable` for a search input:


The filter input, screen-reader-only hint, and status region are injected automatically by the runtime. No additional markup is needed.

#### API

Exported functions:

| Function                                                   | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mgTabs(scope?, activateDeepLinkOnLoad?, options?)`        | Initializes all tab containers. `scope` is an optional `NodeList`; defaults to all `[data-mg-js-tabs]` elements. `activateDeepLinkOnLoad` defaults to `true`. `options.signal` is an optional `AbortSignal`: aborting it destroys the tab sets this call initialized, and an already-aborted signal skips initialization. Calling it on a tab set that is already initialized resumes that set if it was suspended. Every call first checks the tab sets it has initialized. See [Removing tabs](#removing-tabs).                                                |
| `mgTabsRuntime(scope?, activateDeepLinkOnLoad?, options?)` | Initializes tabs within a single container element or a parent that contains tab sets; defaults to `document`. Use this for tabs injected after page load. Accepts the same `options.signal` as `mgTabs`.                                                                                                                                                                                                                                                                                                                                                        |
| `mgTabsDestroy(scope?, preserveState?)`                    | Removes listeners and observers, restores progressively enhanced markup and makes content visible. Call before removing vanilla tab sets for good, or use `options.signal` ([Removing tabs](#removing-tabs)). Every tab set in `scope` is destroyed even if one of them throws; the first error is then rethrown. Pass `true` as the second argument to retain selection, disclosure and filter state for the next initialisation of the same layout; the React wrapper uses this during updates and handles cleanup automatically. Safe to call more than once. |
| `mgTabsApplyStackedDefaults(container, tabs, panels)`      | Re-applies default open/close state for stacked tabs. Useful after programmatically resetting filter state.                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `setDisclosureState(trigger, panel, open)`                 | Sets the open/close state of a stacked disclosure panel. `open` is a boolean.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

If you inject tab markup dynamically (e.g. from an API response), call `mgTabsRuntime()` on the new container:

```js
const newContainer = document.querySelector('#dynamic-tabs');
mgTabsRuntime(newContainer);
```

#### Removing tabs

A tab set listens for events outside its own markup: window `resize`, `orientationchange` and `hashchange`, `document.fonts` `loadingdone`, and a `ResizeObserver` on the rail. Release them before you remove or replace the markup, for example on a route change, when re-rendering a region from an API response, or in a Drupal AJAX update. The React wrapper does this for you.

**Call `mgTabsDestroy()`** with the container, or a parent that contains tab sets, before removing it. It restores the original markup, and calling it again does nothing.

```js
mgTabsDestroy(container);
container.remove();
```

**Or pass an `AbortSignal`** as the third argument and abort it when the tabs go away. This ties the tabs to something your app already cleans up, such as a route or view controller. Aborting destroys only the tab sets that call initialized. A tab set that was already initialized is left as it is, and a signal that is already aborted initializes nothing.

```js
const controller = new AbortController();
mgTabsRuntime(region, true, { signal: controller.signal });

// Later, when the region is replaced:
controller.abort();
```

**If you forget, removed tab sets are suspended, not destroyed.** When a tab set that has been on the page is found outside the document, the runtime releases the window, `document.fonts` and `ResizeObserver` registrations it holds and leaves everything else as it was: the enhanced markup, the listeners inside the tab set and the current selection. Apart from an `AbortSignal` you passed, nothing outside then refers to the element, so once your app drops it, it can be garbage collected.

While any tab set is initialized, the runtime keeps one window `resize` listener and one `hashchange` listener of its own. They refer to no tab set: each event checks the tab sets it has initialized, which costs a few microseconds for 50 tab sets. They are removed once every tab set has been destroyed.

A removed tab set is found:

- when its rail's `ResizeObserver` reports the size change, which in Chromium is usually within a frame of removal (horizontal tab sets only)
- otherwise, on the next window resize or hash change, or when one of its own outside listeners fires (an orientation change or font load)
- or the next time `mgTabs()` or `mgTabsRuntime()` is called for any tab set

A suspended tab set that is put back on the page resumes by itself on the first pointer press, focus, key press or click inside it, on the next window resize or hash change, or when `mgTabs()` or `mgTabsRuntime()` next runs. When one tab set resumes after an interaction, any other re-attached tab sets resume too, including tab sets nested inside it. Re-attaching after a modal closes and reopens, moving a portal target, or re-inserting the same element in an AJAX update keeps the tabs working:

- If the URL hash did not change while the tab set was off the page, the same tab stays selected.
- If the hash changed and names one of its panels, that panel is selected, as it would have been had the tab set stayed on the page. This also applies when the React wrapper re-renders a re-attached tab set, and to `mgTabsDestroy(container, true)` followed by `mgTabs()`.
- If the viewport crossed the `stackOnMobile` breakpoint, the tab set switches layout, keeping its selection.

When the resume comes from a pointer press, focus, key press or click, the tab set waits until that interaction has been handled before it follows a changed hash, scrolls the selected tab into view or switches layout. A tap therefore acts on what was under the pointer, and a tab it selects wins over the changed hash. After a pointer press, the wait ends at the click, or 400ms after the pointer is released if no click follows.

Limits:

- Until a removal is found, the outside listeners stay registered.
- Between being re-attached and resuming, a tab set does not follow hash changes itself and its rail's overflow indicators can be out of date. The next resize, hash change, interaction or `mgTabs()`/`mgTabsRuntime()` call brings it up to date.
- After an interaction on a tab set that crossed the `stackOnMobile` breakpoint while it was off the page, the old layout stays in place until the interaction has been handled. A tap on a visible tab selects it, and the new layout then opens that tab's panel.
- A horizontal tab set initialized before it was added to the page is not suspended until it has been seen on the page, so building tabs off-screen and inserting them later is safe. A stacked tab set can be suspended before it is attached and resumes once it is on the page.
- A tab set that is moved (removed and inserted elsewhere in the same task) is not affected.
- If suspending or resuming one tab set throws while other tab sets are checked, the error is reported with `reportError()` and the check continues, so `mgTabs()` still initializes the tab sets you passed.
- An `AbortSignal` you pass keeps a reference to its tab sets until it is aborted or they are destroyed.

**Drupal behaviors** should release tabs in `detach`. Drupal calls `detach` with the trigger `'unload'` before AJAX replaces or removes content. Use `once()` from `core/once` (add it to your library's dependencies) so each container is set up once, however many times `attach` runs.

The snippet uses `import`, so the behavior file must load as a module. Declare it with `attributes: { type: module }` in your `*.libraries.yml`, and keep it out of JavaScript aggregation:

```yaml
mangrove-tabs:
  js:
    # Aggregation can merge this file with classic scripts, where import is a syntax error.
    js/mangrove-tabs.js: { attributes: { type: module }, preprocess: false }
  dependencies:
    - core/drupal
    - core/once
```

```js
import {
  mgTabsRuntime,
  mgTabsDestroy,
} from 'https://assets.undrr.org/mangrove/2.0.0-rc.1/js/tabs.js';

Drupal.behaviors.mangroveTabs = {
  attach(context) {
    once('mg-tabs', '[data-mg-js-tabs]', context).forEach(container => {
      mgTabsRuntime(container);
    });
  },
  detach(context, settings, trigger) {
    // 'move' and 'serialize' keep the element on the page.
    if (trigger !== 'unload') return;
    // mgTabsDestroy() includes context itself when it is a tab set, which
    // once() does not: AJAX often replaces the [data-mg-js-tabs] element.
    mgTabsDestroy(context);
    once.remove('mg-tabs', '[data-mg-js-tabs]', context);
    if (context.matches?.('[data-mg-js-tabs]')) once.remove('mg-tabs', context);
  },
};
```

This example calls `mgTabsDestroy()` instead of using a signal because tabs present at page load may already have been set up by auto-initialization, and a signal only applies to tab sets its own call initialized. To use a signal in a behavior, add `data-mg-js-tabs-skip-auto-init` to the markup.

#### Skipping auto-initialization

Add `data-mg-js-tabs-skip-auto-init` to skip a container during auto-init. This is useful when another script must run first (e.g. Drupal behaviors):

```html
<article
  class="mg-tabs mg-tabs--horizontal"
  data-mg-js-tabs
  data-mg-js-tabs-skip-auto-init
  data-mg-js-tabs-variant="horizontal"
>
  <!-- tab markup -->
</article>

<script type="module">
  import { mgTabs } from 'https://assets.undrr.org/mangrove/2.0.0-rc.1/js/tabs.js';
  // Initialize after other setup is complete
  mgTabs([document.querySelector('[data-mg-js-tabs-skip-auto-init]')]);
</script>
```

When you pass elements explicitly via `scope`, the skip attribute is ignored — the consumer is intentionally initializing.

### React usage

The `<Tab>` component renders the same HTML as above and calls `mgTabsRuntime()` on mount. It's available from the Mangrove source but not published as a precompiled bundle on the CDN.

```jsx
// Requires the full Mangrove source tree (not available from the npm package alone)
import { Tab } from 'stories/Components/Tab/Tab';

const tabdata = [
  { text: 'Overview', text_id: 'overview', data: '<p>Overview content</p>' },
  {
    text: 'Details',
    text_id: 'details',
    data: '<p>Detail content</p>',
    is_default: 'true',
  },
];

<Tab
  tabdata={tabdata}
  variant="horizontal"
  labels={{ tabListLabel: 'Programme sections' }}
/>;
```

**Props:**

| Prop            | Type     | Default              | Description                                                                                                                                                                                                  |
| --------------- | -------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `tabdata`       | `Array`  | —                    | Array of tab objects (see below)                                                                                                                                                                             |
| `variant`       | `string` | `"horizontal"`       | `"horizontal"` or `"stacked"`                                                                                                                                                                                |
| `stackOnMobile` | `bool`   | `false`              | Horizontal only. Switch to stacked disclosures below 480px; restore the rail at 480px and above.                                                                                                             |
| `defaultOpen`   | `bool`   | `undefined`          | Stacked only. `true` opens all panels, `false` closes all, `undefined` opens first. Per-item `is_default` overrides.                                                                                         |
| `singleOpen`    | `bool`   | `false`              | Stacked only. When `true`, only one panel can be open at a time. Only governs click behavior — does not enforce single-open on initial state. Use with `defaultOpen={false}` for typical accordion behavior. |
| `filterable`    | `bool`   | `false`              | Stacked only. Renders a search input that filters sections by header and content text. Also available via `data-mg-js-tabs-filterable` in vanilla JS.                                                        |
| `labels`        | `object` | `DEFAULT_TAB_LABELS` | `tabListLabel` names the tablist (default "Sections"); `filterPlaceholder` names the stacked filter input (default "Filter sections…").                                                                      |

Each tab object in `tabdata`:

| Property     | Type     | Description                                                                     |
| ------------ | -------- | ------------------------------------------------------------------------------- |
| `text`       | `string` | Tab label                                                                       |
| `text_id`    | `string` | Unique identifier (used in `id` and `href` attributes)                          |
| `data`       | `string` | HTML content for the tab panel                                                  |
| `is_default` | `string` | `"true"` to open by default, `"false"` to keep closed. Overrides `defaultOpen`. |

## Migration

### v2.10: centred, scrollable horizontal tabs

Horizontal tabs now stay horizontal below 480px by default. To restore automatic
mobile stacking, set `stackOnMobile` (`data-mg-js-tabs-stack-on-mobile`).
Choose `variant="stacked"` (`mg-tabs--stacked` + `data-mg-js-tabs-variant="stacked"`)
when disclosure behavior is required.

The React wrapper renders separate rail/panel containers. Existing vanilla
markup is enhanced automatically with preserved panel IDs/hash links, but
custom selectors expecting panels inside `.mg-tabs__list` must be updated.

Horizontal tabs use `--mg-tab-background--active` and `--mg-tab-indicator--active` for the selected pill. Keep overrides scoped to the theme and check text, selected-state and focus contrast together. For dynamically removed vanilla components, call `mgTabsDestroy(container)` before removing their DOM. React performs this cleanup automatically.

### v2.5: trigger ID change

In version 2.5, the ID of stacked tab trigger elements changed. If you have CSS or JavaScript that selects triggers by ID:

- **Before (≤ 2.4):** `#mg-tabs__section-{id}` targeted both the trigger and the panel
- **After (2.5+):** `#mg-tabs__section-{id}--trigger` is the trigger; `#mg-tabs__section-{id}` is the panel

You can also select triggers by class (`.mg-tabs__link`) — this works in all versions.
