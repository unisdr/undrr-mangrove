# Quote highlight

The `QuoteHighlight` component is used to display important quotes with attribution and optional images.

## Features

- Two layout variants: line (with separator line) or image (with side image)
- Three background color options: light, dark, and bright
- Optional attribution with name and title
- Optional portrait image that displays inline with attribution
- Optional side image for the image variant
- Three alignment options: full, left, and right
- RTL (Right-to-Left) language support
- Responsive design that adapts to different screen sizes

## Usage

```jsx
import QuoteHighlight from '@undrr/undrr-mangrove/components/QuoteHighlight.js';

<QuoteHighlight
  quote="One doesn't have to look hard to find examples of how disasters are becoming worse."
  attribution="Mami Mizutori"
  attributionTitle="Special Representative of the UN Secretary-General for Disaster Risk Reduction"
  imageSrc="/assets/author.png"
  imageAlt="Mami Mizutori portrait"
  variant="line"
  backgroundColor="light"
  alignment="full"
/>;
```

## Quote HTML handling

`quote`, `attribution` and `attributionTitle` are rendered as HTML, not as text,
and the component runs each of them through
[DOMPurify](https://github.com/cure53/DOMPurify)'s default allow-list first —
the same call `TextCta`, `Drawer` and the card components make.

Rendering them as HTML is deliberate. Quote copy is authored, and it carries
inline markup — a `<cite>`, an `<em>`, a `<br>` to break a long pull quote, a
link on the name of the person quoted. Escaping the strings would print those
tags. The default allow-list keeps all of that, so nothing these fields exist to
carry is affected.

What it removes is everything that is not inline copy: `<script>`, event-handler
attributes such as `onclick` and `onerror`, `javascript:` URLs, `<iframe>` and
other embeds. If you were passing an embed through one of these three props, it
will stop rendering — use `Tab` or your own wrapper for panel-sized content.

One removal is not a script, and is the one most likely to catch you: the
default allow-list drops **`target`** and `referrerpolicy`, so an attribution
link authored as `<a href="…" target="_blank">` now opens in the same tab. On
an anchor, `href`, `rel`, `class`, `id`, `title`, `hreflang`, `lang`, `dir`,
`aria-*` and `data-*` all survive, so nothing is unstyled and no Linkit
`data-entity-*` reference is lost. This is DOMPurify's library-wide default
rather than a choice made for this component — `TextCta`, `Drawer` and the card
components strip `target` from their HTML props too. If you need a new tab, open
it from the surrounding markup rather than from inside one of these three
strings.

You do not need to sanitise before passing the values in, and doing so anyway is
harmless. Keep the filter you already have where the values are produced: if
they come from a CMS field with an output filter over it, as Drupal's text
formats give you, that filter still decides which markup an editor may author.
The component's pass is a floor, not a replacement.

One detail worth knowing: the two rendering paths differ per prop.
`attribution` and `attributionTitle` always go through as HTML. `quote` is
rendered as text unless it contains a `<`, in which case it goes through as
HTML. That test picks the wrapper element rather than the safety — a plain quote
gets a `<p>`, one with markup gets a `<span>` — so a quote that merely mentions
a `<` takes the HTML path too. Both paths are safe: React escapes the text one,
DOMPurify filters the other.

## Design guidelines

- Use this component for high-signal quotes from key stakeholders.
- Prefer `line` inside body content; use `image` for more prominent standalone callouts.
- Include attribution whenever available.
- Use high-quality, correctly cropped images with meaningful alt text.
- Choose alignment by context: `full` for standalone emphasis, `left`/`right` for inline flow.
- RTL layouts are mirrored automatically.

## Accessibility

### Semantic HTML

- The component uses a `<blockquote>` element for the quote text, giving screen readers proper quote semantics
- The outer wrapper is a `<section>` element, providing a sectioning landmark
- Attribution name and title are rendered as `<p>` elements within the attribution area

### Image alt text

- The `imageAlt` prop controls the `alt` attribute on both the portrait image (line variant) and the side image (image variant)
- When `imageAlt` is not provided, the component generates a fallback: `"{attribution} image"`, or `"Quote image"` if no attribution is set
- Always provide a meaningful `imageAlt` value rather than relying on the fallback, especially when the image conveys information beyond decoration

### Known limitations

- Screen readers announce an unlabeled section (`<section>` has no `aria-label`/`aria-labelledby`).
- Quote text and attribution are not programmatically linked (`<cite>`, `<footer>`, or `aria-describedby` are not used).
- Auto-generated fallback alt text may be too generic for meaningful images.

> **Implementation note (for contributors):** The outer wrapper is a `<section>` with no `aria-label` or `aria-labelledby`. The quote and attribution use `<p>` elements within `<blockquote>` rather than a `<figure>`/`<figcaption>` or `<footer>`/`<cite>` pattern, so there is no programmatic association between the quote and its source.

## Server-rendered / CDN usage

QuoteHighlight supports [layered hydration](https://github.com/unisdr/undrr-mangrove/blob/main/docs/HYDRATION.md). Use data attributes on a container element:

```html
<div
  data-mg-quote-highlight
  data-quote="One doesn't have to look hard to find examples."
  data-attribution="Mami Mizutori"
  data-attribution-title="SRSG for Disaster Risk Reduction"
  data-image-src="/assets/author.png"
  data-image-alt="Mami Mizutori portrait"
  data-background-color="light"
  data-variant="line"
  data-alignment="full"
></div>
```

| Attribute                | Default   | Description                                                                                                                                   |
| ------------------------ | --------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `data-quote`             | `''`      | Quote text (required). A value containing `<` is rendered as HTML, sanitised with DOMPurify — see [Quote HTML handling](#quote-html-handling) |
| `data-attribution`       | —         | Attribution name. Always rendered as HTML, sanitised with DOMPurify                                                                           |
| `data-attribution-title` | —         | Attribution title or role. Always rendered as HTML, sanitised with DOMPurify                                                                  |
| `data-image-src`         | —         | Portrait or side image URL                                                                                                                    |
| `data-image-alt`         | —         | Alt text for the image                                                                                                                        |
| `data-background-color`  | `'light'` | `'light'`, `'dark'`, or `'bright'`                                                                                                            |
| `data-variant`           | `'line'`  | `'line'` or `'image'`                                                                                                                         |
| `data-alignment`         | `'full'`  | `'full'`, `'left'`, or `'right'`                                                                                                              |

```js
import createHydrator from 'https://assets.undrr.org/mangrove/2.0.0-rc.3/components/hydrate.js';
import QuoteHighlight, {
  fromElement,
} from 'https://assets.undrr.org/mangrove/2.0.0-rc.3/components/QuoteHighlight.js';
createHydrator({
  selector: '[data-mg-quote-highlight]',
  component: QuoteHighlight,
  fromElement,
});
```

See the [hydration guide](https://github.com/unisdr/undrr-mangrove/blob/main/docs/HYDRATION.md) for the full API and integration details.

The divergence from `TextCta` was never a decision (nothing in the repo stated a reason for it), and these three fields are the closest match in the library to the content `TextCta` already sanitises: short authored strings, hydration-fed from `data-quote`, `data-attribution` and `data-attribution-title` on a CMS-rendered container. **Consumer-visible:** the default allow-list keeps everything these props exist to carry (`<cite>`, `<em>`, `<br>`, and a link on an attribution name, verified by test), but markup that used to render will now be filtered, including `<script>`, event-handler attributes such as `onclick` and `onerror`, `javascript:` URLs, and `<iframe>` and other embeds. It also drops `target` and `referrerpolicy` from an anchor, so an attribution link authored as `target="_blank"` now opens in the same tab (the one removal here that is not an attack shape, and DOMPurify's library-wide default rather than a choice made for this component). `href`, `rel`, `class`, `id`, `title`, `hreflang`, `lang`, `dir`, `aria-*` and `data-*` survive, so styled or Linkit-referenced anchors are unaffected. Panel-sized content belongs in `Tab` or a consumer wrapper, not in a pull quote. Sanitising upstream is still worth keeping and is no longer required. The `<` check on `quote` stays, now stated for what it is: it picks the wrapper element, a `<p>` for a plain quote and a `<span>` for one with markup, and plays no part in the safety. Reverses the "you must sanitise this yourself" wording added in [#1258](https://github.com/unisdr/undrr-mangrove/pull/1258) across the component comment, the three render sites, the propTypes, this page, the CDN attribute table and the AI manifest entry. One knock-on: DOMPurify needs a DOM, and the AI manifest renders components in plain Node, so it now skips this one the way it already skips `VerticalCard` and the other sanitising components. The `renderedHtml` a vanilla-HTML consumer reads from `ai-components/components-quotehighlight.json` is therefore curated in `scripts/ai-manifest/component-data.js` instead of auto-rendered, and has to be kept in step with the JSX by hand. It carries an `aria-label` the component does not emit by itself: the unnamed `<section>` is a known limitation, and unknown props pass through to it, so a React caller can set the same label. That caveat is now in the example's published name and in the hydration note rather than only in a source comment, since the manifest is read by agents that copy the markup. The manifest's own drift guard, `checkCuratedDrift`, cannot re-render a sanitising component and had been swallowing that failure silently; it now reports each such entry as unverifiable, so the hand-maintained entries are visible as such.

That was already true and nothing about the rendering changed; this only writes it down where a consumer will meet it. The AI manifest hydration note had carried this for some time, and it was the only place it appeared: the component source said nothing, the propTypes said only "The quote text to display", and the MDX said nothing at all, so a React consumer reading the documentation had no way to learn it. The component now carries a block comment with the reasoning and a pointer at each of the three render sites, the propTypes say which fields take the HTML path, the MDX has a "Quote HTML trust contract" section after the usage example with a DOMPurify snippet, and the CDN attribute table repeats it on the three affected attributes. The per-prop asymmetry is stated: `attribution` and `attributionTitle` always render as HTML, while `quote` renders as text unless it contains a `<`, a substring test that picks a rendering path rather than a safe one.
