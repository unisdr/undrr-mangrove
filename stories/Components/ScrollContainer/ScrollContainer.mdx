# Scroll container

`ScrollContainer` provides responsive horizontal scrolling for content wider than its container.

## With minimum width

Sets a minimum width on the container, so it does not collapse below that size in a narrow parent. `min-width` wins over the container's own `max-width: 100%`, so a value wider than the parent makes the container overflow it — the demo below puts it in a parent that contains the overflow. To widen the scrollable track rather than the box, size the items with `itemWidth`.

## With navigation arrows

A scroll container with navigation arrows. Arrows appear when content overflows horizontally and `showArrows={true}`, and only when scrolling is available in that direction.

<div style={{ maxWidth: '800px', margin: '0 auto', position: 'relative' }}>
  <ScrollContainer showArrows={true} itemWidth="350px">
    {scrollCardExamples.map((card, i) => (
      <ScrollExampleCard card={card} index={i} key={card.title} />
    ))}
  </ScrollContainer>
</div>

> **Note:** Arrows show only on horizontal overflow and are hidden on mobile devices.

## With custom step size

Sets a custom arrow step size. By default, arrows scroll by half the container width; override with `stepSize` (pixels).

<div style={{ maxWidth: '800px', margin: '0 auto', position: 'relative' }}>
  <ScrollContainer showArrows={true} stepSize={200}>
    {scrollCardExamples.map((card, i) => (
      <ScrollExampleCard card={card} index={i} key={card.title} />
    ))}
  </ScrollContainer>
</div>

> **Note:** Here, each arrow click scrolls 200px.

## With single child

Demonstrates wrapping all child content in one element (for example, your own grid container).

<div style={{ maxWidth: '800px', margin: '0 auto', position: 'relative' }}>
  <ScrollContainer showArrows={true}>
    <section className="mg-grid">
      {scrollCardExamples.map((card, i) => (

  </ScrollContainer>
</div>

## Usage

```jsx
import { ScrollContainer } from '@components';

const MyComponent = () => (
  <ScrollContainer height="500px" showArrows={true}>
    {/* Your scrollable content here */}
    <div>Item 1</div>
    <div>Item 2</div>
    <div>Item 3</div>
  </ScrollContainer>
);
```

## Props

| Prop         | Type    | Default                | Description                                                                                             |
| ------------ | ------- | ---------------------- | ------------------------------------------------------------------------------------------------------- |
| children     | node    | Required               | Content to be displayed inside the scroll container                                                     |
| height       | string  | 'auto'                 | Custom height for the container                                                                         |
| minWidth     | string  | 'auto'                 | Minimum width for the container                                                                         |
| itemWidth    | string  | 'auto'                 | Width for individual items within the container                                                         |
| padding      | string  | '0'                    | Padding inside the container                                                                            |
| className    | string  | ''                     | Additional CSS class names                                                                              |
| showArrows   | boolean | false                  | Whether to show navigation arrows                                                                       |
| stretchItems | boolean | false                  | Stretch mixed-length items to a shared row height                                                       |
| stepSize     | number  | null                   | Custom step size for arrow navigation (in pixels)                                                       |
| ariaLabel    | string  | `'Scrollable content'` | Accessible name for this container's arrow navigation. Use a unique value for each container on a page. |

## Behaviors

1. **Desktop**:

   - Click and drag to scroll horizontally
   - Optional navigation arrows for controlled scrolling
   - Mouse wheel scrolling works as expected

2. **Mobile**:
   - Native touch scrolling behavior
   - Navigation arrows are hidden on mobile devices
   - Optimized for touch interactions

## Accessibility

### Arrow button labels

When `showArrows` is enabled, the buttons use `aria-label="Scroll left"` and `aria-label="Scroll right"`. They are automatically `disabled` when no further scrolling is available in that direction.

### Container semantics

- The component wraps content in a `<section>` element
- The scrollable region is focusable so keyboard users can reach native horizontal scrolling
- The arrow buttons are grouped inside a named `<nav>` element with class `mg-scroll__nav`. Set a descriptive, unique `ariaLabel` when a page has more than one scroll container, for example `ariaLabel="Related publications"`.

### Keyboard support

The focusable container relies on native browser horizontal scrolling (for example, arrow keys or Shift+scroll wheel on desktop). Arrow controls are standard `<button>` elements, reachable by Tab and activatable with Enter/Space.

### Known limitations

These are gaps that affect users or accessibility auditors:

- There are no live announcements when the scroll position changes
- No keyboard equivalent for mouse drag scrolling beyond the arrow buttons
- Arrow buttons may be hidden on devices classified as mobile by the component's JavaScript touch/user-agent detection, including some iPads or other misclassified devices
- **Pre-existing, out of this component's control:** on macOS Safari at page zoom below 100%, clicks on the arrow buttons (and the native scrollbar itself) can fail to register, while scroll-wheel and trackpad scrolling still work. This is a longstanding WebKit bug where Safari's visual-viewport and layout-viewport coordinate systems diverge under zoom, so the browser can dispatch a click to the wrong element before any application code runs. It reproduces on plain, unstyled interactive elements too, so there's no component-level fix — Safari at 100% zoom or above, and every other browser at any zoom level, are unaffected.

> **Implementation note (for contributors):** The `<section>` is intentionally unlabelled (no `role="region"` or live region). The arrow `<nav>` is named from `ariaLabel`; give each instance a distinct value where several appear together. Arrow visibility is controlled by JavaScript mobile detection (`ontouchstart` plus mobile/iPad user-agent matching), not viewport breakpoints, so any detected-mobile device may hide arrows. The scrollbar theming (`scrollbar-color` and `::-webkit-scrollbar-*`) intentionally uses fixed literal colours rather than `var(--mg-color-*)` tokens — at least one WebKit version treats a `var()`-based value in these specific properties as invalid and silently drops the whole declaration, falling back to the native scrollbar, rather than degrading gracefully.

## Server-rendered / CDN usage

ScrollContainer supports [layered hydration](https://github.com/unisdr/undrr-mangrove/blob/main/docs/HYDRATION.md). Use data attributes on a container element with server-rendered child content:

```html
<div
  data-mg-scroll-container
  data-height="300px"
  data-min-width="200px"
  data-item-width="250px"
  data-padding="16"
  data-show-arrows="true"
  data-aria-label="Related publications"
  data-stretch-items="true"
  data-step-size="300"
>
  <div class="mg-scroll__content">
    <div class="card">Card 1</div>
    <div class="card">Card 2</div>
  </div>
</div>
```

| Attribute            | Default                | Description                                                                      |
| -------------------- | ---------------------- | -------------------------------------------------------------------------------- |
| `data-height`        | `'auto'`               | Container height (CSS value)                                                     |
| `data-min-width`     | `'auto'`               | Minimum width (CSS value)                                                        |
| `data-item-width`    | `'auto'`               | Width for individual items (CSS value)                                           |
| `data-padding`       | `'0'`                  | Container padding                                                                |
| `data-show-arrows`   | `'false'`              | Show navigation arrows (`'true'` or `'false'`)                                   |
| `data-aria-label`    | `'Scrollable content'` | Accessible name for the arrow navigation; make it unique per container on a page |
| `data-stretch-items` | `'false'`              | Stretch mixed-length items to a shared row height                                |
| `data-step-size`     | `null`                 | Scroll step in pixels for arrow navigation                                       |

Child elements are extracted from a `.mg-scroll__content` wrapper inside the container. If no wrapper is found, the container's `innerHTML` is used directly.

```js
import createHydrator from 'https://assets.undrr.org/mangrove/2.0.0/components/hydrate.js';
import ScrollContainer, {
  fromElement,
} from 'https://assets.undrr.org/mangrove/2.0.0/components/ScrollContainer.js';
createHydrator({
  selector: '[data-mg-scroll-container]',
  component: ScrollContainer,
  fromElement,
});
```

See the [hydration guide](https://github.com/unisdr/undrr-mangrove/blob/main/docs/HYDRATION.md) for the full API and integration details.

## Changelog

- **1.3.5**, 2026-09-20 ([#1273](https://github.com/unisdr/undrr-mangrove/issues/1273)): The overflow region is now reachable by Tab with a visible focus indicator, so keyboard users can use the browser's native horizontal scroll keys even when its items contain no links or controls. Arrow navigation now has an accessible name derived from the new `ariaLabel` / `data-aria-label` option. Give each container a unique label on pages with more than one so landmark navigation can distinguish them.

- **1.3.4**, 2026-09-18 ([#1222](https://github.com/unisdr/undrr-mangrove/pull/1222), [#1205](https://github.com/unisdr/undrr-mangrove/issues/1205)): `fromElement` reads its content wrapper from the container it is hydrating instead of re-parsing `innerHTML` with `DOMParser` and querying the copy. The copy only ever held one container's markup, so two hydrated containers on a page never did read each other's children (the reported symptom does not reproduce), but the lookup still matched a `.mg-scroll__content` belonging to a **nested** scroll container, so an outer container with no wrapper of its own rendered the nested container's cards instead of its own content. A direct-child wrapper now wins, otherwise the first descendant wrapper with no nested scroll container between it and this container. Dropping the `DOMParser` round trip also stops the server-rendered markup being re-serialised on the way through. A new "Two hydrated on one page" story hydrates two rows through `createHydrator`; each keeps its own cards.
- **1.3.3**, 2026-09-17 ([#1193](https://github.com/unisdr/undrr-mangrove/pull/1193)): The "With minimum width" story asked for `minWidth="1500px"` in an unbounded parent, so at 375px the demo pushed the whole page sideways to 1516px. The story now uses a realistic value inside a parent that contains the overflow, and the docs spell out that `min-width` wins over the container's `max-width: 100%` and that `itemWidth` is the lever for widening the scrollable track. Story and documentation only: `minWidth` keeps its documented meaning, a minimum width for the container, and no component behaviour changed.

Uses fixed literal colours rather than `var(--mg-color-*)` tokens, since at least one WebKit version silently drops the whole declaration if it contains a `var()` value there. Desktop-only in practice; mobile browsers generally hide or ignore scrollbar styling regardless. Known pre-existing limitation noted: macOS Safari below 100% zoom can fail to register clicks on this component's arrow buttons and its native scrollbar, due to a longstanding WebKit viewport-coordinate bug unrelated to this component.
