# Tree

The `Tree` component provides an accessible hierarchical navigation structure conforming to the [W3C ARIA Treeview Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/).

## Features

- **ARIA APG Treeview Navigation**: Full roving tabindex and arrow keyboard navigation.
- **Controlled & Uncontrolled State**: Support for `expandedIds` / `defaultExpandedIds` and `selectedId` / `defaultSelectedId`.
- **Linked Parent Sections**: Independent toggle control (`mg-tree__toggle`) and navigation link (`mg-tree__label`).
- **Mangrove tokens**: built with canonical interactive and neutral colour tokens.
- **RTL**: ArrowRight and ArrowLeft swap and the chevron mirrors in right-to-left layouts.

## When a treeview is the right pattern

A treeview is a single composite widget. The whole tree is one tab stop, and
arrow keys move a roving `tabindex` between the items inside it. That is what
makes it good for navigating a deep hierarchy quickly, and it is also what
rules out a whole class of interfaces that look like trees.

Use `Tree` when:

- The hierarchy is there to be **navigated or selected from** — a knowledge
  base section list, a category picker, a file tree.
- Each row's whole job is to be chosen or to expand. Activating a row selects
  it, follows its link, or opens its children.
- One tab stop for the entire structure is what you want, so a keyboard user
  arrows through 200 items instead of tabbing past them.

Do not use `Tree` when **each row carries its own controls** — a switch, a
delete button, a menu, an expand button that is separate from the row itself.
A `treeitem` is a composite widget item, so an interactive control inside one
is nested interactive content: axe reports it as `nested-interactive`, and the
underlying problem is real rather than a lint preference. The row owns the
keyboard, so the control inside it has no reliable way to be reached or
operated, and screen readers announce the row's role rather than the control's.
A map layer panel where every row has a visibility switch _and_ an expand
button is the clearest example: it looks like a tree and is not one.

Reach for these instead:

| Shape                                                   | Use                                                                             |
| ------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Nested rows, each with its own switch, button or menu   | Grouped `<details>` / `<summary>`, or a plain nested list of ordinary controls  |
| A row that expands, with nothing else interactive in it | `Tree`, or [ShowMore](?path=/docs/components-showmore--docs) for a single block |
| A flat list of options to choose one or several of      | [Checkbox or switch](?path=/docs/components-forms-checkbox--docs)               |
| A hierarchy that is navigated, with links only          | `Tree`                                                                          |
| Tabular rows with per-row actions                       | A `<table>` with buttons in cells                                               |

Grouped `<details>`/`<summary>` is the honest fallback for the rejected case.
Each summary is its own tab stop, each row's controls are ordinary controls in
the normal tab order, and the disclosure state is announced by the browser
without any ARIA of your own. You lose arrow-key traversal across the whole
hierarchy. For a panel of a dozen or so layer rows that is a good trade;
for a 200-item navigation tree it is not, and that is the line between the two
patterns.

If you are partway into a treeview and axe is reporting `nested-interactive`,
moving the offending control **out of the item's ancestry** is usually the fix,
not adding ARIA to paper over it. A team building a hazard layer panel on
Mangrove cleared eight violations of exactly this shape that way
([#1197](https://github.com/unisdr/undrr-mangrove/issues/1197)).

## Usage

### Basic tree

```jsx
import { Tree, TreeItem } from '@undrr/undrr-mangrove/components/Tree.js';

<Tree defaultExpandedIds={['1']}>
  <TreeItem id="1" label="Section 1">
    <TreeItem id="1-1" label="Topic 1.1" />
    <TreeItem id="1-2" label="Topic 1.2" />
  </TreeItem>
  <TreeItem id="2" label="Section 2" />
</Tree>;
```

### Controlled tree

```jsx
const [expandedIds, setExpandedIds] = useState(['1']);
const [selectedId, setSelectedId] = useState('1-1');

<Tree
  expandedIds={expandedIds}
  selectedId={selectedId}
  onToggle={(id, isExpanded) => {
    setExpandedIds(prev =>
      isExpanded ? [...prev, id] : prev.filter(item => item !== id)
    );
  }}
  onSelect={id => setSelectedId(id)}
>
  <TreeItem id="1" label="Parent">
    <TreeItem id="1-1" label="Child 1" />
    <TreeItem id="1-2" label="Child 2" />
  </TreeItem>
</Tree>;
```

### With links

Parent and leaf items can also function as standard links.

```jsx
<Tree>
  <TreeItem id="1" label="Parent" href="/parent" asLink>
    <TreeItem id="1-1" label="Child 1" href="/child1" asLink />
    <TreeItem id="1-2" label="Child 2" href="/child2" asLink />
  </TreeItem>
</Tree>
```

### Toggle icon

The expand toggle uses `mg-icon-right` by default. Set `toggleIcon` on `Tree` to change it for every item, or on a `TreeItem` to change one. Pick a glyph that points towards the inline end: it turns a quarter turn when expanded and mirrors in right-to-left layouts.

```jsx
<Tree toggleIcon="mg-icon-arrow-right">
  <TreeItem id="1" label="Section 1">
    <TreeItem id="1-1" label="Topic 1.1" />
  </TreeItem>
</Tree>
```

Give the tree an accessible name with `aria-label` or `aria-labelledby`. Other props are passed to the `<ul role="tree">`.

### Drupal and server-rendered HTML (hydration)

The static HTML in the AI manifest has the tree roles but no keyboard support. For non-React pages, render a plain nested list inside a `data-mg-tree` container and hydrate it. Before JavaScript runs, and if it fails, the list still works as ordinary links.

```html
<div
  data-mg-tree
  data-aria-label="Section navigation"
  data-toggle-icon="mg-icon-arrow-right"
>
  <ul>
    <li data-id="about" data-expanded>
      <a href="/about">About</a>
      <ul>
        <li data-id="team">
          <a href="/about/team" aria-current="page">Team</a>
        </li>
        <li data-id="history"><a href="/about/history">History</a></li>
      </ul>
    </li>
    <li data-id="topics">
      Topics
      <ul>
        <li data-id="floods"><a href="/topics/floods">Floods</a></li>
      </ul>
    </li>
  </ul>
</div>
```

```js
import createHydrator from '@undrr/undrr-mangrove/components/hydrate.js';
import Tree, { fromElement } from '@undrr/undrr-mangrove/components/Tree.js';

createHydrator({
  selector: '[data-mg-tree]',
  component: Tree,
  fromElement,
});
```

The bare specifiers above resolve through a bundler or an import map. Without a bundler, map `react`, `react-dom` and `react-dom/` (the hydration runtime imports `react-dom/client`) and import the modules from the CDN, as the [hydration guide](?path=/docs/getting-started-integration-hydration-guide--docs) shows. See the [CDN reference](?path=/docs/getting-started-integration-cdn-reference--docs) for paths.

The page also needs a Mangrove stylesheet for the tree styles. A theme class such as `mg-theme-irp` only takes effect with that brand's stylesheet (`style-irp.css`) or the combined `style-all.css`; `style.css` has no brand blocks. See the [theming guide](?path=/docs/getting-started-integration-theming-guide--docs).

The default export of `components/Tree.js` is `HydratedTree`. It renders the same `Tree` and `TreeItem` components from an `items` array, so keyboard navigation and ARIA match the React version. Without `items` it takes `TreeItem` children like `Tree`. The named `Tree` and `TreeItem` exports are unchanged.

Container attributes:

| Attribute              | Default           | Description                                                      |
| ---------------------- | ----------------- | ---------------------------------------------------------------- |
| `data-aria-label`      | —                 | Accessible name for the tree. Set this or `data-aria-labelledby` |
| `data-aria-labelledby` | —                 | id of a visible heading that names the tree                      |
| `data-toggle-icon`     | `'mg-icon-right'` | Icon class for the expand toggles                                |
| `data-guides`          | `'true'`          | Show indentation guides (`'true'` / `'false'`)                   |
| `data-selected-id`     | —                 | Selected item id, used when no item is marked selected           |
| `data-class-name`      | —                 | Extra class on the tree                                          |

Each `<li>` in the first `<ul>` or `<ol>` becomes a tree item. Nested lists become child groups.

| Item markup                                                | Result                                                                                                                                                              |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data-id`                                                  | Item id. Must be unique in the tree; a repeated id gets a numeric suffix (`x-2`). Without `data-id` the `<li>` id is used, and without either, its position (`1-2`) |
| Child `<a href>`, direct or wrapped once (`<li><span><a>`) | Link item; its text is the label, or its `aria-label` or image `alt` if it has no text. `javascript:`, `data:` and `vbscript:` URLs are dropped                     |
| Text without a link                                        | Plain label. Read as text; markup is not kept                                                                                                                       |
| `data-expanded` or `aria-expanded="true"`                  | Starts expanded (items with children only)                                                                                                                          |
| `data-selected`, or `aria-current` on the link             | Starts selected, and its parent items start expanded. The first match wins. `aria-current` is kept on the rendered link                                             |

Item DOM ids get a generated prefix for each tree, so two trees built from the same ids, such as a desktop and a mobile menu, do not repeat ids on one page. The ids are not stable: in-page links to the original `<li>` ids will not resolve after hydration. Use `data-mg-treeitem-id="{id}"` to find an item from script.

## Keyboard Interaction (ARIA APG)

When the tree receives focus, focus goes to the selected item. If the selected item is inside a collapsed parent, focus goes to its nearest visible parent, and with no selection, to the first item.

| Key               | Expected behaviour                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------- |
| `↓` Arrow         | Move focus to next visible treeitem                                                         |
| `↑` Arrow         | Move focus to previous visible treeitem                                                     |
| `→` Arrow         | Expand collapsed node; or move focus to first child if already open                         |
| `←` Arrow         | Collapse expanded node; or move focus to parent treeitem                                    |
| `Home`            | Move focus to first visible treeitem                                                        |
| `End`             | Move focus to last visible treeitem                                                         |
| `Enter` / `Space` | Select focused treeitem; follow its own link, or expand or collapse a parent without a link |
