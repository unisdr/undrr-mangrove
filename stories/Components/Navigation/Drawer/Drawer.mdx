# Drawer

The `Drawer` component provides an accessible off-canvas drawer and floating panel for navigation, filters, settings, and secondary actions.

## Features

- **Positions**: `start` and `end` follow text direction (they swap in RTL), plus `bottom` for a sheet.
- **Variants**: a modal off-canvas drawer (with backdrop) or a non-modal floating panel (`isFloatingPanel`).
- **Accessibility**: `role="dialog"` named by the title, `aria-modal` while a backdrop drawer is open, focus moves to the close button on open, Tab stays inside a modal drawer, focus returns to the trigger on close, and Escape closes it. A closed drawer is `inert` and hidden, so its controls cannot be reached.
- **Content safety**: string `children` and `footer` render as plain text. Server-rendered markup goes through `bodyHtml` / `footerHtml`, which are sanitised with DOMPurify.
- **Translations**: the close button label comes from `labels.closeLabel`.

## Usage

### React

```jsx
import { Drawer } from '@undrr/undrr-mangrove/components/Drawer.js';

<Drawer
  isOpen={isOpen}
  onClose={() => setIsOpen(false)}
  title="Filter publications"
  position="start"
  labels={{ closeLabel: 'Close' }}
  footer={
    <button type="button" className="mg-button mg-button-primary">
      Show 128 results
    </button>
  }
>
  <p>Narrow the publications list by hazard, region and year.</p>
</Drawer>;
```

### Vanilla HTML (`js/drawer.js`)

For a page with no React, load `js/drawer.js`. It gives you the same
behaviour the React component has — open and close, Escape, focus management,
a focus trap while a modal drawer is open, and cleanup — against markup you
wrote yourself.

The module never builds a drawer. It enhances the one in your HTML, so the
close button's `aria-label`, the title and the body stay on the page that
renders them and translation stays with your CMS. The only element it creates
is the backdrop, which carries no text.

There is no `js/floating-panel.js`, and there will not be. A floating panel is
the same component as a drawer with `isFloatingPanel` set — the React
`Drawer` only switches its base class — so one module drives both. Give the
container `class="mg-floating-panel"` and load `js/drawer.js`.

> **Lands in 2.0.** `js/drawer.js` postdates `2.0.0-rc.2`, so no CDN version
> folder serves it until 2.0 is released — a `<script>` pointing at it returns
> 404 in the meantime, on `latest/` as well as on any pinned prerelease. Until
> then, install the package and bundle
> `@undrr/undrr-mangrove/js/drawer.js` yourself. The stylesheet line below
> works on every version.

Replace `{version}` with the release you are pinning to. The stylesheet uses
`latest`, which always points at the newest stable release.

```html
<link
  rel="stylesheet"
  href="https://assets.undrr.org/mangrove/latest/css/style.css"
/>

<button
  type="button"
  data-mg-drawer-trigger="filters"
  class="mg-button mg-button-primary"
>
  Filter publications
</button>

<div
  id="filters"
  class="mg-drawer mg-drawer--start"
  data-mg-js-drawer
  role="dialog"
  tabindex="-1"
>
  <div class="mg-drawer__header">
    <h2 class="mg-drawer__title">Filter publications</h2>
    <button
      type="button"
      class="mg-icon-button mg-icon-button--small mg-drawer__close"
      aria-label="Close"
    >
      <span class="mg-icon mg-icon-close" aria-hidden="true"></span>
    </button>
  </div>
  <div class="mg-drawer__body">
    <p>Narrow the publications list by hazard, region and year.</p>
  </div>
</div>

<!-- Lands in 2.0; returns 404 on every version folder until then. -->
<script
  type="module"
  src="https://assets.undrr.org/mangrove/{version}/js/drawer.js"
></script>
```

Every `[data-mg-js-drawer]` container is enhanced on page load. For drawers
added later, and for cleanup, import the named exports:

```js
import { mgDrawer, mgDrawerDestroy } from '@undrr/undrr-mangrove/js/drawer.js';

mgDrawer(container); // enhances the drawers in `container`; already-enhanced ones are skipped
mgDrawerDestroy(container); // removes the listeners, the backdrop and the attributes it set
```

`mgDrawer()` returns a handle per drawer with `open()`, `close()`, `toggle()`
and `isOpen()`. `mgDrawerOpen(element)`, `mgDrawerClose(element)`,
`mgDrawerToggle(element)` and `mgDrawerInstance(element)` reach an enhanced
drawer you do not hold a handle for.

| Markup                             | Effect                                                                                                               |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `data-mg-js-drawer`                | Marks the container. Required, and distinct from the `data-mg-drawer` hydration marker — use one path, not both      |
| `id`                               | Required, so `data-mg-drawer-trigger` buttons can find the drawer                                                    |
| `data-mg-drawer-trigger="<id>"`    | On a button anywhere in the page. Clicking toggles the drawer; the button gets `aria-expanded` and `aria-controls`   |
| `class="mg-floating-panel"`        | Non-modal floating panel: no backdrop, no `aria-modal`, no focus trap, and Escape only from inside it or its trigger |
| `class="is-open"`                  | The drawer starts open                                                                                               |
| `data-backdrop="false"`            | An edge drawer with no backdrop, and so not modal                                                                    |
| `data-mg-js-drawer-skip-auto-init` | Skips this container on page-load auto-init; an explicit `mgDrawer()` call still enhances it                         |

Dispatch `mg-drawer:open`, `mg-drawer:close` or `mg-drawer:toggle` on the
container to drive it from script — the same event names the hydrated drawer
answers. The module also dispatches `mg-drawer:opened` and `mg-drawer:closed`
after the drawer has moved; both bubble.

What the module does for accessibility, so you do not have to: it adds
`role="dialog"` and `tabindex="-1"` when your markup omits them, names the
dialog from its own `.mg-drawer__title` when you have given it no `aria-label`
or `aria-labelledby` (minting an id for the title if it has none, and giving it
back on destroy), keeps a closed
drawer `inert` and `aria-hidden` so its controls stay out of the tab order,
moves focus to the close button on open, sets `aria-modal` only while a modal
drawer is open, and traps Tab inside a modal drawer. A floating panel is
deliberately left untrapped: the rest of the page is still operable, and
trapping Tab there would be wrong.

The trap counts anything the browser will stop on, not just links and form
controls — an `<iframe>`, a `contenteditable` region, a `<summary>` — and
ignores anything it will skip: a `display:none` or `visibility:hidden`
element, a control in a closed `<details>`, and every radio in a group but the
one that is actually a tab stop. Getting either half of that wrong is how a
trap leaks: a hidden element at the end of the drawer means Tab never reaches
the wrap point and walks out into the page behind the backdrop, and a hidden
element at the start means Shift+Tab calls `focus()` on something that cannot
take it and focus stops moving at all. If focus does get out — the one case
that remains is tabbing through an `<iframe>`'s own document, which the
parent page cannot see — the next Tab pulls it back.

On close, focus goes to whatever opened the drawer. When that is gone, hidden,
or never existed — a drawer opened from script, or an opener the app has since
re-rendered away — it falls back to a trigger for the drawer, and then to the
document body. It is never left on a control inside the drawer that has just
been made `inert`.

Escape closes the innermost open drawer only, so a drawer opened from inside
another peels one layer at a time, and it leaves an Escape alone when
something nearer the user has already answered it — a nested `<dialog>`, a
date picker, an open `<select>`. A modal drawer answers Escape from anywhere
on the page, because it owns the page while it is open. A **non-modal floating
panel only answers Escape from inside itself or from its trigger**: the page
behind it is still in use, and pressing Escape in a search field there should
not dismiss the panel.

The dialog name is a loan, not a repair. If your markup has a
`.mg-drawer__title` but nothing naming the dialog, the module points
`aria-labelledby` at it — and hands that back on destroy, along with the id it
minted. Markup that carries `role="dialog"` with no name is therefore unnamed
again once the module is gone. Name the dialog in your own markup if you want
that fixed for good.

Calling `mgDrawer()` twice is safe. An enhanced container carries
`data-mg-js-drawer-initialized` and is skipped on a second pass, so a re-scan
after inserting markup cannot bind a second set of listeners. A container that
carries both `data-mg-js-drawer` and the `data-mg-drawer` hydration marker is
refused with a console warning and left to hydration, rather than enhanced by
both paths at once.

### Drupal and server-rendered HTML (hydration)

Use this path when React is already on the page, or when the drawer body is
built from server-rendered markup you want sanitised on mount. For a page with
no React, prefer `js/drawer.js` above: it is smaller, needs no import map, and
keeps your own markup. Pick one. A container marked with both
`data-mg-drawer` and `data-mg-js-drawer` is left to hydration and skipped by
`mgDrawer()`, with a console warning naming the container — React would
otherwise re-render away the markup the vanilla module had just bound
listeners to.

Give the container an `id` and point one or more trigger buttons at it with `data-mg-drawer-trigger`:

```html
<button type="button" data-mg-drawer-trigger="filters">
  Filter publications
</button>

<div
  id="filters"
  data-mg-drawer
  data-position="start"
  data-title="Filter publications"
  data-backdrop="true"
  data-is-open="false"
  data-close-label="Close"
>
  <div class="mg-drawer__body">
    <p>Narrow the publications list by hazard, region and year.</p>
  </div>
  <div class="mg-drawer__footer">
    <button type="button" class="mg-button mg-button-primary">
      Show 128 results
    </button>
  </div>
</div>
```

```js
import createHydrator from '@undrr/undrr-mangrove/components/hydrate.js';
import Drawer, {
  fromElement,
} from '@undrr/undrr-mangrove/components/Drawer.js';

createHydrator({
  selector: '[data-mg-drawer]',
  component: Drawer,
  fromElement,
});
```

The hydrated drawer keeps its own open state. Clicking a trigger toggles it and updates the trigger's `aria-expanded`. Scripts can also dispatch `mg-drawer:open`, `mg-drawer:close` or `mg-drawer:toggle` on the container.

| Attribute                | Default   | Description                                                            |
| ------------------------ | --------- | ---------------------------------------------------------------------- |
| `id`                     | —         | Required for `data-mg-drawer-trigger` buttons to find the drawer       |
| `data-position`          | `'start'` | Drawer edge placement (`'start'`, `'end'`, `'bottom'`)                 |
| `data-title`             | —         | Drawer header title text                                               |
| `data-backdrop`          | `'true'`  | Whether to render the semi-transparent backdrop (`'true'` / `'false'`) |
| `data-is-floating-panel` | `'false'` | Whether to render as a floating panel                                  |
| `data-is-open`           | `'false'` | Initial open state                                                     |
| `data-close-label`       | `'Close'` | Translated close button label                                          |
