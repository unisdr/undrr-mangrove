# Preview access

A page-level PIN gate for unfinished pages. By default, an unlock lasts for the rest of the browser tab's session; set `data-mg-preview-persist="local"` to remember it across tabs and visits.

> **Note:** This is not a security mechanism. The PIN sits in the DOM and the unlock is held in `sessionStorage` (or `localStorage`), so anyone with developer tools can bypass it. The component is editorial signalling for review audiences only.

## When to use

- Sharing unfinished dashboards or content with reviewers before public launch
- Signalling to casual visitors that a page is unfinished (use server access controls to restrict access and indexing)
- Marking a whole product preview (for example, a DELTA preview site) with a single shared PIN

For real access control, gate the page at the edge with a service like Cloudflare Access. This component is for editorial signalling only.

## Vanilla HTML usage

You need three things in the page:

```html
<!-- 1. CSS in <head> -->
<link
  rel="stylesheet"
  href="https://assets.undrr.org/mangrove/2.1.1/css/style.css"
/>

<!-- 2. Trigger as the first element in <body> -->
<div data-mg-preview-access></div>

<!-- 3. Script before </body> as type="module" (the file uses ESM exports) -->
<script
  type="module"
  src="https://assets.undrr.org/mangrove/2.1.1/js/preview-access.js"
></script>
```

With no extra attributes, the gate uses PIN `5498`, default UNDRR copy, and `undrr.org/contact-us` for the contact link.

> **Tip:** Place the trigger as the first `<body>` child to avoid content painting before the gate applies.

All attributes go on the trigger element. All optional except the bare `data-mg-preview-access`.

## Remembering an unlock

The default, `session`, keeps the unlock in `sessionStorage`. That storage belongs to one tab, so reviewers enter the PIN again in every new tab ("open in new tab" included) and on every return visit.

For multi-page previews that reviewers share links into, set `data-mg-preview-persist="local"`. The unlock is then kept in `localStorage` and lasts across tabs and visits on the same browser:

```html
<div
  data-mg-preview-access
  data-mg-preview-id="gar-2026-preview"
  data-mg-preview-persist="local"
  data-mg-preview-max-age="30"
></div>
```

- **Expiry.** With `data-mg-preview-max-age` (days, decimals allowed), a local unlock at least that old is treated as locked and removed when a page initialises. Without it, a local unlock does not expire. Invalid or future-dated timestamps are rejected in either case.
- **Changing the PIN invalidates local entries.** A local unlock stores a short fingerprint of the PIN it was made with. When the page's PIN changes, existing local unlocks no longer match and are removed. This applies to `local` entries only. Both modes still accept an existing `session` unlock until its tab closes, including after a PIN change or local expiry. Already open pages are not relocked automatically.
- **Existing session unlocks still count.** Both modes honour a `session` unlock, so switching a site to `local` does not relock tabs that are already open.
- **Fallback.** If `localStorage` cannot be written (some private modes, storage blocked), the unlock falls back to `sessionStorage` for that tab.

Both modes use the same key, `mg-preview-access:{id}`. A `session` entry is the string `unlocked`; a `local` entry is JSON, for example `{"pin":"6ad1ce55","at":1792108800000}` for the default PIN, with `at` the unlock time in milliseconds.

### Consent

A `local` unlock remembers that the visitor entered the PIN. This component stores only the PIN fingerprint and unlock time, and does not send them to a server or use them for tracking. Ask the site's consent-policy owner to confirm how persistent storage should be handled before enabling it.

## Unlock event

When the gate opens, it dispatches a bubbling `mg-preview-access:unlock` `CustomEvent` on the trigger element. Embeds that need to wait for the page to be revealed (for example, to size a map viewer) can listen for it rather than watching for the `mg-preview-access--unlocked` class.

```js
document.addEventListener('mg-preview-access:unlock', event => {
  const { id, persist, source } = event.detail;
  // id: the storage scope key; persist: configured mode ('session' or 'local'),
  // even if storage is blocked and the unlock falls back to this tab;
  // source: 'pin' (just entered) or 'storage' (already unlocked on load)
});
```

The event fires in both cases: when a reviewer enters the right PIN, and when the gate initialises already unlocked from storage. The storage case fires during initialisation, which runs on `DOMContentLoaded` (or as soon as the script runs, if the DOM is ready). Register the listener on `document` before `preview-access.js` loads, or also check for the `mg-preview-access--unlocked` class, so you do not miss it. A wrong PIN does not dispatch anything.

## JavaScript API

The component auto-initialises on `DOMContentLoaded` (or immediately if the script loads after the DOM is ready). For dynamic content or manual initialisation:

```js
import {
  mgPreviewAccess,
  mgPreviewAccessDestroy,
} from 'path/to/preview-access.js';

// Initialise the first [data-mg-preview-access] in the document
mgPreviewAccess();

// Initialise specific elements
mgPreviewAccess([myGateElement]);

// Tear down (removes the overlay, restores body siblings, clears init flag)
mgPreviewAccessDestroy(myGateElement);
```

After the ESM script has loaded, the initializer is also exposed as `window.mgPreviewAccess`. The file must still be loaded with `type="module"`; loading it as a classic script fails on its exports.

## Usage with React

> **Integration note:** This is a vanilla JS, body-level gate (page-level concern, not subtree state). The exported `<PreviewAccess>` React component is a static Storybook preview. Use one of the patterns below to run the real gate in React.

```jsx
// Option A: drop the trigger element in your root layout and let the
// auto-init handle the rest.
function RootLayout({ children }) {
  return (
    <>
      <div data-mg-preview-access data-mg-preview-pin="5498" />
      {children}
    </>
  );
}
```

```jsx
// Option B: call mgPreviewAccess() yourself in a top-level effect.
import { useEffect, useRef } from 'react';
import {
  mgPreviewAccess,
  mgPreviewAccessDestroy,
} from '@undrr/undrr-mangrove/js/preview-access.js';

function Gate() {
  const ref = useRef(null);
  useEffect(() => {
    const gate = ref.current;
    if (gate) mgPreviewAccess([gate]);
    return () => {
      if (gate) mgPreviewAccessDestroy(gate);
    };
  }, []);
  return <div ref={ref} data-mg-preview-access data-mg-preview-pin="5498" />;
}
```

To activate the real gate from the Storybook story, pass `live` to `<PreviewAccess>`. See the **Live demo** story.

## Accessibility

- The overlay renders as `role="dialog"` with `aria-modal="true"`, `aria-labelledby` pointing at the title, and `aria-describedby` pointing at the body
- Body siblings receive `inert` so focus is trapped in the modal and the rest of the page is hidden from assistive technology
- The wrong-PIN error uses `role="alert"` so the message is announced
- Focus moves into the PIN input on mount, after `requestAnimationFrame` so layout has settled
- After unlock, focus returns to the element that had it before the gate mounted, if there was one. On page load there usually is not (focus is on `<body>`), so focus moves to `<main>` or `[role="main"]`, then the `#main` skip-link target, then the first `<h1>`, with `<body>` as the last resort. Hidden, inert or disabled targets are skipped if they cannot receive focus. Non-focusable targets get a temporary `tabindex="-1"`, removed when they lose focus or immediately if focus fails; author-set values are preserved
- The submit button passes 4.5:1 contrast against `$mg-color-interactive` across all five themes
- There is no Escape-to-close. The gate is meant to hold until a PIN is entered

## RTL and internationalisation

The component supports RTL automatically when `dir="rtl"` and `lang="ar"` are set on the document:

- Headings/chrome use `var(--mg-font-family-ui)`; body/error/contact copy use `var(--mg-font-family-text)`. Under `lang="ar"`, both resolve to Noto Sans Arabic (Roboto Condensed has no Arabic glyph coverage). Font routing lives in `_fonts.scss`; this component has no `:lang(ar)` rule
- All visible copy comes from data attributes, so translations are a content-only change

## Implementation notes

> **Implementation note (for contributors):** Design decisions behind the gate. These choices were intentional — read before "fixing" them.

**CSS-first anti-flash via `:has()`.** The gate hides page content with CSS (not JS): `body:has([data-mg-preview-access]:not(.mg-preview-access--unlocked)) > *:not(.mg-preview-access__overlay) { visibility: hidden }`. This avoids FOUC and deferred-script races. Keep the trigger first in `<body>` to prevent earlier siblings from painting. `:has()` is supported in current evergreen browsers.

**`visibility: hidden`, not `display: none`.** This preserves layout and avoids unlock reflow. Images/iframes still load in the background.

**`inert` on body siblings.** While open, every direct `<body>` child except the overlay gets `inert` (pre-existing inert content stays inert after unlock or teardown), providing focus trapping, AT hiding, and pointer blocking without a focus-trap library. ARIA 1.2 treats `aria-hidden` as redundant with `inert`, so it is intentionally omitted.

**Persistence.** On unlock, the gate stores `sessionStorage["mg-preview-access:<id>"] = "unlocked"`, or with `persist="local"` a JSON entry under the same key in `localStorage` (see [Remembering an unlock](#remembering-an-unlock)). The id defaults to `location.pathname` and can be overridden with `data-mg-preview-id` to share unlock state across pages. The PIN fingerprint is a 32-bit FNV-1a hash: enough to notice a changed PIN, not a security measure. Every storage call is wrapped in `try`/`catch`, so blocked storage means "locked", never an error.

**Contact URL allow-list.** `data-mg-preview-contact-url` is restricted to `http:`, `https:`, or `mailto:`. Other protocols (for example, `javascript:`) fall back to the default UNDRR contact page.

**Bespoke modal shell.** Mangrove has no shared modal primitive yet. This gate uses Mangrove tokens (`$mg-z-index-modal`, `$mg-color-modal-scrim`, `$mg-color-interactive`, `$mg-spacing-*`, `var(--mg-font-family-ui)`, `var(--mg-font-family-text)`) with a custom panel, and should migrate to a shared primitive when available.

## Known limitations

- **Single trigger per page.** The script honours one trigger per page (the first match). Multi-zone gating (a preview block inside an otherwise public page) is a different pattern.
- **No Escape-to-close.** Deliberate. The gate should hold until a PIN is entered. A dismissible variant would be a separate prop.
- **`:has()` is the anti-flash strategy.** If older browser support is needed, add a small inline `<script>` in `<head>` that sets a class on `<html>` and mirror the CSS rule to that class.
- **PIN in the DOM.** This is editorial signalling, not access control. Anyone with developer tools can read the PIN and bypass the gate.
