# Copy button

The `CopyButton` allows users to quickly copy a string to their clipboard, featuring a visual micro-feedback tooltip and accessible status announcements via `aria-live`.

## Integration options

Mangrove offers three integration paths depending on your project setup:

### Option 1: Standalone Vanilla JS (Zero React Dependency)

For Drupal Twig templates, static HTML pages, or server-rendered layouts where React is not used, load the standalone script from the CDN (`https://assets.undrr.org/mangrove/2.0.0-rc.2/js/copy-button.js`) or from npm (`@undrr/undrr-mangrove/js/copy-button.js`). It automatically initializes all `[data-mg-copy-button]` elements on the page.

The script file uses ES module `export` statements, so you **must** load it with `type="module"`. A plain `<script src>` throws `SyntaxError: Unexpected token 'export'`.

```html
<button
  type="button"
  class="mg-button mg-button-primary mg-button-outline mg-button--icon mg-copy-button"
  data-mg-copy-button
  data-text-to-copy="https://preventionweb.net/drr-glossary"
  aria-label="Copy glossary link"
  data-tooltip-label="Copied!"
>
  <span class="mg-icon mg-icon-copy mg-button__icon" aria-hidden="true"></span>
  <span class="mg-copy-button__feedback" role="status" aria-hidden="true">
    Copied!
  </span>
  <span class="mg-u-sr-only" aria-live="polite"></span>
</button>

<!-- JS: type="module" is required -->
<script
  type="module"
  src="https://assets.undrr.org/mangrove/2.0.0-rc.2/js/copy-button.js"
></script>
```

In Drupal behaviors or SPAs, you can manually re-initialize dynamically inserted content:

```js
import { mgCopyButton } from '@undrr/undrr-mangrove/js/copy-button.js';

Drupal.behaviors.copyButton = {
  attach(context) {
    mgCopyButton(context);
  },
};
```

### Option 2: Layer 2 React Hydration (`createHydrator`)

If your Drupal site uses Mangrove's shared React hydration runtime with import maps:

```js
import createHydrator from '@undrr/undrr-mangrove/components/hydrate.js';
import CopyButton, {
  fromElement,
} from '@undrr/undrr-mangrove/components/CopyButton.js';

createHydrator({
  selector: '[data-mg-copy-button]',
  component: CopyButton,
  fromElement,
});
```

### Option 3: React JSX Component

In React applications:

```jsx
import { CopyButton } from '@undrr/undrr-mangrove';

<CopyButton
  textToCopy="https://preventionweb.net/drr-glossary"
  ariaLabel="Copy glossary link"
  variant="outline"
/>;
```

## Data attributes reference

| Attribute            | Default                  | Description                                                   |
| -------------------- | ------------------------ | ------------------------------------------------------------- |
| `data-text-to-copy`  | `''`                     | Text string to be written to the clipboard                    |
| `data-tooltip-label` | `'Copied!'`              | Text displayed inside the transient micro-feedback badge      |
| `data-copied-label`  | `'Copied to clipboard.'` | Text announced to `aria-live` upon successful copy            |
| `data-variant`       | `'outline'`              | Button visual style (`'outline'`, `'primary'`, `'secondary'`) |
| `data-size`          | `—`                      | Button icon size (`'small'`, `'large'`)                       |

### Naming the button

The button is icon-only, so it needs an accessible name of its own (WCAG 4.1.2 Name, Role, Value). Put it in a plain `aria-label` — every integration path reads it, including the React `ariaLabel` prop it maps to under hydration.

`data-aria-label` is the older spelling and stays supported, so markup already in the wild keeps its name: the vanilla script copies it onto `aria-label` when the button has none, and `fromElement` falls back to it. Do not use it in new markup, and never rely on it alone — a button that carries only `data-aria-label` announces as "button" for as long as the script takes to load, and as "button" forever if it fails to.

An `aria-label` or `aria-labelledby` you set yourself is never overridden.

An `aria-label` or `aria-labelledby` you set yourself is never overridden.
  - `fromElement` now reads a plain `aria-label` off the container before the `data-*` spellings, so markup written against these docs keeps its name on the Layer 2 hydration path too.
