# CTA block prototype

A second direction for [web-backlog #2412](https://gitlab.com/undrr/web-backlog/-/work_items/2412):
use the existing TextCta banner as a general promotional block. Its heading,
copy, image and buttons already cover several use cases. An optional React
`children` slot allows a caller-owned form to sit below the copy.

The <LinkTo kind="Example/Newsletter promotion" story="Compact signup">original newsletter prototype</LinkTo>
is preserved for comparison. This version tests a more prominent CTA treatment;
it does not replace the earlier, quieter article signup pattern.

## Proposed boundary

```jsx
<TextCta headline="Stay informed" text="Choose the updates that matter to you." centered={false}>
  <YourSignupForm />
</TextCta>
```

TextCta manages presentation only. The caller controls submission, fields,
preferences, privacy information and feedback. Existing `buttons` usage remains
supported and renders after custom content when both are supplied.

Drupal can compose the same layout using the CTA classes around its native form.
The current TextCta hydrator does not preserve arbitrary form children: do not
apply its hydration marker to this composition. Provider integrations should keep
ownership of their markup and behaviour.

Use the tone, theme, colour and locale controls to compare these examples. This is a
layout exploration; the original newsletter prototype has the fuller simulated
error/confirmation journey.
