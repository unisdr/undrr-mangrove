# Collection page

> **Note:** Designed for PreventionWeb collections on [undrr/web-backlog#2728](https://gitlab.com/undrr/web-backlog/-/work_items/2728); Drupal implements it later. Review against the [component checklist](https://github.com/PreventionWeb/undrr-mangrove/blob/main/docs/REVIEW-CHECKLIST.md).

A collection is a curated set of news, publications, blogs and other resources on one topic, such as [wildfire risk assessment](https://www.preventionweb.net/collections/wildfire-risk-assessment). The page's job is to orient the reader: what the collection is, what is in it, and where to go next. It follows the shape of a PreventionWeb hazard page: a defining header with the image beside it, on the page's own white surface, the detail behind a show-more, then an index of the content.

The examples use real PreventionWeb collections and query the live search index, so the item counts and lists are real.

## Collection page

<Canvas of={Stories.Typical} />

<Controls of={Stories.Typical} />

An orienting header, a sticky "On this page" bar, then three sections, each a landmark named by its heading:

1. **Orienting header.** A [Hero](?path=/docs/components-hero-hero--docs) with `layout="split"` and `variant="neutral"`: "Collection" and the collection type, the title (`h1`), the body summary as the standfirst, the image, a facts row with the item count and the last updated date, and the hazard, country and theme tags. The count links to the content list.
   - **On this page.** A sticky [On this page nav](?path=/docs/components-navigation-on-this-page-nav--docs) under the header, with one link per section: About, In this collection and Related collections. It keeps the related collections one press away from anywhere on a long page, and its clicks show which section readers want.
2. **About this collection.** The body, collapsed with [Show more](?path=/docs/components-showmore--docs) only when it is taller than 320px.
3. **In this collection.** The [syndicated search widget](?path=/docs/components-syndicated-search--docs) scoped to the collection, newest first, with its results count and hazard, theme, type and year filters. Its total is the item count.
4. **Related collections.** A second widget with every control turned off, showing three other collections that share a hazard or theme. The section, and its link in the On this page bar, are left out when there are none.

## Short description

<Canvas of={Stories.ShortDescription} />

Most descriptions are about 150 words and fit under the threshold, so they show in full with no toggle. Readers should not have to press a button to reveal one more sentence.

## Long description

<Canvas of={Stories.LongDescription} />

A few descriptions run to several thousand characters. Collapsed, the content list stays close to the top of the page; the full text is one press away, and it opens on its own when keyboard focus enters it.

## No items yet

<Canvas of={Stories.NoItemsYet} />

When the count is zero the list is replaced with an [empty state](?path=/docs/components-empty-state--docs) that says what is missing and offers a way on. Related collections still show, because they are the most useful next step from an empty page.

## Building one

### Header

The header is a split Hero on the neutral surface. Its eyebrow holds the link to all collections and the type, its facts line holds the linked item count and the last updated date, and the tags sit below. No layout CSS of its own is needed.

```html
<header data-vf-google-analytics-region="collection-header">
  <section class="mg-hero mg-hero--split mg-hero--split-2-3 mg-hero--neutral">
    <div class="mg-hero__split-grid mg-container">
      <article class="mg-hero__content">
        <div class="mg-hero__meta">
          <span class="mg-hero__label">
            <a
              href="/collections"
              data-vf-analytics-label="Collection: all collections"
            >
              Collection
            </a>
            <span aria-hidden="true">·</span>
            Topic guide
          </span>
        </div>
        <h1 class="mg-hero__title">Wildfire risk assessment</h1>
        <div class="mg-hero__summaryText">
          <span>Discover research, assessments and …</span>
        </div>
        <div class="mg-hero__meta meta-detail">
          <span class="mg-hero__label detail">
            <a
              href="#collection-items"
              data-vf-analytics-label="Collection: item count"
            >
              36 items
            </a>
            <span aria-hidden="true">·</span>
            Last updated
            <time datetime="2026-07-10">10 July 2026</time>
          </span>
        </div>
        <div class="mg-tag-container mg-hero__tags">
          <a href="/taxonomy/term/357">Wildfire and Bushfire</a>
          <a href="/taxonomy/term/311">Climate change</a>
        </div>
      </article>
      <div class="mg-hero__media">
        <img
          class="mg-hero__media-img"
          src="…"
          alt="Aerial view of smoke rising from a fire line in a pine forest"
        />
      </div>
    </div>
  </section>
</header>
```

| Part         | Drupal source                                                  |
| ------------ | -------------------------------------------------------------- |
| Type         | `field_collection_type`                                        |
| Standfirst   | The body summary (required; about 164 characters, at most 255) |
| Image        | `field_image`                                                  |
| Item count   | Search total for the content list's filters (see below)        |
| Last updated | The node's changed date                                        |
| Tags         | `field_hazard`, `field_country`, `field_theme`, in that order  |

### On this page

Explicit mode: write the links, because collection bodies have almost no `h2`s for the script to find. Each link points at a section's `id`, so scroll-spy marks the section in view; drop the Related collections link whenever that section is not rendered.

```html
<nav
  class="mg-on-this-page-nav"
  data-mg-on-this-page-nav
  data-mg-on-this-page-nav-label="On this page"
  data-vf-google-analytics-region="on-this-page-nav"
>
  <ul class="mg-on-this-page-nav__list">
    <li class="mg-on-this-page-nav__item">
      <a
        class="mg-on-this-page-nav__link"
        href="#collection-about"
        data-vf-analytics-label="On this page: About"
      >
        About
      </a>
    </li>
    <li class="mg-on-this-page-nav__item">
      <a
        class="mg-on-this-page-nav__link"
        href="#collection-items"
        data-vf-analytics-label="On this page: In this collection"
      >
        In this collection
      </a>
    </li>
    <li class="mg-on-this-page-nav__item">
      <a
        class="mg-on-this-page-nav__link"
        href="#collection-related"
        data-vf-analytics-label="On this page: Related collections"
      >
        Related collections
      </a>
    </li>
  </ul>
</nav>
```

Place it directly in `main`, after the header, so it stays docked for the whole page. Under a sticky site header, set `--mg-on-this-page-nav-offset` to that header's height.

The item count stays out of the link text. It is already in the header and in the list's own results line, it would make the bar shift as the number arrives, and a link name that changes with the count is harder to compare in analytics.

### About

The body uses the vanilla Show more markup with the threshold attribute, so content under 320px stays open and the toggle is hidden:

```html
<section aria-labelledby="collection-about">
  <h2 id="collection-about">About this collection</h2>
  <div id="collection-body" class="mg-content">…body…</div>
  <button
    type="button"
    class="mg-button mg-button-primary mg-show-more--button"
    data-mg-show-more="true"
    data-mg-show-more-target="#collection-body"
    data-mg-show-more-threshold="320"
    data-mg-show-more-label-collapsed="Show more"
    data-mg-show-more-label-open="Show less"
  >
    Show more
  </button>
</section>
```

### Content list

Scope the widget with `customFilters`, not `defaultFilters`. Default filters become removable chips and are written to the URL hash, so a reader could remove the collection scope and see the whole site. Custom filters are invisible and fixed.

```js
{
  customFilters: ['field_collections:101264', '_language:en'],
  defaultFilters: [],
  defaultSort: 'newest',
  resultsPerPage: 10,
  showResultsCount: true,
  visibleFilters: { field_domain_access: false, field_country_region: false, _language: false },
}
```

`visibleFilters` has no data attribute; a Drupal block wrapper merges it into the config, as it already does for `customFilters`.

### Item count

The count in the header must equal the list's total. The example sends the widget's own query with `size: 0` and the same `customFilters`, so the status filter and scope match exactly. In Drupal, run that query on the server and cache it with the node, so the number is in the HTML and does not shift the layout when it arrives. The hidden Views count (`undrr_custom_views_pre_view()`) is a fallback if that is not ready.

### Related collections

```js
{
  customFilters: [
    'type:collections',
    'field_hazard:(357) OR field_theme:(311 OR 1176 OR 333)',
    'NOT nid:101264',
    '_language:en',
  ],
  defaultFilters: [],
  resultsPerPage: 3,
  displayMode: 'card',
  gridColumns: 3,
  showSearchBox: false,
  showResultsCount: false,
  showFacets: false,
  showActiveFilters: false,
  showPager: false,
  enableHashSync: false,
}
```

Each custom filter is a separate `query_string` clause, so a clause can stand alone as an exclusion: `NOT nid:101264` (or `-nid:101264`) removes the current collection. Checked against a local copy of the PreventionWeb index: without it, the current collection came back as its own first match.

Only one widget on a page may sync with the URL hash; leave it to the content list.

### Analytics

The shared UNDRR analytics script ([google_analytics_enhancements.js](https://assets.undrr.org/analytics/v1.0.0/google_analytics_enhancements.js)) reports each click with the innermost `data-vf-google-analytics-region` around it, and uses `data-vf-analytics-label` as the click's name when present. The labels are fixed English strings with no counts, as on Share this and Cite this, so reports do not split by language or by number.

| Element             | Region                                                                                    | Label                                                                                          |
| ------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Header              | `collection-header`                                                                       | "Collection: all collections" (the Collection link), "Collection: item count" (the count)      |
| On this page bar    | `on-this-page-nav`                                                                        | "On this page: About", "On this page: In this collection", "On this page: Related collections" |
| About section       | `collection-about`                                                                        | "Collection: show more or less" (the toggle)                                                   |
| In this collection  | `collection-content`; the widget uses `collection-content-form`, `-results` and `-facets` | "Collection: browse all collections" (empty state)                                             |
| Related collections | `collection-related`; the widget uses `collection-related-results`                        | Card titles                                                                                    |

Because the innermost region wins, a region on the section never reaches clicks inside a search widget, which reports its own. Set each widget's `analyticsRegionPrefix` (`data-analytics-region-prefix` on a hydrated container) to the section's region so the two widgets do not both report `undrr-search-results`. Tag links keep their term names as labels: the term is the useful thing to count.

## Accessibility

- One `h1`, then an `h2` per section; the empty state's title is an `h3` under its section.
- Each section is a `section` named by its heading with `aria-labelledby`, so screen reader users can move between them as regions.
- The count is link text ("36 items"), read in full, and goes to the list. The widget announces its own total in a live region when results load.
- The middle dots between facts are hidden from assistive technology.
- The On this page bar is a `nav` named "On this page"; the section in view carries `aria-current="true"`, and following a link moves focus to that section.
- Show more clips the body visually only; screen readers read it in full. See [Show more](?path=/docs/components-showmore--docs#accessibility).

## Design decisions

**No tabs.** Splitting about, content and related into tabs hides the content list, which is what most readers came for, and makes the count link point at a tab that may not be showing.

**A sticky On this page bar.** The content list can run to many pages of results, which puts related collections far down the page. The bar keeps them one press away, and its clicks record which section readers were looking for.

**"In this collection", not "Latest additions".** The list is sorted by each item's publication date, not by when it was added to the collection, so "latest additions" would claim something the index cannot show.

**A neutral Hero for the header.** A coloured band made the page read as a campaign rather than a reference page, and the hazard pages it follows sit on white. The header is still a Hero rather than page-specific CSS, so the eyebrow, facts line and tags it needed are now Hero options any page can use.

**Body summary as standfirst.** It is required on collections and already written as a one-sentence pitch, so the header can carry it without new editorial work.

## Reuse

The same structure could serve hazard and theme pages: scope the list with `field_hazard:<tid>` or `field_theme:<tid>` instead of `field_collections:<nid>`, and relate collections on the same term. This is not built or tested yet.

## Still to test

- Is 320px the right threshold for PreventionWeb's descriptions, and should the collapsed height rise from 200px to show more of a long one?
- Should related collections match on hazard only? Broad themes such as Climate change make the theme match loose.
- Translated collection pages: the language filter is fixed to the page language, which hides items with no translation.
