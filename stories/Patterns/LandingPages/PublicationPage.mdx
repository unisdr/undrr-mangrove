## Report branding within a site theme

A publication can have its own visual identity while its host site keeps navigation, controls and reading conventions consistent. Start with the selected site theme and component props, then supported custom properties. Add a narrowly scoped consumer rule only for a requirement those controls do not cover.

These paired examples use the same illustrative content, the native Hero with primary and secondary editorial CTAs on a dark surface, and `StatsCard variant="compact"`. The figures describe the example page; they are not research findings. These canvases isolate each report in its own iframe, so its main landmark, heading hierarchy and local section links belong to that example rather than the surrounding documentation. The paired examples show the report body. The local overview action explicitly uses the supported `button.target="_self"` field: Storybook sets a parent navigation target inside iframe canvases, and an in-page action must stay in its own document. The existing full-page reference above supplies the surrounding site chrome; use the host site's approved header, navigation and footer in production.

The property rule targets the actual Hero element because a value declared there can override an inherited wrapper value. Fetch a component's `customProperties` records and theme `tokens.json` for the supported scope, defaults and value formats. `--mg-color-hero` takes channels; use `rgb()` at a colour use site, not around the value assigned here. Avoid copying these rules globally or replacing the site's typography roles with font-family literals.

### Keep shared behaviour with the component

Do not replace Hero's grid, breakpoints, copy padding, title size, `max-width` or protective scrim independently: those rules work together across long titles and narrow screens. The shared width property above is the supported coordination point. A publication that requires a different content hierarchy should choose a different composition before overriding component geometry.

Keep secondary CTA hover, visited and focus rules together. A generic report rule such as `.report a { color: … }`, or a rule removing outlines, can defeat the dark-surface treatment. Changing a surface or foreground requires checking their contrast together in every target theme and state. Do not use the orange non-text accent as a text background. Do not reduce statistics by overriding only the numeral size or child margins; use the compact variant.

These examples add no component props, theme tokens, animation or Gutenberg block. The scoped stylesheet is consumer-owned CSS and needs explicit host integration. Gutenberg serialization and an editor round trip are not established by a Storybook canvas; map the composition to supported blocks using the page-building guide and verify the published result.

For release review, compare both canvases across all five themes at narrow and wide widths, keyboard focus, hover, long copy, RTL and forced colours. A successful render or automated scan does not establish screen-reader usability, browser parity or a Gutenberg round trip. Keep the actual checked conditions and remaining limitations in the integration handoff.
