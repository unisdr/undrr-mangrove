# Content teaser

**Experimental, for review in [#1381](https://github.com/unisdr/undrr-mangrove/issues/1381).** These patterns cover all 15 node bundles selected by the inspected Drupal search index. They share the horizontal `teaser_3_9` layout, content hierarchy and omission rules, rather than introducing 15 visual card variants. Drupal is one source; normalised data also supports other publishing systems.

See the [source audit](https://github.com/unisdr/undrr-mangrove/blob/main/docs/CONTENT-TEASER-DRUPAL-AUDIT.md) for the inspected revision, exact field mappings, hidden fields and deliberate departures. People use a conservative title/summary baseline because their configured teaser does not use Display Suite.

## When to use

Use these patterns for structured search results, related content and listings. Existing syndicated search still renders indexed Drupal HTML. Production adoption needs verified adapters, domain policy, parity, server output and performance acceptance. This draft changes no Elasticsearch queries or Drupal files.

All metadata is optional. The title and resolved destination are always required. Fields absent from a pattern's hierarchy are omitted even if present on an upstream record. The caller selects labels and supplies translated text; Mangrove does not infer a type label or taxonomy visibility from the theme.

## Shared content contract

Pass one `content` record and a contextual `headingLevel` (default 3, supported 2–6). All strings are plain text, including summaries, attribution and metadata. HTML is escaped. Supply localised display strings and HTML-valid machine-readable dates; no browser-locale or client-clock decisions occur during rendering.

| Field                      | Meaning                                                                                                                                                                                                                                                                                                                                       |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`, `title`, `link`    | Required supported normalised type, non-empty full title and resolved HTTP(S) or root-relative destination. Invalid required inputs throw. Relative URLs require confirmed availability on the consuming site.                                                                                                                                |
| `shortTitle`               | Optional news editorial title, falling back to the full title. Other patterns use `title`.                                                                                                                                                                                                                                                    |
| `image: { src, alt }`      | Optional image on the patterns listed above. Supply meaningful alt text or an explicit empty string when redundant with the title. No image means no frame or reserved column. Cover and logo URLs are preserved; no derived crop is invented.                                                                                                |
| `typeLabel`, `labels`      | Optional translated type label and ordered labels. Labels accept strings or `{ label, link? }`. Resolved links retain native keyboard behaviour; unsupported link schemes degrade to text. Duplicate label/destination pairs are omitted. Select relevant taxonomy values upstream, including domain visibility.                              |
| `summary`                  | Optional concise editorial plain text. No automatic truncation, clamping or HTML interpretation.                                                                                                                                                                                                                                              |
| `published`                | `{ dateTime, text, label? }`: news release date, publication/blog date or commitment publication date. It is not used for collections, vacancies or events.                                                                                                                                                                                   |
| `sources`, `authors`       | Ordered arrays of organisation names or author names. Rendered as semantic lists without fabricated links. | `location`                 | Resource location, vacancy location or organisation country. String or `{ label, link? }`; only supply a link where appropriate (Drupal links organisation country). Events use `event.location`.                                                                                                                                             |

### Distinct dates

A date value is `{ dateTime, text, label? }`, with a valid HTML year/date/timestamp and a localised equivalent. An optional translated `label` precedes the native `time` element. There are separate inputs for separate meanings:

- `event: { start, end?, timeZone?, location?, label? }` uses date values for occurrence dates. Start is required to display the range; an end alone is omitted. Provide full dates where needed to disambiguate multi-day ranges, and explicit time zones for timed events.
- `deadline` is a date value for vacancy closing dates. Include a localised label such as Closing date. Publication time is never substituted.
- `freshness: { kind: 'updated' | 'created', date }` is explicit collection freshness. The adapter supplies the newest linked content date, or creation date when no linked content exists, with Last updated/Created as the date label. No fallback to `published` occurs in the component.
- `session: { bucket?, schedule?, exhibitions?, room?, format? }` retains conference-specific metadata. Schedule and exhibitions are arrays of `{ start, end?, timeZone?, label? }`, so multiple ranges are preserved. Label exhibition ranges to distinguish them. Resolve time zone precedence (session, parent conference, fallback) upstream; the renderer does not reconstruct it. Supply the resolved room hierarchy and format text, without leaking Drupal taxonomy IDs into the UI.

This proposal reuses `title`, `image`, `summary`, `labels` and `link` from [#885](https://github.com/unisdr/undrr-mangrove/pull/885). Metadata additions are provisional, not a second canonical schema. The summary is a plain-text subset of the schema's HTML-capable field. Reconcile these extensions with [#891](https://github.com/unisdr/undrr-mangrove/pull/891) before graduation; this draft does not rename the legacy card APIs.

## Omission and responsive behaviour

No metadata or image creates no empty container. Resource/event images and hidden people profile fields remain omitted even if supplied. Minimum records still have useful native heading links. The shared horizontal layout places configured media beside text on wider screens, then stacks it at narrow widths; media-free records use the whole reading width. Themes own the shared horizontal book-card surfaces.

Use `ul.mg-content-teaser-list` with one teaser per `li` for a responsive reading list. The class preserves list semantics, spaces rows and removes duplicate card bottom margins. Choose a suitable reading width rather than forcing these detailed teasers into a narrow card gallery. Covers are not forced into equal-height stages.

## Drupal adapter and link boundary

Map source fields before rendering. Do not pass entity objects or Display Suite HTML. The audit records each bundle's visible fields, summary formatters and conditional labels. Confirm actual indexed fields and active rendered teasers before adopting an adapter, especially collection freshness, multiple source organisations, conference schedules and hidden profile fields.

`link` and optional metadata destinations arrive already resolved. Proposed policy keeps readers on the current site when content is published there, then follows an agreed deterministic fallback. Domain aliases, fallback order, authoritative external URLs and ownership remain open. Do not infer authority from `field_domain_access[0]`, array order, source attribution or a theme name.

Publication ARISE/IRP/UNDRR taxonomy visibility is selected upstream; linked labels preserve the supplied destination. Source organisation and author names remain unlinked as configured. Search highlighting needs a reviewed structured contract before integration; raw HTML is not accepted by this pattern.

## Accessibility and server output

The title is a native anchor within a semantic heading and article. Metadata links are separate siblings above the shared stretched-link overlay, with permanent underlines and dual-band focus rings. They do not nest inside the title anchor or trigger its destination. Sources/authors and result lists preserve native list semantics. Shared focus, hover, reduced-motion and forced-colour behaviour apply; there is no extra client interaction or new animation. Content wraps without fixed text heights. RTL follows document direction and shared card rules.

Static React rendering includes complete titles, destinations and metadata. Native links remain usable without JavaScript. Drupal can implement the same semantic class contract in Twig without adding a JavaScript runtime. This draft tests static React output, not a Drupal SSR integration. An interactive React consumer must use its matching SSR/hydration pipeline rather than hydrating `renderToStaticMarkup` output. Non-JavaScript output must remain usable for people as well as crawlers.

## CSS and JavaScript references

- React: `ContentTeaser.jsx`, exported through the package root and `components/ContentTeaser.js`, including `DRUPAL_TEASER_TYPES`.
- Pattern selection: `contentTeaserPatterns.js` owns media eligibility and before/after-title field order.
- Styles: `content-teaser.scss` adds wrapping, metadata rhythm, list semantics, independent metadata-link focus and logo framing. It uses shared `--mg-card-*`, `--mg-card-publication-*` and spacing tokens; no new colour or surface defaults.
- No hydration registration: the complete teaser markup needs no client initialisation.

## Review gates before production adoption

Approve the canonical content contract and domain policy, verify live source adapters and representative multilingual parity fixtures, then test actual server/non-JavaScript output and measurable payload/render performance. Include conditional taxonomy, missing media, dates/time zones, attribution, native link destinations, keyboard access and all five themes. Keep indexed HTML until those criteria are met. Taxonomy result patterns, index freshness, prompt unpublishing, federation and Views replacement remain separate work.
