# Article story

> **Note:** Reference design for [undrr/web-backlog#3060](https://gitlab.com/undrr/web-backlog/-/work_items/3060). Review against the [component checklist](https://github.com/unisdr/undrr-mangrove/blob/main/docs/REVIEW-CHECKLIST.md).

A news or event article page: headline, header image, social share, reading
body, related content, editors' recommendations, taxonomy tags and page
feedback — the full page, not just the header. The ticket compares
undrr.org's current story pages against news.un.org, UNESCO and UNDP, which
run a large image above the headline rather than a small one beside it. This
pattern makes that comparison directly testable, and separates two questions
the ticket raises that are easy to conflate:

- **How prominent is the header image?** `imageProminence` — `large` bleeds
  it full width; `compact` keeps it inside the reading column.
- **Is the header image the same one used for teasers and social cards?**
  `heroImage` — `main` reuses that image, `alternate` shows a different one
  in that position, `none` drops it from the article page entirely without
  affecting what a teaser card or an Open Graph tag uses.

The content is a real undrr.org story — [Towards knowledge, action and resolve
to address non-economic losses in the Pacific Indigenous Communities Nadi,
Fiji](https://www.undrr.org/news/towards-knowledge-action-and-resolve-address-non-economic-losses-pacific-indigenous) —
so reviewers are judging the layout against an actual case rather than a
synthetic one. The live page returns a bot-check 403 to automated fetches, so
this was built from a saved copy of the page. The headline, date, source
line, two-sentence summary, editors' recommendations, taxonomy tags
and both images (including the article's second inline photo, used here for
the `alternate` `heroImage` state) are reproduced as published. The reading
body is placeholder (lorem ipsum) text, not the article — sized to roughly
the same length, with inline links in the same places a real body would carry
them, so the `mg-reading` column can be judged at a realistic length without
reproducing the article's text.

## Split hero (text and image side by side)

<Canvas of={Stories.SplitHero} />

A third `imageProminence`, added as a "left field" comparison point:
education.gouv.fr runs its news pages with a two-column hero on a tinted
band — headline/lede/byline in one column, a smaller image beside it, rather
than a large image above or below the text. This reuses the shipped `Hero`
component's `layout="split"` (already used by `ContentHub`) rather than
introducing a new header treatment: `split="2/3"` keeps the text column
dominant, and `data[0].media` is omitted when `heroImage` is `"none"`, so
`Hero` falls back to a text-only band gracefully. Known gap: `Hero` has no
caption slot, so this variant loses the photo credit the other three show.

Building this surfaced real bugs in `Hero` itself — a title measure that
wrapped headlines too aggressively, a hardcoded width instead of the shared
`mg-container` utility, and a forced padding — fixed at the source rather
than patched around here. See `Hero`'s own changelog (v1.6.4) for detail.

## Share lives in the margin rail

`ShareButtons` sits in the same rail as "On this page", in every variant —
not beside the photo. An earlier version anchored share to the image, but a
full-bleed image has no natural "beside" for it to sit in, and a rail
placement doesn't need a separate fallback for `heroImage: "none"`.

## Building one

The page composes existing, shipped pieces rather than introducing new ones:
`mg-container-full-width` for the header image's bleed, `mg-reading`/
`mg-reading__article` for the body and `TableOfContents`, `VerticalCard` in an
`mg-grid` for related content, `ShareButtons` in the margin rail,
`mg-tag-container` for the taxonomy links under "Explore further",
`Imagecaption` for the header image's caption and credit, and
`UserFeedback` for the "Is this page useful?" prompt and report-an-issue link
— the same building blocks `ContentHub` uses, plus the ones a full article
page needs that a hub page doesn't. The body also scatters `QuoteHighlight`,
`HighlightBox` and `EmbedContainer` as a rough positioning experiment — see
"Still to test". What is new is demonstration-only: the `mg-demo-article-*`
classes that size the header image and lay out the rail, loaded only with
these stories. "Editors' recommendations" is plain markup — there is no
shipped component for it yet.

## Design decisions

**`imageProminence` and `heroImage` are independent props.** Collapsing them
into one variant (e.g. "big hero" vs "no hero") would hide that a small
image can still be the wrong one, and a full-bleed image can still be the
right one. Keeping them separate lets each be decided on its own evidence.

**No real image-compression work here.** The ticket also asks to revisit
Drupal's compression settings once a layout is chosen — that depends on
which `imageProminence` ships, so it is out of scope until this reference
design is reviewed.

## Still to test

- Which `imageProminence` reviewers actually prefer once seen next to the
  comparison screenshots in the ticket, or whether both ship as editor
  choices.
- Whether `heroImage: "none"` needs a fallback treatment (a coloured band, a
  pull quote) rather than going straight from identity chrome to the
  headline.
- How this composes with `HubHeader` for an article that also belongs to a
  content hub.
- The Drupal side: whether `heroImage` maps to a real "use main image on this
  page" toggle on the content type, and what that does to existing content.

## Changelog

- **1.0** — 2026-09-10: Initial reference design for the news/event article
  layout — large and compact image variants, and a `heroImage` toggle
  decoupling the header image from the teaser/social image, in English and
  Arabic. ([undrr/web-backlog#3060](https://gitlab.com/undrr/web-backlog/-/work_items/3060))
  Current state and rationale are covered in the sections above; this log
  only tracks what changed and when.
  - Replaced synthetic content with the real undrr.org story, and the pull
    quote above the header image with `ShareButtons`.
  - Design review against the four reference sites: dropped centering the
    headline/lede/byline over the image in favour of left alignment, and
    unified `ShareButtons` into the margin rail in every variant. Scattered
    `QuoteHighlight`, `HighlightBox` and `EmbedContainer` through the body as
    a positioning experiment (English only).
  - Added the `split` `imageProminence` variant, and fixed the `Hero` bugs it
    surfaced at the source (see "Split hero" above and `Hero`'s own
    changelog).
  - Audited the demo-only CSS against `mg-grid`: none of it fits `mg-grid`'s
    equal-fraction columns; the rail/article split and the caption/credit row
    are both asymmetric shapes it can't express.
  - Replaced the caption/credit row entirely with the shared `Imagecaption`
    component (`stories/Molecules/ImageCaption`), fixing real bugs in it at
    the source rather than continuing to hand-roll a demo-only equivalent:
    `caption`/`credit` were stringly-typed (`"true"`/`"false"`) with a dead
    no-op variant-class system behind them, and `Imagecaption` passed an
    undefined `name` variable into `Imagecredit`, which doesn't even accept
    that prop. Now real booleans, no dead code, and one less demo-only class
    family (`mg-demo-article-caption`/`-credit`/`-media-foot` are gone).
