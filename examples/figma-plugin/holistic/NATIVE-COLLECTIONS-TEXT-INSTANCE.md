# Plain TEXT and source INSTANCE partition candidate

This opt-in second profile is a guarded mechanics candidate. It retains the original FRAME-only version1 contract. It does not make the full source catalogue importable, migrate canonical variables/styles/consumers, publish a library or prove native text rendering.

## Source and ownership contract

The declaration is `nativeCollections:{version:2,profile:"plain-text-instances-v1",planId,primary,collections}`. It uses a new plan identity and exact version2 collection and scene ledgers. Shared pure ledger constructors emit `{version:2,profile,planId,collectionId}` for collections and `{version:2,profile,planId}` for scene nodes. The original version1 ledger shapes remain unchanged. Plan version/profile properties are immutable. Normal source variable/style IDs and name-based alias syntax remain intact; there is no equality-based deduplication or collection rebucketing.

The profile accepts a complete document and all modes, with pruning disabled. Every role belongs to exactly one declared collection. All original typed values, alias graphs, existing native ownership and retained occupancy participate in preflight. Existing collection names cannot authorize adoption. Requested and retained native variables must fit the unchanged 5,000-variable capacity per collection.

Version2 adds a deliberately narrow topology fence: each variable is literal in every source mode, or aliases exactly the same target in every source mode. A varying alias target or alias/literal mixture refuses. This prevents independent collection mode selections from reaching an alias cycle that paired-brand resolution did not visit. It is a restricted slice profile. The actual normal foundation and source93 have mode-varying aliases, so neither whole catalogue passes this restriction. Full integration needs separately reviewed union-DAG validation and propagated reachable native role/font constraints.

Only FRAME, ordinary whole logical TEXT and genuine INSTANCE anatomy is accepted. Variant roots remain FRAME recipes that the existing builder materializes as native COMPONENT masters. Family names, variant selectors, property tuples, sibling anatomy IDs and dependency graphs remain strict. INSTANCE selectors must identify exactly one source variant; TEXT-only overrides must exist in that selected master. Dependency cycles refuse before asset creation. Differing authored defaults cannot share one set-level text property name. Actual nested source instances remain linked and editable; the candidate does not detach them or draw an imitation.

Plain styles require exact font-family STRING and font-size FLOAT bindings. All source modes must agree with their declared templates. Unbound style attributes must remain identical in every mode: native face style, line height, letter spacing, NONE decoration and AUTO wrapping. Only bound family and size can vary. Font sizes are positive. Explicit source axis settings, paragraph indentation/spacing, textCase, rich runs, links/decoration offsets, effects, gradients, masks, SVG, images, positioning, context appearance overrides and review specimens are refused in this first profile. No forbidden fields are deleted from a real source component to claim coverage.

## Font and asynchronous boundaries

The importer loads all declared source style faces before collection/variable writes, using a private validated source copy and exact target/page guards around awaits. Prior invalid native literal font values can still be repaired from valid source. Variable import is a separate journaled phase and returns no style import.

The builder resolves actual qualified native font-family and size roles through every source mode, loads those faces plus source faces, existing style faces and affected TEXT, and restores Inter preparation before a fresh TEXT is created. A transition in any declared collection prepares affected text; a primary-collection check alone is insufficient. The first profile refuses unresolved named font axes before permanent style/scene writes. It does not silently substitute an axis value or invoke an unjournaled font-default probe.

Exact relevant local style identities/kinds, current native roles, scene TEXT/property fields and genuine instance-to-main identities are refreshed after awaited preparation and before style/scene phases. Existing same-name unowned styles refuse. Any style import error prevents the whole partition scene closure from being constructed. Setter failures can still leave reported partial style writes; this is not a transaction or a rollback guarantee. Edits after the last guard remain an ordinary application concurrency boundary.

## Offline evidence and transport gate

The dedicated pure mock uses two source collections with independent native mode IDs, cross-collection family/size/paint/width aliases, a plain label master and a genuine wrapper dependency. It checks immutable version/profile, exact ledgers, strict source styles/properties/selectors, all-mode native size/family values, a malicious mixed-mode alias graph and staged source refusals.

The dedicated actual importer/builder mock runs all five brands, checks import reports, actual plain style binding UUID ownership, source logical characters/set defaults, genuine nested main IDs, actual owning consumer property edits and independently selected foundation-MCR/helper-DELTA modes. Two zero-create builds and imports compare nonempty recorded geometry, characters, property definitions/references/overrides, native modes, styles and variables. The instance display fixture is explicitly bounded to the documented owning character property reference. It is a model of native displayed inheritance, not native font metrics or a substitute for actual native evidence.

Missing source/native fonts, unresolved named axes and changed TEXT ownership during awaited font preparation refuse before permanent style/scene construction. These observations do not prove glyph shape, font-byte equivalence, wrapping, arbitrary consumer state switching, publication or ordinary desktop behavior.

The first early actual production v2 compile measured 38,688 import characters and 55,026 build characters, before later builder fences. The build exceeded the unchanged 50,000-character ceiling and was refused. That historical early measurement is not the final candidate size. No v2 native connector execution or native rendering acceptance is claimed. Further compiler specialization must retain the actual required guards, complete source closure and exact version1/absent-profile behavior; it is a separate reviewed implementation task.

The final held candidate measures 39,090 import characters and 59,962 build characters. The complete two-family build still refuses the unchanged ceiling. An external binding-aware AST specialization experiment retained validation and saved only 289 characters, leaving 59,673; it was not adopted into production. The importer size alone does not establish scene rendering acceptance.

Independent peer checks passed the held all-brand importer and builder fixtures. Fresh ordinary kit and maintenance regressions also passed. The originally executed version1 import (29,907 characters) and build (46,791 characters), and the ordinary Button whole/scoped and rich-overflow payloads, retain exact byte parity. These checks protect existing routes; they do not establish native acceptance of version2.
