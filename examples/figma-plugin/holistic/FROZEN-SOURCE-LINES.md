# Finite source line copy ownership

This opt-in capability protects authored line copy when a finite source layout cannot flow as one native TEXT node. Its first consumer is the actual desktop ArticleStory paragraph around the secondary float. The source has294 characters and four measured lines, with offsets0,68,135,205,294. The first three line allocations are485.40625px; the last is722px. This capability does not calculate those widths, shape glyphs or support changed paragraph text.

`mgFrozenSourceLine.sourcePlans(records)` is pure. Each record supplies the exact builder `key`, component variant `ownerKey` and TEXT `spec`. An opted-in spec includes `sourceLine` with exactly `paragraphId`, `paragraphCharacters`, `start`, `end`, `lineIndex`, `lineCount`. The source TEXT must equal that paragraph slice. All lines for a paragraph/owner must be present, contiguous, unique and concatenate exactly to the whole paragraph. The TEXT uses HUG/HUG within a separate fixed source line allocation. Whole-string properties, character bindings and reset/alternative resize profiles are refused. Ordinary plain and rich TEXT without this field retain their existing edit contract.

`await mgFrozenSourceLine.preflight(plans, adapter)` performs reads only. The adapter provides `mainByKey(key)` as all matching indexed main candidates, `identity(node)` using shared identity, `instances` as actual loaded current-page INSTANCE nodes, and `mainForInstance(instance)` using the documented actual main-component resolver. Main candidates are empty for a fresh component or contain exactly one COMPONENT. Duplicate main identities refuse. A collapsed index that has discarded duplicates must not pretend to satisfy that candidate contract.

Existing main TEXT is resolved under its actual nearest COMPONENT owner. A linked consumer TEXT is resolved only when its actual main-component ID matches the indexed main and that main has the expected shared identity. Same names or source keys on unrelated component copies are not sufficient ownership. Nested instance targets are checked using their own actual main relationship. Changed, missing or duplicated owned line copy refuses with `Frozen source line preflight: reflow-needed`. The receipt lists checked main and instance TEXT IDs. Earlier line copy is rechecked after later awaited main relationship reads. The helper writes no workflow fields to Figma nodes.

The integration must validate complete source groups across the selected dependency closure before fonts or assets are prepared. Run native preflight before font preparation and again after awaited preparation immediately before the first permanent style/image/scene phase, with freshly collected current-page candidate nodes. These reads do not make a transaction against new user edits after the last guard or during style/scene writes. Further phases retain their existing stale ownership and partial-failure gates. The existing font preparation journal remains separate: temporary font probes are real writes, and their receipt must not be described as mutation-free source preflight. Late style-import or stale-source failures retain the existing partial asset failure reporting, without claiming rollback.

The initial integration checks indexed mains and the supplied loaded current-page linked copies. It does not inspect unloaded pages, another file's consumers or published remote instances. Those remain explicit gates. Native font bytes, glyph metrics, text baselines and raster equivalence remain open. This is a line copy freeze, not a promise that arbitrary manual typography edits retain the measured source layout.

Shared integration is implemented and independently reviewed. The builder validates complete source groups in the selected dependency closure before font preparation, then reads fresh current-page ownership again immediately before style import. It refuses orphan managed lines when the expected main is absent. The full plugin enumerates the helper. The scoped compiler validates complete groups before rich source validation and includes the helper only for selected profiles using `sourceLine`. Exact validated key/copy metadata is projected out of the strict rich DTO without relaxing its allowed fields or style/run checks. The standalone token importer does not perform this component-line validation.

The actual builder integration passes all five modes, two zero-create repeats, supported ordinary consumer edits and compiled plain-line repeats. Source/main/linked copy changes, orphan lines and changes or duplicate owners introduced during awaited font preparation refuse before permanent style/image/scene writes. The ordinary instance fixture models displayed inheritance through the actual referenced property. The dedicated actual article exclusion harness also passes rich lines with the source HTTPS link. With the feature absent, normal compiler samples remain byte-exact at38,608 and41,407 bytes. An independent small rich frozen connector fixture validates correctly but exceeds the unchanged50 KB transport ceiling at68,541 bytes. Full rich native execution, font pixels, reflow, publication and cross-file consumers remain open.

The isolated helper test covers complete source groups, malformed/overlapping/missing line metadata, property/reset conflicts, exact main and linked copy refusal, duplicate identities, nested ancestor targets, unrelated same-key copies, fresh components, native proxy handles and source edits during an awaited ownership read. Before/after node fields are compared, including absence of new workflow fields. It is a model of documented ownership shapes, not native Figma acceptance.
