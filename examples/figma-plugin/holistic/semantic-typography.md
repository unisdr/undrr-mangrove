# Semantic typography source recipes

This initial source cohort implements six contract families and 96 finite specimens from 480 of the 660 measured source cases. It is not complete BaseTypography coverage or native Figma acceptance. The source archive retains all 660 cases across five brands, English, Arabic and Japanese at 390 and 1164 pixels.

| Family                    | Finite specimens | Actual source contract                      |
| ------------------------- | ---------------: | ------------------------------------------- |
| semantic-heading-specimen |                6 | Whole HeadingDemo caller with H1 through H6 |
| semantic-paragraph        |               60 | Default P and nine supported size utilities |
| semantic-copy-separators  |               12 | Small and solid Hr callers                  |
| semantic-description-list |                6 | Whole authored dt/dd list                   |
| semantic-figcaption       |                6 | Bundled image, caption and owning figure    |
| semantic-inline-emphasis  |                6 | Authored Mark caller                        |

The factory `buildSemanticTypographyRecipes({root,modes,variables,styles})` stages typed helpers and text styles on cloned inputs and publishes only after complete source, foundation and identity validation. Source inputs, the lossless archive, capture driver, active font bodies and media are pinned. Module and caller correspondence comes from the recorded source inputs; these are finite source specimens, not a generic HTML renderer or a new package export.

Source boxes and ancestor relationships remain explicit. Dimensions become literals only when every measured brand has exactly the same value. Mode-dependent allocations and signed START offsets use typed helpers. Font, size and text-color aliases follow guarded authored declarations. Mark's UA black ink and LightYellow background are literal source colors, not aliases selected by equal current RGB values. Actual source opacity is one. Hr is a measured two-pixel solid rule, not a dashed or UA-marker substitute.

The Latin and Japanese requested family is Roboto. Arabic H1 through H3 uses Noto Kufi Arabic; other Arabic copy uses Noto Sans Arabic. Arabic source letter spacing is zero. The selected published Bold face for requested weight 600 remains a provisional named-font mapping; native font bytes, variation defaults, glyphs and pixels are not accepted here. Roboto's pinned cmap does not establish Japanese glyph coverage, so browser/platform fallback remains unresolved. Read-only native Noto Sans Arabic availability confirms a family, not matching bytes, axes or bidi rendering.

Small is actually 12.8 pixels at both measured widths: Normalize's 80% declaration wins in the compiled source cascade. Its inherited 24-pixel line height is preserved as PIXELS. This cohort does not change CSS or reinterpret that line height as a relative Small rule. P utilities retain their actual narrow/wide token mappings. Source AUTO, BALANCE and PRETTY wrapping are recorded, but arbitrary edited wrapping is not proven.

The figcaption keeps the actual bundled 320 by 44 JPEG and its 8.75-pixel image-owner bottom padding and measured inline gap. Its media licence is unverified. Mark retains its five-pixel added background extent through the measured padding and actual logical editable text; edited highlight fitting remains a separate gate.

Every supported text property has a stable treatment, locale, viewport and anatomy namespace. Plain main text is authored source: a direct main-node copy edit is restored on rebuild. Owning consumer TEXT-property edits are retained. No whole-string property replaces mixed formatting in this initial phase because these selected contracts contain whole plain logical text.

The dedicated offline harness imports through the actual importer with empty error lists, checks all five source modes, authored defaults, font profiles, paints, padding, fixed owning boxes and exact original image hashes. It checks authored restoration, all supported owning consumer edits, two zero-create repeats with nonempty geometry snapshots and a stable single-image cache. Source/font artifacts, malformed or missing typed foundations, alias cycles, foreign identities, wrong style kinds and missing fonts refuse without caller publication or permanent scene/style/image writes as applicable. These mocks do not simulate native glyph layout, bidi, clipping or browser raster matching.

## Required followon contracts

The measured remaining 36 finite specimens are named requirements: Cite (6), Quotation (6), OL/UL (12), and mixed Code/Abbr (12). They are not implemented or counted as covered by these six families. Their actual source needs include logical mixed inline text, native/browser font synthesis or fallback proof, UA quote and list-marker flow, inline code background/padding and inherited line-box behavior. Separate source-backed capability work must preserve whole logical editable paragraphs and supported run ownership. Independent fragment edits, invented markers, quote glyph substitutions and guessed font fallbacks would not satisfy these contracts.

Native fonts, source/native raster, edited reflow, RTL/CJK line layout, consumer publication and complete semantic-contract acceptance remain open. The source packet is an experimental source-only artifact; it does not update the canonical maintenance cohort.
