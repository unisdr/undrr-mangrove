# Native collection plan v1

This opt-in planner is an initial capacity architecture primitive. It does not make the source catalogue native-importable. The complete source packet remains non-importable, and canonical maintenance, existing collections and consumers are unchanged.

`kit-native-collections.js` implements pure whole-document source partition validation, pure native-snapshot preflight, collection-qualified native value resolution and explicit node mode application. Importer, builder and compiler wiring is owned separately. Source/native transport, fonts, full component closure, rendered pixels and publication remain separate checks.

## Source declaration

The existing flat variable IDs/names and alias-name syntax remain unchanged. `nativeCollections` has exactly `version:1`, a stable `planId`, `primary`, and `collections` containing `{id,name,variableIds}`. Every document variable belongs to exactly one declared collection. Names and IDs are globally unique. The primary collection name equals `doc.collection`. Each collection has at most 5,000 requested variables; actual native occupancy is also checked independently.

All original source modes and values are validated before selection. V1 accepts the whole document only: omitted `selectedClosure`, or an array containing exactly all source variable IDs. It does not perform family/style/recipe/review dependency extraction. Those runtime consumers require the adapter and existing source validators. Review dimensions such as specimen `instanceWidth` are runtime allocations, not ignorable evidence metadata. Advanced profile support and declaration on the maintenance path must be explicitly rejected by integration until separately implemented.

`mgNativeCollectionsSourcePlan(doc, selectedClosure)` returns Maps `sourceById`, `sourceByName`, `ownerBySourceId` (variable ID to logical collection ID), `collectionById`, `counts`, `modeById`, plus `planId`, `primary` and a pure `resolveSource`. FLOAT values must be finite, COLOR components must be finite within zero to one, and STRING/BOOLEAN must have their native types. Aliases are exact same-type source references without extra fields or cycles.

`mgNativeCollectionsSourceCapability(doc)` is the separate first-profile fence. It returns the source plan after requiring empty actual text/effect arrays, components version1, unique named component-set families and named variants with consistent string properties and unique property tuples, no declared family review and FRAME-only trees with unique sibling anatomy IDs. Tree fields are exactly id/type/name/layout/bindings/children/fill/stroke/visible. Plain tree opacity and strokeWeight refuse because the generic FRAME renderer does not apply those fields; their supported native bindings remain available. Supported layout fields are mode, width, height, gap, padding.block/inline and clipsContent; other fields refuse. Every used COLOR/FLOAT/BOOLEAN role is validated in all source modes, with positive fixed dimensions, nonnegative padding/corners/stroke bindings and percentage opacity bindings from0 to100. Gap bindings and source gaps require finite values, including negative overlap; this is not an assertion that the Figma API forbids negative spacing. It refuses RECTANGLE and advanced declarations, rather than treating them as supported source primitives. Existing normal DTO/builder validation still owns complete family/anatomy/layout validation.

## Native snapshot and ownership

`mgNativeCollectionsPreflight(plan, snapshot, identity)` takes `{collections,variables}`. Collections expose actual `id`, `name`, `modes:[{modeId,name}]` and `variableIds`; variables expose actual `id`, `name`, `resolvedType`, `variableCollectionId` and `valuesByMode`. Ownership callbacks are `identity.readCollection(asset)` returning parsed `{version:1,planId,collectionId}` or null, and `identity.readVariable(asset)` returning the existing source variable ID or an empty string. The integration uses the new legitimate `mgNativeCollectionPlan` key through its normal identity callbacks, preserving private/shared mode behavior.

The profile is local-owned only, without remote or extended collection adoption. A matching name without the exact collection ledger refuses. Requested native variables need their exact source ID, name, type and declared native owner. Global same-name or source-ID conflicts refuse, even in another collection. All native mode names must belong to the source modes; missing source modes are reported as needed creations, while duplicate or undeclared modes refuse. Native mode IDs are mapped separately in each collection.

Capacity includes every retained occupant, including identified stale assets that are not requested and are never adopted or updated by this planner. Unidentified foreign occupants refuse. A stale nonempty variable identity is not proof of its historical origin; the planner counts it and leaves it unchanged. Native inventory membership must match actual collection variable IDs. At 5,000 occupied/requested roles the plan can pass; at 5,001 it refuses before writes. No pruning or rebucketing occurs.

Preflight returns Maps `collectionsBySourceId`, `variablesBySourceId`, `modeIdsByCollectionId` (logical collection ID to source-mode/native-mode Map), `sourceModeNames`, and `occupancy:{existing,missing,resulting}`; arrays `neededCollections`, `neededVariables`; and Map `neededModes` with missing source mode records. Fresh missing assets are permitted, but their resolution/application refuses until materialized. Existing source aliases require actual native aliases to the exact declared native target; literals cannot bypass the source graph. Native literals for source literals retain type/finite validation, without claiming their current values equal a new desired import value.

## Builder runtime value constraints

SourceCapability also records `plan.runtimeRoles` (role name to type) and `plan.runtimeConstraints` (role name to the strict combined min/exclusiveMin/max requirements from actual schema sites). `mgNativeCollectionsValidateValues(plan,state)` resolves every used role in every source mode through the qualified native alias map and applies those requirements before scene writes. A native alias target that became a negative width can pass basic type/finite asset preflight but must refuse this builder guard. Multiple uses of one role combine their constraints, rather than losing an earlier width or opacity requirement.

This guard does not require native values to equal source values: a valid maintained width155 can pass when the captured source was130. Native opacity binding101 or negative padding/radius/stroke refuses. Source checks enforce the same ranges. The importer deliberately does not call this builder-only native constraint guard before applying valid source values, so it can repair invalid existing literal values. Preflight still refuses ownership, alias graph, type and nonfinite corruption. Integrations must retain the SourceCapability-returned plan, rather than replace it with a fresh foundation-only SourcePlan without runtime constraints.

## Resolution and node modes

`mgNativeCollectionsResolve(plan,state,sourceRoleName,sourceModeId)` traverses exact native IDs, membership and collection-specific modes. It refuses missing or drifted values, mode names, alias IDs or types. It does not infer native alias behavior from one primary collection's mode ID.

`mgNativeCollectionsApplyModes(node,state,sourceModeId,requiredCollectionIds)` validates every required mapping before calling native mode setters. It sets only requested collection modes and preserves unrelated modes; repeated exact mode applications make no setter calls. A setter API failure can still be partial, so integration must journal mutation failures. This planner is not a rollback system.

Current absolute x/y offsets are construction-time resolutions, not live native position bindings. Retaining their helper roles does not establish live brand repositioning. Applying modes to an isolated snapshot mock does not establish actual linked-instance inheritance or publication semantics.

## Checks and open gates

`node examples/figma-plugin/dev/mock-native-collections.cjs` covers all five source modes, deliberately distinct native mode IDs between collections, cross-collection COLOR/FLOAT aliases, exact repeated node modes and preserved unrelated modes. It checks reordered plans, complete partition, alias types/cycles/nonselected-mode values, caller/snapshot immutability, ownership/name/membership drift, native alias/literal corruption, missing/duplicate/extra modes, local-only ownership, and capacity at 5,000/5,001 including retained identified occupants. Missing mode mappings refuse before any node mode setter. Source/native nonselected-mode geometry, negative alias targets and wrong opacity ranges are tested separately from general type preflight; valid changed widths and finite negative gaps remain accepted.

These are pure source and modeled native-snapshot tests. They do not import variables/styles, create scene nodes or execute a compiled connector. A production compiled fixture must use actual supported FRAME/filled-FRAME primitives, preserve the unchanged 50,000 limit and normal absent-profile byte parity, and undergo independent target/prewrite review. The full profile needs importer/builder/compiler integration and genuine native mode/alias/repeat/restoration proof before any full catalogue claim. Source font/glyph, gradient/mask pixels, consumer/library publication and canonical migration remain open.

## Production wiring and isolated native rehearsal (2026-10-06)

The opt-in production importer, builder and connector compiler now wire this first profile. Import takes a private source copy, checks the whole local inventory twice before creating assets, journals collection/mode/variable mutations, and creates every declared variable before applying cross-collection aliases. The builder takes a source copy, validates every used native role in every mode before scene writes, and refuses changed scene ownership/topology or a changed page across asynchronous preflight. Managed scene nodes carry a matching `mgNativeScenePlan` ledger. The maintenance runtime explicitly refuses this experimental declaration.

The first profile remains font-free FRAME-only. Its review specimens are disabled by a source-validated compiler discriminator. It does not add support for text, source instances, styles, SVG, media, gradient, mask, rich text or frozen-line profiles. Normal absent-profile connector output remains byte-for-byte identical to the previous verified compiler, including the unchanged refusal of a rich-text payload above 50,000 characters. The ceiling is unchanged.

An independently reviewed production pair was executed in the separate unpublished [native partition rehearsal](https://www.figma.com/design/4cphvmjWpM6umE8qrpjyQa). Its purpose-built diagnostic document has two owned collections, five modes per collection with distinct native mode IDs, five explicitly scoped variables, cross-collection FLOAT/COLOR aliases and two FRAME variant masters. This is a mechanics fixture, without an assertion that it implements a Mangrove component. Import used 29,907 characters and build used 46,791 characters. The native importer created all five variables and both collections without errors; the native builder created seven scene nodes without errors.

Recorded native master and consumer root widths/paint fields followed all five mode pairs. An actual linked consumer retained its own MCR modes and deliberate hidden visibility while the UNDRR width changed 100 to105 to100 and its colour changed and was restored. Both original variables have their source values again. A full inventory includes the consumer child FRAME with MCR width130 and its original colour. Cloud traversal initially skipped that hidden instance descendant: the documented `skipInvisibleInstanceChildren` flag was true. The subsequent complete checks temporarily set the flag false and restored it in `finally`.

Two unchanged production rebuilds created zero nodes. Their reviewed in-operation comparisons reported exact JSON equality for the complete recorded nine-node scene, five variables and both collections. Two unchanged production imports created zero variables, collections or modes and reported the same equality. The archived complete final build and import snapshots also agree independently; individual raw baseline and intermediate snapshots for these compact repeat pairs were not all archived. The linked consumer, hidden child, explicit modes, visibility, geometry, paints, bindings and shared identities remained intact. The earlier three-snapshot response hit the tool response limit; it is preserved as truncated evidence and superseded by complete compact receipts. These checks establish the recorded fields only, without claiming every Figma property or rendered pixel.

The external evidence directory is `/tmp/mangrove-native-partition-rehearsal-20261006`. It retains the empty baseline, exact fixture/source/payload SHA256 manifest, independent prewrite verdict, import/build reports, first screenshot, live mode/value rehearsal, complete descendant read, and untruncated import/rebuild repeat scripts and reports. The independent native review accepted these bounded fields and receipts in `native-independent-verdict.json`. No publication or canonical migration occurred. Full source partition ownership, advanced renderer profiles, large-collection occupancy, text/font/glyph fidelity, published cross-file consumer behaviour and complete catalogue rollout remain open.
