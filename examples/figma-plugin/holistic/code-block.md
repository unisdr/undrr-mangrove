# CodeBlock source cohort

This source-only `code-block` family projects six actual authored CodeBlock stories at 390px and 1164px source viewports, plus genuine narrow horizontal-end states for the four overflowing JSX stories. These produce 16 finite presets from 80 fresh Chromium captures across all five brands. Bash examples fit at both widths and have no invented end state. There is no Copy control in the source component.

`buildCodeBlockRecipes({root,modes,variables,styles})` is an isolated recipe producer. It publishes helper arrays after complete source, foundation, identity and style-kind validation. It does not register with the standard exporter or change source React, SCSS, maintenance components or Figma. Stable anatomy, source-context property names and variant IDs prevent different filename or plain-code defaults from sharing a component property.

## Actual source

The public export is `stories/Components/CodeBlock/CodeBlock.jsx`, with CSF3 stories in its adjacent story file and CSS in `stories/Atom/BaseTypography/Code/code.scss`. PrismLight registers Bash, JavaScript and JSX. The finite authored stories demonstrate plain text, Bash highlighting, filename headers, and JSX line numbers. Language API support beyond those stories remains a separate coverage gate.

Every code body is one editable logical TEXT node. Highlighted presets use source-derived contiguous text runs with exact character offsets, semantic token styles and source paints. Each run has an explicit native style identity so identical adjacent paints do not require guessed ownership. Plain code and filenames expose stable context-specific TEXT properties. Highlighted code supports the existing rich-run ownership edit contract; there is no whole-string property that resets its formatting. Changes do not run Prism, alter language, renumber line numbers or update capture allocations. The fixed gutter is a separate whole logical multiline TEXT node with no property or renumbering claim.

Filename treatments preserve the actual 30px caption, source padding and square inner code corners. A filename suppresses the language badge. Nonfilename highlighted bodies retain the actual uppercase badge and increased top padding. Actual line-number inline styles override the CSS gutter rule: the source 31.5px slot includes 14px right padding, leaving a 17.5px right-aligned ink allocation. Body glyph baselines and fractional line-height quantization remain native gates.

The background preserves the actual inset one-pixel interactive-color shadow with alpha 0.2, including its inherited inline-code origin. Source token paints bind known neutral, blue and orange aliases where their values match in every mode; Sendai colors absent from the foundation are explicit source-derived component colors. All native node opacity stays 1. Paint alpha belongs to the COLOR/effect contract, not percent node-opacity bindings.

## Overflow and source fonts

The fixed clipped pre viewport and inner code surface use actual source rectangles and scroll offsets. At the narrow end state, the source dark code background itself moves left and exposes a transparent right strip. The recipe preserves that behavior rather than enlarging the dark surface to the content scroll width. These are initial and end snapshots, not a scrolling prototype. CSS margins outside the component root are excluded from its own allocation.

Source code requests `ui-monospace, SFMono-Regular, Consolas, "Liberation Mono", Menlo, monospace`, weight 500, 14px, 22.4px line height and disabled ligatures. Five finite source canvas strings across all 80 contexts have identical advances under that stack and explicitly requested Menlo. This establishes a finite advance candidate, not which physical face the browser selected, its font bytes, ligature behavior or glyph equality. The DTO requests Menlo Regular without a substitute. The previously observed native cloud font inventory lacks Menlo; installed font availability and glyph equivalence remain open. A missing native face refuses before permanent builder writes.

Source filename copy uses Roboto Regular. Badge CSS weight 600 maps provisionally to the available Roboto Bold 700 named face; the source font request and archived active Roboto files are guarded, but this is not proof of identical badge pixels or an actual native 600 face. No proprietary system font bytes are distributed.
