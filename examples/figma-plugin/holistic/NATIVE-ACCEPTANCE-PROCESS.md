# Native acceptance process

Source recipes, browser evidence, native construction, source fidelity, ordinary
rebuild stability and publication are separate gates. A stable native baseline
can already be wrong. The BookCard title-style and underline findings demonstrate
why lifecycle equality alone cannot accept an implementation.

## Source and target preflight

- Pin the complete source cohort, dependency closure, input SHA256, runtime and
  actual file/page. Verify the recipe's meaningful authored states without
  replacing difficult variants with smaller unrelated samples.
- Derive identity keys from the importer and builder source. Variables use
  `mgId`, styles use `mgStyleId`, and managed scene nodes use `mgKitId`. An empty
  result from an incorrectly named read key is a diagnostic failure, not proof
  that import identity is missing.
- Pin the actual source-image owner name, geometry and complete recorded fills,
  including filters, opacity and transforms. Use actual receipts rather than
  shorthand messages to construct guards.
- Check current font-family aliases across every relevant mode before binding
  fonts, applying bound styles or changing modes. Load verified concrete faces
  and current text range fonts. Native TEXT font bindings can be arrays; inspect
  every entry. Style bindings can be singleton alias objects. Refuse foreign,
  cyclic, malformed or conflicting aliases before scene setters.

If native fileKey is unavailable, preserve the report's null value. Use an
explicitly reviewed association between fresh documented desktop URL
observations, unique local collection/style keys and exact ownership topology.
Do not describe this as an available native fileKey guard. Recheck context
before setters and after awaited native calls.

## Applied source contracts

Before a lifecycle baseline is accepted, compare the actual managed nodes with
the frozen source intent, not only with the current local foundation inventory.
For TEXT this includes source identity, copy or declared consumer overrides,
applied style ID, decoration, fonts, bindings and full range coverage. Validate
UTF16 range boundaries and their exact character slices. A shared style existing
in the file does not prove the correct style reached its node.

An explicit tree decoration takes precedence. Otherwise the imported style
provides decoration, with `NONE` as the final fallback. Verify linked and plain
variants separately. Check actual ranges as well as top-level TEXT fields. A
wrong style ID or erased underline must fail even if two rebuilds reproduce it
exactly. Rich text requires its own full run comparison; a plain-text helper
cannot accept rich ranges by omitting unsupported fields.

Keep semantic identity, recorded numeric geometry and rendered source evidence
separate. Document explicit native Float32 storage where demonstrated. Do not
introduce epsilon rounding or infer glyph, image-crop or gradient fidelity from
node counts and matching IDs.

## Lifecycle and recovery evidence

Once applied contracts pass, establish a fresh baseline and exercise ordinary
production rebuilds with the intended options. Save each complete operation
report and fresh post-build inspection. Verify zero creates, errors, stable
identities, genuine instance links, retained supported edits and modes, and exact
recorded fields across the repeats. Record first-run normalization separately
from repeat stability.

Awaiting a main-component read or a microtask is not a demonstrated layout
settlement barrier. Saved inspections are sequential observations, not atomic
transactions. Same-operation removal journals need a fresh committed lookup of
the actual created IDs before cleanup is accepted. Preserve residual reports
and later absence reads without rewriting earlier failures.

## Transport and handoff

- Budget both input and UTF8 output. Test diagnostics with native-shaped fields
  and Unicode, not only compact mock records.
- Use reversible lossless encoding or complete native report downloads when
  necessary. Decode and verify every recorded field. Never truncate acceptance
  fields to fit a transport limit.
- If an output limit is reached after setters, retain the complete attempted,
  created, mutated and removed ID journal, host declarations, restoration state
  and explicit snapshot completeness. Refuse acceptance of discarded samples.
- Preserve exact raw receipts and hashes. Lossless compressed archives must
  reproduce the original bytes and comparisons without editing reports or
  inventing native file keys.
- Obtain independent review of meaningful new writes, evidence and fixes.
  Source-only mock passes and isolated diagnostics do not satisfy canonical
  integration, selective publication, consumer update/restoration, novice
  handoff or reviewer merge acceptance.

These requirements inform the ongoing plain TEXT contract helpers and their
negative fixtures. They do not claim that every native catalogue contract or
rich-text adapter is already implemented. See [native integration
status](NATIVE-INTEGRATION-STATUS.md) for the current bounded evidence and open
gates.
