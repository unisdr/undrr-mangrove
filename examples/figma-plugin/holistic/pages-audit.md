## Shared dependencies and reuse boundaries

`UndrrChrome` imports PageHeader and MegaMenu. Page owners insert SkipLink. Its localized header uses four languages and no account control. LandingPage, ArticleStory and ContentHub do not insert Footer. Adding one to those compositions would change the authored source.

PageHeader contains an exact logo asset, external toolbar background, optional account icon and language control. Inline language links fall back to the icon dropdown at widths up to the source tablet breakpoint; lists exceeding the configured maximum also fall back. The invisible native select overlay is browser behaviour. A static closed control can be represented, with no claim that Figma implements the native popup.

Footer.jsx imports no FooterNavigation, FooterLists, FooterLogo or similar molecules. It loads a remote syndication widget, initially shows loading copy and has an error fallback. Disabled syndication and complementary regions have deterministic authored specimens. The exact loaded global footer requires a captured payload and asset provenance. The DELTA footer bar is local source markup and can be represented independently. Filename similarity is not a dependency edge.

Existing Hero, VerticalCard, TOC, TextCta, input, checkbox, table and button recipes provide partial drawing contracts. Hero/card local recipes are not blanket publication acceptance. Pattern copy, child count, optional media and content properties must match an actual reusable variant before inserting its native INSTANCE. Existing draft HighlightBox exposes plain Title/Body, while the article sample floats a rich body with strong numerals. Draft Tag excludes linked taxonomy containers. Draft UserFeedback covers initial states, while confirmation needs mixed styled linked copy. Reusing the nearest drawing alone would leave those contracts incomplete.

HubHeader is its own component, not a Hero variant. Its identity/navigation persists without a banner. Executable SCSS marks current and ancestor links with bold underlined text; an earlier leading-rule comment is stale. Secondary surface adds an accent bottom rule while retaining a safe hero-colour text surface. Four surfaces, compact/expressive structure, optional CTA/image and narrow overflow need explicit fixtures.

Search is the single public SyndicationSearchWidget family, with its own form, custom select/facets/chips, Pager wrapper, server teaser cards, progress/error/empty states, MobileFilterDrawer and optional external portal wrapper. These are not automatically covered by similarly named normal Select, Chips or card recipes. The separate search audit owns the complete state/configuration graph. ErrorPage's optional native search form is a distinct source contract.

## Responsive and content contracts

Reading uses a maximum 46rem article and a 16rem rail at 48rem. The source demo shell has wider narrow-viewport gutters below that threshold. HubHeader changes banner columns, media aspect ratio and identity/navigation treatment at 48rem. Grid/container and site chrome also use the source tablet 900px, desktop 1164px and desktop-wide 1440px boundaries. Query equality differs between source selectors and must be checked at the boundary instead of applying one invented tablet rule.

Proposed browser/native acceptance scenes are 390px, 767/768px, 899/900/901px, 1164px and 1440px where the relevant source rule changes. These are measurement viewports, not eight authored component variants. Record actual container allocation, viewport, active args, brand, language, loaded/requested fonts and exact asset source. English and Arabic are authored page contracts; a Latin measurement cannot establish RTL or Arabic font acceptance. Do not generate an arbitrary cross-product of every story control as new catalogue components.

Plain titles, paragraphs and optional slots should have stable content properties where that remains faithful. Rich inline links, strong spans, lists, source metadata and arbitrary editor content need a fuller text contract. The current builder applies whole-string text styles and fills. It does not provide an editable mixed inline style/link-run DTO. Splitting a sentence into unrelated text nodes changes wrapping and does not solve that contract.

The builder already supports image bytes with stable asset IDs, SVG, nested frames, auto-layout wrapping and native instances. Exact remote image preparation is therefore an asset/provenance task. CSS float with surrounding flowing paragraphs, sticky rails, overflow indicators, portal geometry, browser controls and responsive reflow need either explicit bounded visual presets or additional capability work. No static preset promises browser runtime interaction.

## Implementation packages

1. **P1, source chrome and assets.** PageHeader, MegaMenu, exact logo/toolbar assets and UndrrChrome. Capture authored closed/open views and language treatments.
2. **P2, layout and rich editable copy.** Container/grid/reading presets, hierarchy and source linked/list runs. Verify edit retention before dependent page assembly.
3. **P3, editorial units, after P2.** IconCard, BookCard, SectionHeader, ShareButtons, Imagecaption, QuoteHighlight and EmbedContainer, plus article-specific HighlightBox/Tag extensions. Use real media provenance.
4. **P4, HubHeader, after P1/P2.** Compact/expressive, current/ancestor, four surfaces, optional CTA/media and measured narrow/wide source scenes.
5. **P5, forms and feedback, after P2.** FormAction/FormGroup composites, authored newsletter states and rich feedback confirmation. Preserve source-specific sizing.
6. **P6, actual page assemblies, after P1 through P5.** Landing topic/report/index, ArticleStory media shapes, ContentHub route groups, Default and DELTA examples. Reuse faithful child identities.
7. **P7, search/footer integration, after P1/P2/P3.** Follow the search audit and exact configured page wrapper. Start deterministic local footer specimens; obtain evidence before representing remote loaded footer.
8. **P8, errors/challenges, after P1/P2.** Code-specific copy and optional states, plus source placeholder challenge treatment and static-template comparison.

This is an implementation dependency order, not a completion estimate. Reusable-unit and search audits may refine the package boundaries without inventing new source families.

## Acceptance still open

Source recipes and mock repetitions must prove stable anatomy, bindings, supported edits and refusal before mutation. Browser fixtures must compare actual source assets, fonts and responsive content. Native experiments require the exact separate unpublished target key and the machine-enforced target guard before any runtime/import mutation. Then verify native structural/visual fidelity, two ordinary zero-create repeats with exact recorded geometry and reusable-instance edit retention.

Native integration, selective publication and consumer update/restoration remain distinct gates. None of this source audit closes recovery layout drift, deliberately changed text/effect-style publication, composite publication, novice handoff or reduced maintenance merge acceptance. Canonical and consumer keys, isolated recovery, backups, History and deliveries remain protected. Desktop interaction currently fails `window_not_focused` after successful launch/observation, with both relevant permissions reported granted; the cause remains unconfirmed.
