# Guarded named font preparation

The rich builder can resolve native named-instance font defaults when `listAvailableFontsAsync()` lists only family/style but native TEXT and TextStyle font names contain variation axes. This is an optional preparation phase with real disposable TEXT writes. It precedes the mutation-free rich ownership preflight and all style import/component construction. It does not widen maintenance scope or prove native rich rendering.

`mgResolveNamedFontDefaults(figma, inputs, mgAssertExperimentOperationTarget)` requires the trusted zero-argument compiled experiment target assertion. Inert document metadata and a captured current file key are insufficient. Missing guards refuse. The hook is checked before probes and after asynchronous API operations. Current-page changes also refuse. Cleanup after target changes removes only captured fresh probe objects, never looked-up scene nodes.

The operation loads Inter Regular and every requested named face before creating probes. Each probe must be a fresh empty current-page TEXT. Assigning the named family/style uses the documented font input API. The concrete readback is checked against `getFontFamilyVariationAxes()` and the full source input, including explicitly supplied axes. Missing, nonfinite, extra or mismatched axes refuse. Concrete defaults are cached only inside that build operation. No source brand or later file inherits a stored default map.

The builder uses preparation only when requested variable-font faces lack complete native inventory axes. Otherwise it retains the existing mutation-free font resolution. The returned `fontPreparation` receipt records created, removed, residual and unverified-removal IDs, concrete fonts and errors. Successful preparation requires verified removal of every probe and exact equality of the explicitly recorded scene and asset fields. The receipt describes its verification scope; it does not assert equality of every native property, remote consumer or instance link.

Any preparation error, residual node, unknown removal or changed recorded state blocks style import and component construction. Cleanup and verification failures retain their journal. A partial failure is reported honestly, with no general rollback claim. An ordinary zero-create component rebuild can still have disposable probe creations and removals; these are separate from the builder's created component node IDs.

The isolated mock and actual-builder adapter exercise native-shaped inventory without axes, concrete readback, all font waits, operation-only resolution, two scene zero-create repeats, edited rich text retention, invalid axes, unavailable/read/set failures, missing/changed targets and failed cleanup verification. They do not establish native font bytes or native rendering. The separate native five-face primitive receipt initially proved the supported API and cleanup. The exact installed production `mgRichText` and `mgResolveNamedFontDefaults` modules have now also passed a guarded helper-only native probe in the unpublished experiment. The32,870-byte script retained both source modules byte-for-byte and used the production immutable target guard, below the unchanged50,000-byte limit. Inter Regular resolves wght400/slnt0; Roboto Regular/Bold resolve wght400/700 with wdth100; Roboto Condensed Regular/Bold resolve wght400/700. Every concrete map exactly covers its discovered native family axes. The helper reports recorded scene and asset equality within the declared verification scope. Independent review verified the production source/payload hashes, named faces, journal and bounded receipt. The receipt does not expose raw before snapshots for an independent recomputation of every recorded comparison.

This is native acceptance of the installed helper primitive and scoped cleanup in that guarded file. Installed end-to-end rich component build, consumer mode/font/range behavior, native font bytes, rendering and publication remain open gates.

The rich connector includes the helper only for rich scopes. Its existing 50,000-byte ceiling remains unchanged; a refused script is not native acceptance. The ordinary plugin has no trusted experiment assertion, so unresolved native defaults fail closed there until a separately reviewed target-safe workflow is available. The standard maintenance importer and token/style publication cohort remain unchanged.

Externally updating an existing shared rich style's font before rebuilding still fails the existing range ownership ledger. The separate `rich-font-only-migration-after-independent-maintenance-style-import` gate remains open. Default resolution does not authorize migration of user-selected axes or formatting.
