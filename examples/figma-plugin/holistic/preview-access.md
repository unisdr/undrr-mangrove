# PreviewAccess source candidates

`buildPreviewAccessRecipes` returns two finite source families: `preview-access-static` has four presets, and `preview-access-live` has six. Each covers widths 390 and 1164. These are ten candidate drawings of one source component, rather than ten independent components.

The evidence contains 60 actual settled browser scenes across all five brands. Fifty drawable scenes cover Default and ProductBranded initial dialogs, and actual LiveDemo activation, wrong PIN `0000`, and subsequent error clearing with value `1`. Ten unarmed LiveDemo scenes preserve host context as reference evidence. The static form deliberately prevents submission without implementing the live handler. Its wrong-PIN state is therefore excluded. No successful PIN was submitted, and no unlock or security enforcement has been accepted.

The source modal, custom input and submit, error allocation and contact link are retained. Each logical text owner uses its actual source capacity, with a stable story, state and viewport property context. The contact is one editable rich run with the real HTTPS destination and source underline with automatic offset and thickness. The live scrim retains black alpha 0.85; it is not a preflattened opaque image. CSS opacity is converted to the builder's percentage role convention.

The actual focused input clips its value. Its white spread-2 gap effect is applied to the input, and its outer golden outline is a separate sibling so it is not clipped with the value. The captured focus width and offset are checked against public focus roles. This is a source candidate for native effect and outline rendering, not accepted raster equivalence. Input selection ranges, focus and numeric input mode remain evidence metadata. There is no invented caret, selected-text highlight, password masking or IME behavior.

Active bundled font bytes, declarations and licences are pinned. The source submit requests Roboto 600, while the loaded source inventory has 400 and 700. Browser canvas metrics for 600 match 700 in the recorded probe; the CSS matching rule also searches heavier faces first above 500. Bold 700 is therefore an explicit source matching candidate. This does not prove native font bytes, glyph shape or arbitrary text reflow.

The dedicated offline harness runs the actual importer and builder in every brand, verifies source owner geometry and opacity, focus-outline placement outside the clipped input, source text sizes and whole logical capacities, and distinct text property defaults. It creates a linked consumer with a maintained heading and rich contact copy, then checks two exact zero-create repeats. Source, evidence, bundled-font, licence, helper identity/type/style-kind and missing-font refusals remain separate checks. The mock models supported rich text and the observed set-wide TEXT default behavior; it does not render native pixels.

Open gates include native pixels, shadows, font matching, selected range and caret, live modes, browser behavior, keyboard and accessibility, arbitrary copy reflow, ordinary installed plugin operation, publication and novice handoff. The source drawing is not an authentication or security implementation.
