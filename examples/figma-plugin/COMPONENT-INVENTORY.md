# Mangrove native component inventory

Catalogue audit: 3 October 2026. The current TOC, Status Label and initial Segmented subset checkpoint is dated 4 October 2026, with browser sources and native evidence documented in [LEARNINGS.md](LEARNINGS.md). This is the build inventory for the full Mangrove kit. An inventory entry is a source pattern, not a promise that every prop becomes a variant.

The [core kit](CORE-KIT-STATUS.md) contains 25 candidate families and 297 recipe variants with bounded construction/consumer evidence. **File organisation and durable updates are the next open gate**, before catalogue expansion: see [KIT-ARCHITECTURE.md](KIT-ARCHITECTURE.md). The full inventory remains follow-up work.

## Scope and evidence

Discovery reconciles the 74 curated entries in [component-data.js](../../scripts/ai-manifest/component-data.js), the ordinary Storybook catalogue, JSX and SCSS under `stories/Atom`, `stories/Components`, `stories/Molecules`, `stories/Patterns` and `stories/Utilities`, and the published component entries in [webpack.config.js](../../webpack.config.js). The curated manifest alone misses visual dependencies and some catalogue entries, including Snackbar and CookieConsentBanner. Conversely, `src/index.js` is not a complete public-component list: the assembled npm package exposes component subpaths and CSS/vanilla patterns. See [assemble-npm-package.mjs](../../scripts/assemble-npm-package.mjs).

Three levels must stay separate:

- **Mapped:** source anatomy, candidate states and dependencies are identified below. Remaining entries are at this level unless explicitly stated otherwise.
- **Built:** a declarative recipe and native component exist. Passing mocks establishes API-contract and update behaviour, not rendering fidelity.
- **Observed:** an actual native consumer was inspected against a measured browser fixture. Observation applies to the recorded state, width, brand and script only.

Native instances can represent visual states and editable content. They do not implement browser keyboard semantics, form validation, network requests, focus trapping, media playback, persistence, animations or HTML layout algorithms. Prototype and deprecated source patterns retain those labels in the kit. Documentation, code examples and layout rules receive foundation documentation or composition specimens where useful, rather than fabricated production components.

## Next source and native gates

The 28 native families include item dependencies, size splits and compositions; family counts do not measure completed public-component coverage. Segmented Control now exports 30 Default-size leaves with source styles/paint roles and a separate five-state ordinary-rebuild gate. Its joining diagnostic still leaves the source wrapped-row origin and middle-over-neighbours focus unresolved. The four Default FullWidth presets have separate bounded 240/390px editing and ordinary-repeat acceptance; composed Focus, Small and variant switching remain outside that contract. Form Action's raw joining diagnostic exposed ignored layout switching and zero-width paragraphs. The later fixed-master optional-wrapper diagnostic addresses paragraph sizing, but actual variant switching, canonical shared styles, reusable nested masters and ordinary component rebuild acceptance remain pending.

First close the [core milestone gates](CORE-KIT-STATUS.md#remaining-gates-before-the-core-milestone-is-done): natural editor instances, the Default Segmented composition and bounded edited Chips/Text CTA/Compact Empty State consumers. After the core handoff, prioritise measured UserFeedback, Accordion, Pager and HighlightBox. UserFeedback uses Roboto text but its source actions have a 40px minimum; Accordion changes the standalone Details anatomy; Pager parts require their own sizing; Latin HighlightBox headings inherit the source text font in this context. Measure each before reusing whole masters. Editorial CTA styling and exact Condensed-font loading remain parallel dependency gates for larger compositions.

## Build order

This order follows dependencies and present font/API limits. It is a recommended implementation sequence for the authorised full inventory, not a claim of completed source measurements for the remaining rows.

1. **Finish the present checkpoint acceptance.** Exercise existing native consumer edits/re-import, focus effects, long field labels/help/errors, all five brand round-trips and narrow layouts. Preserve current identities and resolve or document Condensed loading independently of the plan upgrade.
2. **Form choices and grouped feedback.** Radio and Checkbox now each have 30 bounded variants; FormErrorSummary has six native presets with corrected underline/balancing observed in bounded UNDRR consumers. Extend the existing Switch families with pending/custom-size/motion/RTL coverage, then FormGroup with a faithful fieldset contour. Extend remaining Radio/Checkbox width and state coverage.
